# 测试通道运行说明

> 状态：**现行**
>
> 更新日期：2026-10-15
>
> 适用范围：统一测试通道入口 `scripts/run_test_channels.py` 的通道划分、`external` / `real_model` / `requires_db` / `requires_gpu` 标记语义、物理设备/重档的显式 opt-in（`QLH_RUN_PHYSICAL_TESTS`）、运行方式与跳过条件；与 `pytest.ini` 的 markers 和 `requirements-test.txt` 对齐。

项目测试拆成三条通道，避免协议测试加载真实权重，也避免数据库和 GPU 生命周期互相争用。邮件通道已从主仓裁撤。

## 安装测试依赖

`requirements-test.txt` 包含完整运行时依赖和测试工具，且签名测试沿用发布链的
`cryptography>=42,<47` 约束。禁止将它直接安装到系统 Python；否则 pip 可能为了满足测试约束，
降级其他工具共用的包。

默认创建完全隔离的 `.venv-test`：

```powershell
python scripts/setup_test_env.py --proxy http://127.0.0.1:7897
```

CUDA 开发机不希望重复安装大型 PyTorch 运行时时，可创建轻量覆盖环境：

```powershell
python scripts/setup_test_env.py --reuse-runtime --proxy http://127.0.0.1:7897
```

覆盖环境可读取系统运行时包，但 pip 的新增、降级和升级只写入 `.venv-test`。`--proxy` 可省略；
脚本也支持 `--wheelhouse <目录>` 离线安装、`--check` 只读健康检查，以及 `--recreate` 显式重建。
同一目录不能在完全隔离与覆盖模式之间静默切换，切换模式必须使用 `--recreate`。

## 一键运行

```powershell
.venv-test\Scripts\python.exe scripts/run_test_channels.py
```

入口默认拒绝系统 Python。仅一次性 CI 镜像或明确的依赖诊断可以使用
`--allow-system-python` 绕过；日常开发不得使用该参数。

### 环境分割铁律（2026-08-14 事件后强调）

1. **测试依赖只允许存在于 `.venv-test`**（通过 `setup_test_env.py` + `requirements-test.txt` 安装）。系统 Python（主环境）只装 `requirements.txt` 运行时依赖。
2. **严禁在 `.venv-test` 与主环境之间复制/同步 site-packages**——两个环境的包集合必须各自独立演化。
3. 测试一律用 `.venv-test\Scripts\python.exe` 运行；发现主环境出现 pytest 系包或 `.venv-test` 丢失 pytest 时，立即用 `setup_test_env.py --check` 体检并按提示重建（`--recreate`）。
4. 违反第 2 条的症状：主环境出现 pytest 系包、`.venv-test` 丢失 pytest（两侧包集合被复制混淆）。此时用 `setup_test_env.py --check` 体检并按提示 `--recreate` 重建。

运行顺序为：

1. `unit`：排除 `external`、`requires_db`、`slow`、`requires_gpu` 和 `real_model`，安装 `pytest-xdist` 后默认使用 4 个 worker 和 `loadscope` 并行。
2. `external`：运行必须串行的用例（`external`，如起真实 socket / 子进程）与外部资源测试，固定 `-n 0`。
3. `smoke`：运行 `real_model` 标记用例（串行加载真实权重），固定 `-n 0`。

**物理设备 / 重档用例是显式 opt-in**（票 13 第三条，`CI-RELEASE-01`）：设置
`QLH_RUN_PHYSICAL_TESTS=1` 才收集 `real_model` / `requires_gpu` / `slow` / `requires_db`。
未设置时它们**不进入收集**，而不是"跑了再 skip" —— 后者在有 GPU 的机器上会真的跑起来，
等于隐式 opt-in。`QLH_RUN_REAL_MODEL_SMOKE=1` 保留为向后兼容的等价开关。

`manifest.json` 的 `physical` 与 `smoke` 字段分别记录 `opt_in`（授权）、`attempted`（已尝试）、
`ran`（实际有非 skip 用例执行）、`passed` / `skipped` 计数和 `status`。开启物理开关但只运行 unit
不会显示物理已执行；启动 pytest 却全部 skip 也不能通过必验门。普通 CI 未开启物理档时明确记录
`NOT_RUN`，核心通道通过不代表真机通过。归属明确的外置 docagent／退役基准测试默认不收集，
可用 `QLH_INCLUDE_WORKSPACE_TOOL_TESTS=1` 交给外置工具环境执行；核心缺依赖仍然使 collection 失败。

每次通道执行都会在 `build/audit/test-channels-<UTC时间>-<PID>/` 生成
`manifest.json`、每次运行对应的 JUnit XML 和完整日志。`build/` 是本地审计工件目录，
不进入版本库。默认会生成一个随机顺序种子并写入 manifest；用 `--order-seed` 或
`QLH_TEST_ORDER_SEED` 可以复现同一顺序。

可单独运行：

```powershell
.venv-test\Scripts\python.exe scripts/run_test_channels.py --channel unit --workers 4
.venv-test\Scripts\python.exe scripts/run_test_channels.py --channel external
.venv-test\Scripts\python.exe scripts/run_test_channels.py --channel smoke

# 重复执行用于观察 flaky，不是失败重试；任一次失败都会使入口失败
.venv-test\Scripts\python.exe scripts/run_test_channels.py --channel unit --repeat 5 --order-seed 20260921

# 审计测试级真实并发；日常默认仍为 loadscope
.venv-test\Scripts\python.exe scripts/run_test_channels.py --channel unit --dist load --repeat 3
```

`--dist loadscope` 将同一模块内的用例放入同一 worker，降低共享状态互扰；
`--dist load` 才是测试级真实并发，专门用于暴露互扰和竞态。重复执行产生独立的
`unit-001`、`unit-002` 等证据文件，不使用 rerun 插件把失败隐藏成绿色。

当前已明确使用 marker 的重资源路径包括：CUDA pager 用例 `requires_gpu`、
Qwen 1.8B CUDA/真实权重回归用例 `real_model + requires_gpu`、Gemma 4 官方分段
smoke 用例 `slow`。新增真实模型或外部资源测试必须先声明对应 marker。
这些 marker 的收集由 `QLH_RUN_PHYSICAL_TESTS` 控制（见上文"一键运行"）。

## 启动回归矩阵

`scripts/startup_matrix.py` 将启动优化的四个验收维度收束为一个入口：Edge 预检、完整 API 冷启动、无 Torch 的 GGUF 路径，以及 TUI 后端/页面启动。它复用既有 pytest 和 `edge_preflight.py`，不会创建第二套探针。

在 Windows 开发机上运行完整矩阵：

```powershell
.venv-test\Scripts\python.exe scripts/startup_matrix.py --report local_docs/startup-matrix.json
```

单独运行某个维度：

```powershell
.venv-test\Scripts\python.exe scripts/startup_matrix.py --profile edge
.venv-test\Scripts\python.exe scripts/startup_matrix.py --profile full
.venv-test\Scripts\python.exe scripts/startup_matrix.py --profile no-torch
.venv-test\Scripts\python.exe scripts/startup_matrix.py --profile tui
```

`edge` 使用 `.venv-edge`，其余 profile 使用 `.venv-test` 当前解释器；JSON 报告保留每个子进程的返回码、耗时、命令和末尾输出，适合作为本地证据。系统 Python 默认被拒绝，只有一次性诊断环境才使用 `--allow-system-python`。

## 真实模型冒烟

冒烟测试必须显式开启，并且始终串行：

```powershell
$env:QLH_RUN_PHYSICAL_TESTS = "1"            # 物理设备/重档总开关（含 smoke）
$env:QLH_RUN_REAL_MODEL_SMOKE = "1"          # 等效开关，保留作向后兼容
$env:QLH_SMOKE_MODEL_ID = "qwen3-5-2b"      # 省略时按设备画像取默认模型
$env:QLH_SMOKE_ENGINE = "pytorch"
$env:QLH_SMOKE_QUANT = "int4"
.venv-test\Scripts\python.exe scripts/run_test_channels.py --channel smoke
```

可选设置 `QLH_SMOKE_MODEL_PATH` 指向对应内置模型槽位的本地 Safetensors 目录或 GGUF 文件；未设置时使用项目模型注册表中的路径。冒烟流程只做一次最小生成，然后卸载模型，失败应视为当前解释器、模型文件、CUDA/量化依赖或引擎适配问题，而不是单元测试失败。

`QLH_SMOKE_MODEL_ID` 未设置时按设备画像取默认模型（`src/model_config.py` 的 `DEFAULT_MODEL_BY_TIER`）；验证其他模型时显式设置，例如 `QLH_SMOKE_MODEL_ID=deepseek-r1-distill-qwen-1.5b`，并确认本地模型已完整下载。

## 票 13：证据完整性和物理必验

摘要同时核对整数退出码、真实 JUnit testcase、suite 计数、每个预期通道与重复次数。空 runs、
缺失或损坏 XML、失败记录但 exit 0、全 skip、重复复用 XML、逃出 session 的路径及未结束会话均失败。
`latest.json` 指向本次尝试；本次中断后不会退回上次成功。需要固定一次证据时，runner 和摘要都支持
`--session NAME`；runner 拒绝覆盖已有 session。

```powershell
$env:QLH_RUN_PHYSICAL_TESTS = "1"
.venv-test/Scripts/python.exe -B scripts/run_test_channels.py --channel all --require-physical --session release-audit
.venv-test/Scripts/python.exe -B scripts/summarize_test_channels.py --artifacts-dir build/audit --session release-audit --require-physical
```

`--require-physical` 要求每次 external 和 smoke 都有实际物理用例通过；普通 external 的 socket 测试不能
替代物理用例。marker 归属在收集完成后写入 JUnit。此门不保证每种硬件都已覆盖，也不能替代
[产品接力证据门](产品接力证据门-CI-RELEASE-01.md)的两个不同远端、DL/LL、无整模及星状连接验收。
