# 二进制 hidden 帧：实现与验收

> 状态：**部分实施**
> 更新日期：2026-10-20
> 适用范围：票21a `COMM-WIRE-01` 的现行编码合同、开发验证、复跑入口与剩余设备门。投机生成、多位置native ABI和协议时序改造分别由21b、21b-0、21c负责。

## 1. 实现合同

`src/task_worker_protocol.py` 的 `BINARY_HIDDEN_PATHS`、`split_inline_hidden`／`restore_inline_hidden` 将 `stage_offer.root_input.hidden_f32`、`stage_result.output.hidden_out_f32` 与两类chunk的 `payload_b64` 从JSON内联值转为原始字节体；接收后恢复既有字段并执行原业务校验。`src/tcp_comm.py:build_message`／`TCPClient.recv_data` 保持 `[meta长度][meta JSON][body长度][raw]` 的同帧布局。`binary_hidden_frame_bytes` 按真实metadata、body长度头和raw计算完整预算，初始meta长度头单独计；上限读取 `MAX_BINARY_FRAME_BYTES`，旧JSON读取 `MAX_MESSAGE_BYTES`。

`src/task_worker_adapter.py` 的 `TaskWorkerControlPlane` 与 `RemoteFullWorkerProvider._supports_binary_hidden` 使用实际协商结果；`src/scheduler_task_worker.py` 按当前连接归属收发和重放，超限时预先选择分片。`QLH_TASK_WORKER_BINARY_HIDDEN` 经 `binary_hidden_transport_enabled` 影响能力广告与ACK；缺能力、ACK false或缺省时沿用JSON/base64。内存中的base64及其摘要校验继续执行，字节收益与CPU收益分别测量。

Android `SocketTaskWorkerTransport`／`TaskWorkerProtocol` 的协商围栏和整数解析修复分别登记于[已知问题 #99／#100](已知问题记录.md)。这些条目的根因与当前边界以问题记录为详细来源。

## 3. 完整帧与CPU／时延

测量口径：同机IPv4 TCP loopback，`TCP_NODELAY`，3次warmup加每格式21次样本，成对交替先后顺序。计时覆盖base64 staging、生产消息构造和校验、抽体、完整帧构建、TCP收发、恢复、原校验和raw解码；排除证据相等断言。四类hidden承载消息、三档字节规模的逐样本结果均保存在 `native-wire-r4.json:wire.cases`；下表为layer offer的完整帧字节、wall time均值±样本标准差，以及进程CPU周期均值。CPU时间同时保留于原件；Windows小帧时间粒度为15.625 ms，周期计数补足小样本分辨率。

hidden体的base64到raw缩减约25%，包含头与元数据的完整帧缩减按上表读取。当前全路径实验的binary wall与CPU周期均值较高，编码CPU／本机时延收益尚无正例。减少链路字节可独立确认；跨机完整生成吞吐需同设备条件重采。`tcp_comm.build_message` 本身直接传raw，而task-worker仍有内存base64恢复与校验，性能判断使用完整调用范围。

## 4. 复跑

仅执行混合能力、重连与帧微基准：

```powershell
.venv-test/Scripts/python.exe -B -X utf8 scripts/comm_wire_bench.py --json-out build/comm-wire-recheck/wire.json
```

追加已有proper head／tail的数值门；路径指向现有模型与manifest，`--head-expect`／`--tail-expect` 只可补缺失声明，禁止覆盖冲突：

```powershell
.venv-test/Scripts/python.exe -B -X utf8 scripts/comm_wire_bench.py --native --head <head.gguf> --head-manifest <head.manifest.json> --tail <tail.gguf> --tail-manifest <tail.manifest.json> --head-expect 'head_count_kv=4,key_length=256,full_attention_interval=4' --tail-expect 'head_count_kv=4,key_length=256,full_attention_interval=4' --steps 32 --threads 8 --ctx 256 --json-out build/comm-wire-recheck/native.json
```

`comm_wire_bench.main` 在异常时写入失败及已收集的原生步骤；完整JSON／binary／mixed三条路径、长度、格式、逐步argmax和hidden摘要均满足时才设置数值门通过。`_native_contract` 检查manifest／header／native维度与层数、实际词表及有限logits守卫，缺少能力时具名拒绝。Windows native模式用 `edge_bench._protected_model` 保持模型只读句柄；其他系统可运行wire模式，native无复制保护方式另待实现。

Android复跑入口：在 `android/` 执行 `./gradlew.bat :app:testDebugUnitTest --tests "com.qlh.inference.worker.*" --console=plain --offline`。Python工具负例与真实TCP小样本入口为 `tests/test_comm_wire_bench.py`。
