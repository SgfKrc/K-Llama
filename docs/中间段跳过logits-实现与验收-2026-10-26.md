# 中间段跳过 logits：实现与验收

> 状态：**已实现并通过本机真机数值门与性能门**（单段，CPU）。
> 日期：2026-10-26 ｜ 主机：i9-13900H（6P+8E / 14C20T）、31.6 GB RAM、RTX 4060 Laptop（**未使用**）
> 改动性质：**局部性能优化**，缺省行为不变；由 `QLH_LAYER_SKIP_LOGITS` 显式开启。
> 证据目录：`local_docs/perf-skiplogits-20261026/`

## 0. 一句话结论

keep-head shim 过去对**每个 token** 都标 `batch.logits[i] = 1`，而中间段的语义只是
"吃 hidden、吐 hidden" —— 它从不读 logits，却因此每步都要跑一遍 `output.weight`（`lm_head`）
的矩阵乘。现在由 `QLH_LAYER_SKIP_LOGITS=1` 让**输出 hidden 的入口**不再请求 logits
（`n_outputs = 0`），实测：

| 段 | 关（既有行为） | 开 | 收益 | hidden 是否逐位一致 | 末段 argmax 是否一致 |
|---|---|---|---|---|---|
| 9B `[4,24)` 20 层 | 119.1 / 120.2 ms | 102.6 / 106.7 ms | **-15.0 ms（-12.5%）** | ✅ 相同 | ✅ 相同 |
| 2B `[16,20)` 4 层 | 22.1 ms | 13.0 ms | **-9.1 ms（-41.4%）** | ✅ 相同 | ✅ 相同 |

（9B 为两次同源对照的均值；详见 §3。）

## 1. 根因定位

三机流水线里的**中间段**在本机的执行路径是：

```
scheduler_task_worker / relay_mid_service --role middle
  -> inference_service.engine_host.EngineHost.execute_task_worker_stage
     -> _execute_layer_forward_stage_locked            (engine_host.py:3238)
        -> _layer_forward_upstream()                    (engine_host.py:2973)
           -> llama_keep_head.KeepHeadUpstream(mode="nextn")
              -> forward_hidden_to_hidden()             (llama_keep_head.py:756)
                 -> qlh_kh_forward_embd_seq()           (shim / qlh_keep_head.c)
```

判据落在 shim 上（`scripts/model_tools/keep_head_shim/qlh_keep_head.c`）：

* `qlh_fill_common()` 与 `qlh_fill_explicit()` 过去无条件写 `batch->logits[i] = 1`
  （改动前的 206-233 行），**两个函数被全部 5 个前向入口共用**；
* 其中 3 个入口（`qlh_kh_forward` / `qlh_kh_forward_embd` / `qlh_kh_forward_embd_seq`）
  的输出是 **hidden**，调用方（`forward_tokens_to_hidden` / `forward_hidden_to_hidden`）
  **从不调用任何取 logits 的 API**；
* 只有 2 个入口（`qlh_kh_forward_embd_token` / `qlh_kh_forward_embd_tokens`）会用
  `llama_get_logits_ith()` 做 argmax —— 那是**末段**。

llama.cpp 侧（`android/app/src/main/cpp/llama.cpp`，本次只读未改）：

* `llama-graph.cpp::llm_graph_context::build_inp_out_ids()`（:2259）总是构造
  `out_ids`，长度 = `n_outputs`；架构 graph 在 `lm_head` 之前用
  `ggml_get_rows(cur, inp_out_ids)` 把 hidden **裁到有输出的行**
  （`qwen35.cpp:220`、`qwen2.cpp:69`）；
* 因此 `batch.logits` 全 0 ⇒ `n_outputs = 0` ⇒ `get_rows` 输出 0 行 ⇒
  `build_lora_mm(model.output, ...)` 的 `output.weight` 矩阵乘**不再有有效行**；
* `layer_inp`（本 shim 取 hidden 的通道）与 logits 掩码**无关**：
  `llm_graph.cpp::set_outputs()`（:1240-1248）按 `cparams.embeddings_layer_inp`
  独立 `ggml_set_output`，`llama-context.cpp::extract_layer_inputs()`（:2230）
  不看 `n_outputs`；且 `t_layer_inp[n_layer]` 在 `ggml_get_rows` **之前**登记
  （`qwen35.cpp:213` vs `:220`）。

### 已经做过的那一半（不重复实现）

`src/llama_engine.py:2637` 的 pip 绑定路径 `forward_layers_to_hidden()`（上游 token→hidden）
**早已**写 `batch.logits[i] = 0`，注释就是"上游不需要 logits，只要 hidden"。
但那是**另一条路径**：keep-head shim（生产中间段真正走的那条）从未跟上。
`src/llama_engine.py:2742` 的 `forward_layers_from_hidden()` 是**下游/末段**，
logits 全开有明确理由（"每个 token 都可能是某条序列的末位"），**本次未改**。

## 2. 实现

### 2.1 配置键

| 键 | 缺省 | 真值 | 作用 |
|---|---|---|---|
| `QLH_LAYER_SKIP_LOGITS` | **关**（不设/空/`0`/`false`/`no`/`off`） | `1`/`true`/`yes`/`on`（大小写不敏感、去空白） | 只对**输出 hidden 的入口**停止请求 logits |

缺省关闭 ⇒ 不设该变量时行为与改动前**完全一致**（不悄悄改语义）。
开关**不是** `SHIM_SYMBOLS` 的一部分 —— 旧 shim 不会因为多了这个可选能力而整体不可用；
但若**开了开关而 shim 没有该符号**，一律 **fail-loud**（`KeepHeadUnavailable`），
绝不静默退回"仍然算 logits"。

### 2.2 shim（C）

* 新增可选导出 `qlh_kh_set_skip_hidden_logits(void * handle, int32_t skip)`（返回 0 / -1）；
* `qlh_fill_common` / `qlh_fill_explicit` 增加 `want_logits` 形参；
* `qlh_kh_forward` / `qlh_kh_forward_embd` / `qlh_kh_forward_embd_seq`（输出 **hidden**）
  传 `handle->skip_hidden_logits ? 0 : 1`；
* `qlh_kh_forward_embd_token` / `qlh_kh_forward_embd_tokens`（输出 **token**）
  **恒传 1** —— 末段不受开关影响，这是本改动的数值门；
* `qlh_kh_load` 用 `calloc` ⇒ `skip_hidden_logits` 初值为 0（旧行为）。

### 2.3 Python

* `src/llama_keep_head.py`：`SKIP_HIDDEN_LOGITS_ENV` 常量、
  `skip_hidden_logits_requested()` 解析、`__init__` 中**先验符号再加载模型**
  （fail-fast，不为一次注定失败的初始化白读几 GB 权重）、
  `skip_hidden_logits_applied` 只读属性（区分"配置请求"与"native 已落实"）；
* `src/llama_keep_head_worker.py`：初始化回执新增 `skip_hidden_logits`，
  让**进程隔离模式**下的"已落实"由子进程确证，而不是靠主进程"我设了环境变量"。
  子进程继承父进程 environment ⇒ 主进程侧无需改 worker CLI 协议。
* 其余调用方（`engine_host` / `relay_mid_service` / 各探针脚本）无需改动：它们都经
  `KeepHeadUpstream`。

## 3. 验收证据

工件与驱动（与 `docs/本机跨框架层段成本与干扰实测-2026-10-25.md` §1 同口径）：

* 9B：`models/q35-9b-local-artifacts/q35-9b-local-mid4-24.gguf`（3.97 GB，`[4,24)` 20 层，
  `n_embd=4096`，`n_vocab=248320`）
* 2B：`build/keephead/q35-2b-cut-16-20.gguf`（`n_embd=2048`，4 层，`n_vocab=248320`）
* 驱动：`KeepHeadUpstream.forward_hidden_to_hidden`（`mode="nextn"`，`n_threads=8`，`n_batch=4096`）
* 方法：预热 4 步 → 取 **9 步** 单 token 增量 decode 的**中位数**；每臂各一次运行，
  9B 做**两次交替**（on/off 顺序与首轮相反）以排除页缓存顺序效应
* shim：`build/keephead/build-cpu-skiplogits/bin/qlh_keep_head.dll`（本次编译产物）；
  基线对照另跑 `build/keephead/build-cpu/bin/qlh_keep_head.dll`（改动前的产物）

```
=== q35-2b-cut-16-20.gguf  (n_embd=2048, n_layer=4, n_vocab=248320) ===
label                           flag  median_ms   mean_ms  vs first   digest     tail
q35-2b-cut16-20-off              off     22.116    22.082    +0.000     same     same
q35-2b-cut16-20-on                on     12.971    13.321    -9.145     same     same

=== q35-9b-local-mid4-24.gguf  (n_embd=4096, n_layer=20, n_vocab=248320) ===
label                           flag  median_ms   mean_ms  vs first   digest     tail
before-baseline                  off    122.615   122.453    +0.000     same     same
after-skiplogits-off             off    119.090   120.748    -3.525     same     same
after-skiplogits                  on    102.584   102.254   -20.031     same     same
repeat-skiplogits-off            off    120.249   120.896    -2.366     same     same
repeat-skiplogits-on              on    106.740   106.361   -15.875     same     same
```

`digest` = 末步 hidden（f32）的 sha256；`tail` = `forward_hidden_to_token` 的 argmax 与
`forward_hidden_to_tokens` 的 3 位置结果。

### 3.1 数值门（硬）

* 9B 五次运行的 `hidden_digest` **全部等于** `c97ab4ca9616a84b231114ee175b170c20
  1620ec2ef969a37e3d8b0c857fd3f1`，`hidden_first8` 逐值相同，`hidden_absmax` 相同；
* 2B 两次运行的 `hidden_digest` 全部等于
  `46152324bd3f166261c3b3c3e10947d47a76841aaa074a13159f5b4b0d1007c3`；
* 末段 argmax：9B `tail_token = 150045`、`tail_tokens_multi = [84607, 84607, 191019]`
  在**开/关两种情况下都相同** —— 证明末段 logits 路径未被关掉；
  2B `tail_token = 108188` 同样相同。

### 3.2 回归门

* **同源对照**：改动后的 shim 在**开关关闭**时 119.1 / 120.2 ms，与改动前的
  122.6 ms 同量级（差 2.4-3.5 ms，落在步时抖动 ±4 ms 内），hidden 与 argmax 全部相同
  ⇒ 缺省行为未变；
* 新增单测 `tests/test_llama_keep_head_skip_logits.py`：**8 passed**
  （真值解析、缺省关闭、缺符号 fail-fast、符号以 `(handle, 1)` 调用、
  关闭时**不**触碰可选符号、worker 回执必须确认、旧回执向后兼容、回执落地记录）；
* keep-head / worker / scheduler 相关既有测试：
  `test_llama_keep_head*.py`、`test_keep_head_shim.py`、`test_refactor_bootstrap.py`、
  `test_worker_prepare_runtime.py`、`test_scheduler_task_worker_capabilities.py`
  ⇒ **194 passed, 10 skipped, 0 failed**。

### 3.3 机制旁证（收益确实来自 `output.weight`）

两段的 `n_vocab` 相同（248320），`output.weight` 的字节数只随 `n_embd` 变：

| 段 | `n_embd` | `output.weight`（Q4_K 估算） | 实测收益 | 反推有效带宽 |
|---|---|---|---|---|
| 2B `[16,20)` | 2048 | ≈ 285 MB | 9.15 ms | ≈ 31 GB/s |
| 9B `[4,24)` | 4096 | ≈ 570 MB | 15.0 ms | ≈ 38 GB/s |

收益之比 1.64×（对同源对照），与权重字节数之比 **2.0×** 同量级；两条独立测量反推出
**同一档有效内存带宽（31-38 GB/s）**，与本机 DDR5 实测区间一致，也与
`docs/本机跨框架层段成本与干扰实测-2026-10-25.md` §2 的"瓶颈是内存带宽"结论吻合。
⇒ 省掉的确实是那次权重读取，而不是别的副作用。

## 4. 编译方式与产物

```powershell
# gcc 15.2.0 (MSYS2 UCRT64)；先复制运行时闭包，再就地替换 shim
$dst = 'build/keephead/build-cpu-skiplogits/bin'
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item 'build/keephead/build-cpu/bin/*' $dst -Force
& 'C:\msys64\ucrt64\bin\gcc.exe' -shared -O2 -o "$dst/qlh_keep_head.dll" `
    'scripts/model_tools/keep_head_shim/qlh_keep_head.c' `
    -I'android/app/src/main/cpp/llama.cpp/include' `
    -I'android/app/src/main/cpp/llama.cpp/ggml/include' `
    -L'build/keephead/build-cpu/src' -lllama
# exit code = 0
```

* 产物：`build/keephead/build-cpu-skiplogits/bin/qlh_keep_head.dll`（111120 B，gcc exit=0）
* 编译方式与 `scripts/model_tools/build_keep_head_shim.ps1` 完全一致（同 `-O2`、同一份
  `include/llama.h`、同一个 `libllama.dll.a` 导入库）；**未启用 CUDA**，
  `qlh_kh_load` 恒 `n_gpu_layers = 0`。
* 本次**没有**覆盖生产默认路径 `build/keephead/build-cpu/bin/qlh_keep_head.dll`（避免影响
  并发会话与既有部署）。要启用：

  ```powershell
  # 方式 A：指向新目录
  $env:QLH_KEEP_HEAD_SHIM = '<repo>\build\keephead\build-cpu-skiplogits\bin\qlh_keep_head.dll'
  $env:QLH_LAYER_SKIP_LOGITS = '1'
  # 方式 B：用新 DLL 覆盖默认产物，然后只设开关
  ```

## 5. 未做 / 未验收

* **端到端未测**：三机流水线的整体步时（全局约 10% 的说法）**没有**复现 —— 本文只测
  本机单段。目标基线 139 → 99 ms 在本机复现为 122.6 → 102.6 ms（幅度较小，
  可能与工件/负载/机器状态有关），**不宣称**已达成用户的端到端数字。
* **生产默认 DLL 未替换**（见 §4），因此该优化**尚未在任何服务里生效**。
* 只在 **qwen35** 工件上实测；`qwen2` 分支代码上同样走 `build_inp_out_ids`（`qwen2.cpp:69`），
  但**未实测**。其他架构未评估（本 shim 目前也只登记了这两个架构的 `layer_inp` 槽位）。
* **prefill（多 token）形态未单独测**：本文全部为单 token 增量 decode。
* **未跑 CUDA**：本机显卡按要求未使用；`qlh_kh_load` 本身恒 CPU。
* `QLH_LAYER_SKIP_LOGITS` 未接入 `scripts/start_pc_layer_worker.ps1` 的参数面（只在注释里
  说明）；`-Detach` 走计划任务、**不继承**当前 shell 的环境变量，需要时请在该任务内设置。
