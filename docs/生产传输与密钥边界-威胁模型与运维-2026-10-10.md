# 生产传输与密钥边界：威胁模型与运维（2026-10-10）

> 状态：**现行**
> 更新日期：2026-10-11
> 适用范围：`SEC-BOUNDARY-01` 的生产信任边界、允许的传输形态、凭据生命周期与节点撤销顺序。

## 1. 文档定位

本文定义 `SEC-BOUNDARY-01` 的生产信任边界、允许的传输形态、凭据生命周期和节点撤销顺序。它回答“哪些链路可用于生产”“长期 `cluster_secret` 由谁保护”“节点丢失后按什么顺序撤销”，不把本机单测、loopback TLS 或编译成功写成真实设备/真实网络验收。

关联记录：

- 排票与验收状态：[彻查后修复与重构排票计划](彻查后修复与重构排票计划-2026-10-09.md)票 9 `SEC-BOUNDARY-01`。
- 已修问题：[已知问题记录](已知问题记录.md)#89。

本文不改变以下架构不变量：

1. master 是唯一协调节点和 worker 数据转发中心。
2. worker 不建立 worker peer 数据连接。
3. D→L、L→L 多段接力保持既有顺序语义。
4. Route-A 保持 master 编排的顺序执行，不改成 mesh 或 worker 自主路由。

## 2. 保护对象

本票保护的对象包括：

- 长期集群根凭据 `cluster_secret` 及其 `cluster_secret_epoch`。
- bootstrap 一次性请求私钥、request nonce 和返回凭据信封。
- JoinGrant issuer/target 私钥、一次性 grant nonce 和待处理入群请求。
- TCP 注册身份、连接代次与防重放状态。
- Android/PC 本地凭据副本、系统备份、诊断包和日志输出。

模型权重、聊天内容、推理张量、操作系统补丁、Tailscale 账户本身和软件供应链不由本票单独解决；其中能影响上述凭据安全的部分在“边界外威胁”中明确列出。

## 3. 信任根

### 3.1 跨机网络信任根：Tailscale

生产跨机 bootstrap 与 legacy TCP 依赖 Tailscale/WireGuard overlay 提供链路保密性、完整性和设备准入。服务端只把 loopback、Tailscale IPv4 `100.64.0.0/10` 和 Tailscale IPv6 `fd7a:115c:a1e0::/48` 视为受保护来源。

这意味着：

- “位于同一 Wi-Fi/LAN”不是信任证明。
- `QLH_TRUSTED_BOOTSTRAP_CIDRS` 只保留发现/兼容语义，不能把自定义 LAN 变成可取得长期凭据的安全通道。
- 被撤销节点必须先从 Tailnet 移除；只在 QLH 内删节点记录不足以切断其网络信任。

### 3.2 PC 本地信任根：本机 OS 用户边界

PC 侧 `node_config.json` 不再保存明文 `cluster_secret`，只保留公开引用/epoch 投影；长期 secret 与 epoch 作为同一原子加密记录，JoinGrant 私钥与 TOTP seed 也使用用户目录下的 AES-GCM `LocalSecretStore`。加密记录是凭据唯一事实源，启动时必须覆盖陈旧 `.env` 投影，避免轮换后重启静默回滚；SQLite、WAL/SHM sidecar 和凭据文件显式收敛到当前用户权限。但 wrapping key 与密文仍位于同一用户安全域，其安全性依赖本机 OS 的用户目录、ACL、进程隔离和账户完整性。

该边界主要防止配置文件、普通诊断包、误提交和只复制 `node_config.json` 时泄密；它**不**声称能抵御本机管理员、root/SYSTEM、已攻陷的当前用户账户、进程注入、内存转储或同时窃取密文与 wrapping key 的攻击者。

### 3.3 Android 本地信任根：Android Keystore

Android 侧长期凭据使用 AndroidKeyStore 中不可导出的 AES-256 key 加密，SharedPreferences 只保存 AES-GCM ciphertext 与 IV。旧 DataStore 明文 secret 在成功迁移后删除；key 无效、记录损坏或认证失败时 fail-closed 并清除不可用记录，节点需要重新 bootstrap。

当前只验证了 JVM 合同和 instrumentation 编译，尚未在真机或模拟器执行 `ClusterCredentialStoreInstrumentedTest`，也未证明目标设备一定使用 hardware-backed/StrongBox。文档只声明“依赖 Android Keystore 的非导出 key”，不声明硬件级抗提取能力。

### 3.4 人类高危操作信任根：管理员会话 + TOTP

集群根凭据轮换只允许当前 master 上的已登录管理员调用，并要求 Auth App/TOTP 一次性确认。TOTP seed 不再明文保存在 SQLite；节点强制注销、离线记录删除和 master identity reset 也必须是实名管理员，即使全局认证仍处于兼容模式也不能匿名执行。TOTP 证明的是高危操作的人类确认，不替代 Tailnet 设备撤销，也不替代本机 OS/Android Keystore 的本地保护。

## 4. 传输准入矩阵

| 通道 | 允许用途 | 生产定位 | 关键限制 |
|---|---|---|---|
| loopback bootstrap | 本机初始化、测试和同机组件接入 | 允许 | 只接受 `127.0.0.1` / `::1`；仍使用一次性凭据信封 |
| Tailnet bootstrap | 跨机首次取凭据、重新 bootstrap | 生产允许 | 来源必须是 Tailnet；自定义 LAN CIDR 不足以放行 |
| loopback legacy TCP | 同机 worker/control data | 生产允许 | 注册仍要求 v2 HMAC、nonce、时间戳和 epoch |
| Tailnet legacy TCP | 当前跨机控制/数据面 | 生产允许 | TCP 载荷本身不是 TLS；保密性/完整性依赖 Tailscale overlay |
| custom LAN legacy TCP | 临时实验/故障诊断 | 默认拒绝 | 仅 `QLH_ALLOW_UNPROTECTED_CLUSTER_TCP=1` 显式放行；属于明文不安全模式 |
| loopback WSS | Transport v2 协议、证书 pin 和故障语义诊断 | 非生产 | 只绑定 loopback，使用本地临时 CA；不是公网证书或真实 443 网关 |
| 真实 443/WSS | 未来生产候选 | 尚未验收 | 当前不得宣称已具备跨机生产合同 |

`QLH_ALLOW_UNPROTECTED_CLUSTER_TCP=1` 只放宽 legacy TCP 的来源检查，不会放宽 `/api/bootstrap/first-connect`。运维不得先打开明文 LAN，再依赖自动 bootstrap 把长期 secret 送过去。

## 5. Bootstrap 凭据交换

### 5.1 请求

每次 bootstrap 都创建新的临时 RSA-2048 keypair、18-byte request nonce 和请求时间。私钥只保存在调用进程内存中，不写入配置、日志或启动 JSON。

### 5.2 响应

服务端只在来源同时满足 loopback/Tailnet 安全来源、master 角色和 bootstrap 开关时生成信封：

- 内容使用随机 AES-256-GCM key 加密。
- 内容 key 使用客户端临时 RSA 公钥和 RSA-OAEP-SHA256 包装。
- AAD 绑定 `cluster_id`、`node_id`、request nonce、`cluster_secret_epoch`、签发时间和过期时间。
- bootstrap request nonce 在 SQLite ledger 中原子消费；同一 nonce 的再次提交被拒绝。
- 原始 HTTP JSON 只包含 ciphertext envelope 和公开连接信息，不直接包含长期 `cluster_secret`。

客户端必须验证 schema、算法、node/cluster/nonce/epoch 绑定和有效期，再解密并持久化。任何绑定不一致、过期、重复消费或认证失败都必须重新发起全新 bootstrap，不复用旧 key/nonce。

## 6. 本地落盘、迁移与备份

### 6.1 PC

- `node_config.json` 只保存 `cluster_secret_ref` 和 `cluster_secret_epoch`。
- 旧用户配置或安装目录 `node_config.json` 中的明文 secret 在读取时迁入 `LocalSecretStore`。
- 已有加密记录是唯一权威事实源：低 epoch legacy 明文不得覆盖更高 epoch 记录；primary 配置迁移失败不得回退另一份旧安装配置。
- 密文存在但 wrapping key 缺失时必须 fail-closed，不得回退 `.env`，也不得生成新 key 覆盖不可解密记录。
- 安装目录旧文件在迁移成功后优先删除；删除失败时原子重写为脱敏配置，避免旧副本继续保留明文。
- JoinGrant issuer/target 私钥从 SQLite 明文字段迁入同一类加密 store；SQLite 只保留引用。
- TOTP seed 同样迁出 SQLite 明文；重新绑定在同一事务中吊销该账户全部旧会话，客户端必须按 `reauth_required=true` 重新登录。
- `node_secrets.json` 与其 wrapping key 文件都属于敏感用户数据，不得进入支持包、普通备份、代码仓库或共享目录。

### 6.2 Android

- AndroidKeyStore key 不进入 DataStore、SharedPreferences、worker startup JSON 或日志。
- SharedPreferences 中只保存凭据 ciphertext/IV；旧 DataStore secret 迁移成功后删除。
- `backup_rules.xml` 与 `data_extraction_rules.xml` 同时排除认证会话、集群凭据、DataStore、日志和数据库，覆盖旧版 Auto Backup 与 Android 12+ cloud/device transfer。
- 备份规则的源码/JVM 合同已验证，但签名 release 在真实 Android 备份/恢复流程中的行为尚未验收。

### 6.3 日志

PC/Android 诊断输出不得打印 cluster secret、JoinGrant 私钥、bootstrap private key、PEM 或同类敏感字段。Android 在写文件和 Logcat 前统一脱敏；运维仍应把历史旧日志和迁移前备份视为潜在敏感材料。

## 7. 注册、重放和一次性授权

### 7.1 Legacy TCP 注册

注册认证使用 v2 HMAC，签名绑定：

- `node_id`
- 有限数值时间戳，允许窗口为 ±5 分钟
- 18-byte 随机 nonce
- `cluster_secret_epoch`

服务端校验当前 epoch、时间窗和 HMAC，并以有界 replay cache 在同一服务进程内跨连接消费 `(epoch, nonce)`。该 cache 不是 durable ledger；master 进程重启会清空它，因此本文不声明“跨重启的严格 nonce 一次性”。生产安全仍要求 Tailnet 准入、短时间窗、secret 未泄露和时钟同步。

HMAC 只认证注册，不为后续 legacy TCP payload 提供加密。跨机 payload 的保密性与链路完整性来自 Tailscale；在 custom LAN 上打开不安全开关等于接受明文链路风险。

### 7.2 管理身份边界

账户列表、修改、删除、非首次账户创建以及 TOTP 绑定/校验必须由实名角色执行；全局认证兼容模式不得把匿名主体提升为这些管理操作的合法调用者。节点强制注销、离线记录删除和 master identity reset 同样强制实名管理员，避免“匿名重置管理员口令—取得实名 token—接管集群”的链式路径。

### 7.3 JoinGrant

JoinGrant 在任何角色切换、配置写入或网络连接副作用前验证并原子消费 nonce。随后若连接失败，旧 grant 也不得重试，必须生成新的待处理请求和新 grant。这样可避免“先改状态、后发现授权被重放”的事务倒序。

## 8. 节点撤销与密钥轮换 Runbook

节点丢失、转让、疑似泄密或需要强制全群换根时，必须按以下顺序执行：

1. **先从 Tailnet 撤销节点。** 在 Tailscale 管理面移除/禁用目标设备或使其设备凭据失效，确认它不再拥有 overlay 访问能力。
2. **确认当前操作节点是有效 master。** 使用已登录管理员会话，准备当前 TOTP；不要在 client、旧 master 或来源不明的管理入口执行。
3. **调用轮换接口。** `POST /api/cluster/credentials/rotate`，请求体包含当前 `otp_code` 和 `tailnet_revocation_completed=true`。如果未确认 Tailnet 撤销，接口以 `tailnet_revocation_required` 拒绝。
4. **由服务端完成原子切换。** master 先在 TCP client registry 锁内轮换 `cluster_secret` 并递增 epoch，再清空现存/待确认 peer 并关闭 socket。响应只返回新 epoch、断链数和 `rebootstrap_required=true`，绝不返回新 secret。
5. **剩余可信节点重新 bootstrap。** 仅通过 loopback/Tailnet 重新取得新凭据信封；旧 secret/epoch 的注册必须失败。不要通过聊天、邮件、共享文件或 custom LAN 明文复制新 secret。
6. **复核旧节点未回归。** 观察节点列表与注册日志，确认被撤销节点没有重新注册，剩余节点均以新 epoch 建立连接；异常节点继续保持隔离并重新走 bootstrap。

`tailnet_revocation_completed=true` 只是已登录管理员对运维前置步骤的声明，QLH 当前不会调用 Tailscale API 核验设备状态。它不能阻止仍拥有 Tailnet 成员资格的旧节点再次 bootstrap；因此第 1 步的控制面撤销才是真正安全边界，声明字段不得被当作技术证明或自动撤销机制。

若第 3～4 步返回失败，不得假定轮换已完成，也不得手工恢复旧节点。先保留 Tailnet 撤销状态，检查 master 本地 secret store/config 写入与 TCP server 状态，再重新执行受控轮换。

## 9. 凭据丢失与恢复

- PC secret store/key 损坏或缺失：视为本节点凭据丢失，从 Tailnet 可信 master 重新 bootstrap；不要从旧日志或备份恢复明文 secret。
- Android Keystore key 失效、App 数据被清除或 ciphertext 认证失败：清除不可用记录并重新 bootstrap。
- 节点时钟偏差超过注册窗口：先恢复可靠时钟同步，再重新连接；不得扩大时间窗绕过校验。
- master secret store 损坏且没有可信恢复材料：建立新的集群根并让所有保留节点重新 bootstrap，而不是从 worker 反向收集 secret。

## 10. 边界外威胁与未声明能力

以下事件超出当前安全边界，发生时应按主机/账户全面失陷处理，而不是依赖本票继续保密：

- Tailscale 控制面、组织账户、ACL 管理员或节点设备身份被攻陷。
- master 本机管理员/root/SYSTEM、当前用户账户、进程内存或调试权限被攻陷。
- Android OS/boot chain/Keystore 被攻陷，或攻击者具备足以绕过应用沙箱的物理/系统权限。
- 构建、依赖、签名密钥、更新链路或发行物供应链被攻陷。
- 模型/张量侧信道、流量分析、可用性攻击和 Tailnet 内已授权恶意节点造成的资源滥用。
- 迁移前已产生的明文配置、旧备份、旧日志或第三方诊断包已被复制。

当前也不声明以下能力已经完成：

- 真实公网/跨机 443 WSS 生产网关。
- Windows 干净机安装/升级后的旧配置迁移与 ACL 验收。
- 签名 Android release 的 cloud backup/device transfer 恢复验收。
- Android Keystore instrumentation 真机/模拟器执行或 hardware-backed/StrongBox 证明。
- 真实 Tailnet 下的撤销、secret rotation、全连接断开和多节点重新 bootstrap 演练。
