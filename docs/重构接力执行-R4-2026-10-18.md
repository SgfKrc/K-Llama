# 重构接力执行 R4

> 状态：**现行**（R4软件门完成）
> 更新日期：2026-10-18
> 适用范围：`REFACTOR-EXECUTION-01` 的冻结接力计划、本地 native owner、有界 FIFO、请求终局与清理、判停、采样准入及独立恢复域。客户端切换与裁撤由 R5 接续；发行物与多设备模型验收属于 R6。

主[api_server.py](../src/api_server.py)`_execute_chat_full`、[routes_chat.py](../src/api/routes_chat.py)`chat/chat_stream`及独立[EngineHost](../src/inference_service/engine_host.py)`chat_full`传入同一请求 deadline 和会话 revision。已发布线性请求从主 API 进入时跳过外层模型执行锁，native 互斥由运行时 owner 承担。线性结果的错误、首 token 即 EOS 的空完成以及结果处理异常均保持具名终局；追问使用模板，避免对首段模型发起额外整请求计算。

## 2. 冻结计划与身份围栏

[execution.py](../src/qlh_core/contracts/execution.py)`ExecutionPlan/Segment`为不可变合同。计划至少包含两个不同计算节点；连续非空 proper segments 完整覆盖 decoder，master 首段承担 embedding，LM head 恰好归属首段或尾段。`digest`覆盖部署与 boot、authority、总层数、每段身份、connection 及完整 assignment payload。

`ExecutionApplication.freeze/current`从 durable active deployment 构造计划，并在每段前后重验当前 boot、authority、connection、部署有效性、输入版本和远端 incarnation。远端须广告非空`node_incarnation`及`stage_kv_cleanup=True`；缺少时分别返回`execution_node_incarnation_unsupported`、`execution_kv_cleanup_unsupported`。PC 广告 model-control boot ID；Android 的[TaskWorkerService.kt](../android/app/src/main/java/com/qlh/inference/worker/TaskWorkerService.kt)在服务实例内生成稳定 UUID。进程或服务换代使冻结 attempt 失效。

`StageIdentity`包含 authority、deployment、assignment、incarnation、connection、request、attempt 和 step；`LinearExecutor.accept`拒绝身份不匹配，同身份同摘要结果幂等，冲突摘要返回`execution_stage_result_conflict`。底层 task-worker 继续核对已准备 assignment、provider attempt、lease 和连接身份。hidden 由 master 接收及转发，保留既有二进制帧、预算与分片合同。

## 3. 请求终局、取消与 native 清理

`RequestService`提供有界 FIFO，容量由所属`PipelineQueue`的现有配置传入。队满返回`request_queue_full`；pause 拒绝新准入，存量继续。队列取消立即释放等待容量，执行取消决定终局后仍保留物理执行槽。`phase/terminal/outcome`与`execution_state`分别记录，后者按`waiting → running → draining → stopped`推进；清理未证实则保留`cleanup_pending`并隔离对应 deployment。重试创建新 RequestId／AttemptId。

[deadline.py](../src/qlh_core/contracts/deadline.py)`RequestDeadline`保留本地 monotonic 截止与 wire epoch 表达，准入、排队、前向、远端等待和清理共同使用原 absolute deadline。[outcome.py](../src/qlh_core/contracts/outcome.py)`TerminalOutcomeLatch`保持首写终局。旧`request_deadline/request_outcome`模块重导出同一类型；相同语义的 deadline reason 也由 relay、worker 和 outcome 引用该唯一常量。

[task_worker_adapter.py](../src/task_worker_adapter.py)`RemoteFullWorkerProvider.execution_drained`只接受物理 result／error、明确`execution_stopped`或执行前拒绝等证据。释放 reservation、取消 ACK 的`execution_in_flight`均保持等待；PC 的[scheduler_task_worker.py](../src/scheduler_task_worker.py)在实际执行 finally 后补发 stopped 回执，Android 复用既有物理结束回执链。

`NativePorts.cleanup`等待已发送 attempt 物理结束，向使用过的远端段发送`cleanup_only`并核对精确`{"kv_cleared": true}`输出，最后清本地 KV 并释放 native 执行锁。PC 的[EngineHost.execute_task_worker_stage](../src/inference_service/engine_host.py)及[LlamaCppEngine.clear_pipeline_kv](../src/llama_engine.py)执行实际 reset；Android 的[AndroidFullWorkerStageExecutor.kt](../android/app/src/main/java/com/qlh/inference/worker/AndroidFullWorkerStageExecutor.kt)、[LocalInferenceEngine.kt](../android/app/src/main/java/com/qlh/inference/service/LocalInferenceEngine.kt)和[qlh_llama_jni.cpp](../android/app/src/main/cpp/qlh_llama_jni.cpp)`nativeClearLayerKv`连到`llama_memory_clear`。清理消息先验证已准备身份，执行失败保留债务。

`ModelHost`的装载、切换、commit／abort、卸载以及供给 GC 与 native 执行互斥；取消后卸载要等待实际计算及本地清理返回。`RuntimeServices.close`先等待请求 owner 成功排空；超时保留依赖资源和关闭失败状态，计算停止后可重试关闭。manager 和发布诊断在 owner publication 锁内观察，F05 的旧 host 镜像遮蔽由显式属性投影消除。

## 4. 采样、判停与会话

`SamplingPolicy.for_request`集中区分默认与显式参数；主 API 和独立`/v1`请求模型的`pipeline_sampling`共用它。分布式入口与转发在客户端未显式提供采样参数时使用`temperature=0, top_p=1`，OpenAPI 既有字段默认值保持原合同；显式参数原样保留，由`require_greedy`对非零 temperature 返回`route_a_sampling_unsupported`。单纯标量 argmax 的当前执行能力按 greedy 准入。

[stopping.py](../src/qlh_core/execution/stopping.py)`StopPolicy`统一处理 EOS、token 上限及文本 stop。跨 token 停止串的潜在前缀和未完成 UTF-8 后缀保留到判定后再发送；完成输出与已发送 token 前缀保持一致。兼容 Route A 循环共用该判停策略及 greedy 准入，F15 正确目标断言转为正常通过。

[chat_context.py](../src/chat_context.py)`ConversationContextService.commit_turn`继续以 prepared revision CAS 提交成功 turn；取消和部分输出保留独立请求记录。请求生成终局与会话 CAS 是相邻提交，当前事务边界分别属于 request journal 和会话存储。外层 API／SSE 的会话串行锁、active session 及 facade 消费者收敛由 R5 继续迁移。

## 5. 持久化与恢复语义

`SqliteRequestRepository.transact`在一个本地 SQLite 事务中写入请求聚合和`request_journal_events` hash chain。记录包括 revision、observed_at、boot、authority、plan digest、冻结 assignment 身份、sampling、context revision、absolute deadline、终局与资源状态；提交范围为`local_sqlite`。

`RequestService.start`校验完整日志链，损坏以`request_journal_corrupt`拒绝恢复。新 boot 将未完成生成结束为`request_process_restarted`，未证实停止的资源标为`recovery_required`；KV 按新 attempt 重新建立。写盘失败关闭后续准入、保留诊断并继续物理清理。已耐久完成的终局保持 completed，后续诊断写盘失败单独关闭准入。

[cluster_auto_role_runtime.py](../src/cluster_auto_role_runtime.py)`JournalPrefixAuthority`分别核对`requests:v1`与`model-control:v1`。承诺的 request floor 缺失、倒退或分叉时拒绝提议与恢复；旧 workflow 水位只证明旧域。跨主多数复制和物理接管验收属于独立 HA 门，当前证据范围为本地耐久提交。

## 7. R5／R6 接续边界

R5 `REFACTOR-CLIENT-CUTOVER-01`继续将 API／SSE／TUI／Android 切到版本化快照，统一队列及错误投影，裁撤旧 PipelineQueue／MLFQ／抢占、通用任务图／PoC 和独立 Launcher，并同步依赖、配置、构建与测试。`task_provider` DTO／provider adapter、旧模块重导出、ModelHost 未知属性代理及旧无 spec 执行入口目前仍为兼容面；F14 的旧 readiness 字符串解析随客户端适配迁出。request 历史当前保留在进程记录和 SQLite 日志，保留期与压缩策略按后续产品要求设置。

R6 `REFACTOR-PRODUCT-GATE-01`执行新发行物首启／迁移、实际多设备 9B LL／DL、节点数量变化、掉线／取消／重入及独立无整模观测。旧节点缺少新 incarnation／cleanup 广告时按具名能力拒绝，部署新构建后进入该验收。native 编译、fixture 清理及软件端口测试分别提供对应层证据；R2／R3 历史原件及原验收数字继续保留在原目录。
