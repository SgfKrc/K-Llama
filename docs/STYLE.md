# 文档体例规范

> 状态：**现行**
> 更新日期：2026-11-03
> 适用范围：`docs/` 下除记录清单外的全部文档。这些文档会直接并入技术报告与说明书，
> 因此按正式技术文档写，不按工作笔记写。

---

## 1. 一条硬规则

**文档只陈述结论与证据，不记录本文档自己的修订过程。**

读者拿到的是定稿，他不需要知道「这里原先写的什么、后来怎么改、为什么改」——那些
属于 commit message。判断方法：把这句话删掉，读者的技术理解若不受影响，它就是修订
痕迹，删。

| 禁止（工作笔记） | 应为（技术文档） |
| --- | --- |
| 初稿写 X，**作废**，实为 Y | 该项为 Y。依据：…… |
| 早先这里写「k=1 亏损」，那是漏了免费 token | k ≥ 2 才有意义（§10）。 |
| 原稿只给基线数字没说怎么测，**已改** | 测量方法：3 轮交替取中位数并报噪声底。 |
| 这条曲线**推翻了两个直觉** | 两条常见假设不成立：…… |
| 与初稿的差异、勘误、补充说明 | 并入正文对应章节，或删除 |

**项目演进史不是修订痕迹**，可以写：主语是系统（「旧仓库的 ANSI 界面已弃用」）就写，
主语是本文（「原稿」「上一节」「本文原先」）就删。

## 2. 元信息

每篇开头三行加一个分隔线：

    # 标题
    > 状态：**现行**
    > 更新日期：YYYY-MM-DD
    > 适用范围：一句话说明读者与边界

状态只能取下列之一：

| 取值 | 含义 |
| --- | --- |
| **现行** | 描述的系统行为与当前代码一致 |
| **已实现** | 功能已落地，文档描述其行为 |
| **已验证** | 结论有实测或源码证据支撑 |
| **方案** | 设计或评估，代码未实现 |
| **未实现** | 明确不做或待做 |
| **已退场** | 曾经生效、现已废弃（正文说明替代物） |

不把「待拍板」「草稿」「进行中」「未收敛」当状态值。决策未定用 **方案** 并在首段写
「待定项：……」；缺陷根因未定位用 **已验证**（已验证的是现象）并在首段写「未定部分：
……」。

## 3. 结构

按需要选骨架，章节号连续、不留空号：

- **说明类**（ARCHITECTURE / DEPLOYMENT / PACKAGING / TESTING / TUI / RESPONSES-API）：
  1 问题 → 2 设计 → 3 实现 → 4 约束与失败模式 → 5 验证
- **评估类**（ANDROID-SURFACE / EXLLAMAV3 / PRIMA / THREE-SEGMENT）：
  1 结论 → 2 方法与切点 → 3 实测 → 4 分解与归因 → 5 边界 → 6 证据等级
- **方案类**（SLIM-ARC / LILICORR / AUTO-ASSIGN）：1 结论 → 2 依据 → 3 方案 →
  4 代价与风险 → 5 未做
- **缺陷类**（ISSUE-*）：1 现象 → 2 复现 → 3 定位 → 4 根因 → 5 修复与验证

已有文档不强制重排，但必须删掉「与其他稿的差异」「勘误」「补充」这类章节，把仍有
价值的内容并回对应章节。

## 4. 数字

- **一个测量只有一个权威出处**。首次给全（设备、线程数、n、口径），别处引用写
  「见 X 文档 §n」，不重复数字——重复的数字迟早不一致。
- 报中位数同时报分散度（p90 或 min–max），不报孤立平均数。
- 数字带单位与口径：`206.1 ms/token（n=24，greedy）`。
- 推算值标「推算」并写算式，不与实测值混排在同一张表里不加区分。
- 每篇不超过 240 行。超出部分是冗余，不是深度。

## 5. 术语

| 用 | 不用 |
| --- | --- |
| 段 / stage | 节点、分片 |
| 头段 head / 中继段 relay / 尾段 tail | 主段、从段 |
| 整模 + `layer_range` | 完整模型、全量模型 |
| hidden（段间张量） | 中间结果、激活值 |

「草稿」在投机语境是术语（draft），正常使用；不要用它指「本文草稿」。

## 6. 豁免

下列是**记录清单**，允许过程、时间顺序与多次修订，不套用 §1–§3，但仍受 §4 约束：
`PROGRESS.md`、`MEASUREMENTS.md`、`INVENTORY.md`、`FIXES.md`、`BASELINE.md`。

## 7. 交稿前检查

1. 搜「初稿 / 原稿 / 原 § / 早先 / 已改 / 作废 / 推翻 / 勘误」——出现即处理。
2. 状态行在 §2 取值表内，且带更新日期。
3. 每个数字带口径；跨文档引用的数字与权威出处一致。
4. 交叉引用指向的章节存在（`§n` 与实际标题对得上）。
5. 没有「待补」「TODO」「见下」这类占位。
