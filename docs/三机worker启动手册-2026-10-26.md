> 目的：**重启 worker 不需要重新摸索**。这份手册记录实际可用的启动方式与踩过的坑，
> 用于 LOCAL-EXECUTORS-01 及后续所有需要三机在线的验收。

## 1. 本机（master）

```powershell
cd G:\C\PYT\qlh
$env:PYTHONUTF8 = '1'
Start-Process cmd.exe -ArgumentList '/c','koakuma.bat --no-splash' -WorkingDirectory 'G:\C\PYT\qlh' -WindowStyle Hidden
# 等 8000 LISTEN
```

**注意**：`--no-splash` **不是** `qlh.py` 的合法参数（只认
`--port/--route/--host/--thinking/--log-token`），它一直被静默忽略。加不加都一样。

## 2. surface

仓库：`C:\Users\surface\Documents\LEDS_BJTU`。

```powershell
$key = "$env:USERPROFILE\.ssh\id_ed25519"
$remote = 'surface@100.100.52.106'
# 必须脱离 SSH 会话，否则 SSH 一断进程就被杀：
$cmd = 'cmd.exe /c "cd /d C:\Users\surface\Documents\LEDS_BJTU && koakuma.bat >> C:\Users\surface\Documents\LEDS_BJTU\qlh-surface.out 2>&1"'
ssh -i $key $remote "wmic process call create '$cmd'"
```

**坑**：
1. 只用 `surface` 这个用户名能连上（`koakuma` 是本机的名字，不是它的）。
2. **`textual` 缺失会让启动直接失败**，报
   `[错误] 未安装 textual —— 交互外壳需要它`。修复：
   ```powershell
   ssh -i $key $remote "cd /d C:\Users\surface\Documents\LEDS_BJTU && python -m pip install -r requirements-tui.txt"
   ```
   （设备重启后环境可能又缺，2026-10-26 已装 `textual 8.2.8`。）
3. 用 `wmic process call create` 让进程脱离会话；直接 `ssh ... koakuma.bat` 会在
   SSH 退出时被杀。
4. 顺带发现：`qlh-sync-s2` 这条 SSH key 是 forced command，指向
   `C:\Users\surface\Documents\LEDS_BJTU\tools\ssh_sync_helper.py` —— **该文件不存在**，
   走它会报 `No such file or directory`。同步是否完整值得单独核。

日志：`C:\Users\surface\Documents\LEDS_BJTU\qlh-surface.out`

## 3. y700（Android APP + Termux）

worker 是**原生 APP**，不是 Python 进程。

```powershell
# 1) 无线 adb（USB 也可，现有 USB 设备是 HA26PYZQ，不是 y700）
adb connect 100.99.211.13:5555
# 2) 启动 APP
adb -s 100.99.211.13:5555 shell 'monkey -p com.qlh.inference.debug -c android.intent.category.LAUNCHER 1'
# 3) 确认
adb -s 100.99.211.13:5555 shell 'dumpsys activity activities | grep topResumedActivity'
#   期望 com.qlh.inference.debug/com.qlh.inference.MainActivity
```

**包名**：`com.qlh.inference.debug`（另有 `...debug.test`、`com.qlh.acceptance.jniprobe`）。

### Termux sshd（只在需要 SSH 进 y700 时）

设备重启后 **Termux 的 `sshd` 不会自动起**，表现为
`banner exchange: Connection to UNKNOWN port -1: Connection refused`。
用 adb 起它（**sshd 在 `usr/bin`，不是 `usr/sbin`**）：

```powershell
adb -s 100.99.211.13:5555 shell 'run-as com.termux /data/data/com.termux/files/usr/bin/sh -c "/data/data/com.termux/files/usr/bin/sshd"'
# 验证
ssh -i $env:USERPROFILE\.ssh\id_ed25519 -p 8022 u0_a250@100.99.211.13 'echo SSH_OK'
```

`run-as com.termux` 可用（uid `u0_a250`），所以无需 root。

**y700 上没有 `qlh.py`**（只有 `qlh-3voter/`、`qlhprobe/`、`qlh-tools/`、`qlh-jr/`
与 `qlh-app-debug.apk`）⇒ **它不通过 `koakuma.bat` 启动**，只走 APP。

## 4. 一键核对清单

1. `Get-NetTCPConnection -LocalPort 8000 -State Listen` ⇒ LISTEN
2. `adb connect 100.99.211.13:5555` ⇒ device
3. 启 APP（第 3 节）
4. surface 若未起 ⇒ 第 2 节
5. `online_count == 3`
6. 供给：`POST /api/models/intent {model_id:"qwen3-5-9b", quant_type:"int4"}`，
   轮询 `/api/models/intent/current` 到 `ready`
7. 日志（`%LOCALAPPDATA%\QLH-Edge-Inference\state\logs\qlh-<date>.log`）查
   `容量输入区间` / `容量求解结果`

## 5. 2026-10-26 真机实测记录

三机全在线，供给 `admitted=True`、`domains` 全 0：

```
容量输入区间: [('master','',     [[0,8]],   [[0,8]]),
               ('android','',    [[8,20]],  [[8,20]]),
               ('TABLET','',     [[20,32]], [[20,32]]),
               ('master','cpu',  [[8,24]],  None)]
容量求解结果: assignments = master[0,8) + android[8,20) + TABLET[20,32)
```

**CPU 段仍未被选**。根因与离线探针不同：本机 CPU 段的 `layer_ranges=[[8,24]]` 是
**精确匹配**语义 ⇒ 只能吃满整段 **16 层**；而两个远端各 12 层的方案在目标函数第二项
`Σ work²/weight`（均衡项）上更优。同样 3 段，求解器选了远端组合。

注意这里 `android`/`TABLET` 带 `candidate_layer_ranges`（来自本轮规划），
而 CPU 段没有 —— 但真正卡住它的是**区间刚性**，不是候选锁。
⇒ 解法：给本机 CPU 段也开 `layer_budget.local_cut`，让它能像远端一样按容量自适应切分。
需要把 `per_layer_bytes` 传进 `_local_cpu_executor_record`（现为 `static`，拿不到
descriptor）。**待下一轮实现。**
