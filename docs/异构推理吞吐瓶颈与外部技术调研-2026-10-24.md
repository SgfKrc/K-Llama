## 1. 调研结论与采用顺序

QLH 的优化空间同时存在于**控制面热路径、实际引擎与量化、执行调度、通信和跨轮状态复用**。当前短上下文的慢速已有逐步完成回执及 Python 栈采样支持，优先处理[#132 完整状态重复读取](已知问题记录.md#132-逐-token-部署校验与-tui-查询反复读取完整控制面快照2026-10-24未修复)，再用固定模型和切点分离 native compute 与传输成本。将所有成本归为“异构设备或网络天然慢”，会漏掉已有证据指向的可消除工作。

| 方向 | 对 QLH 的直接价值 | 采用次序与前提 |
| --- | --- | --- |
| 精简执行视图、版本失效、查询复用 | 消除逐 token 的重复数据库读取／解析和查询投影，保留部署栅栏 | 首先做同条件 A/B；当前有实测热路径证据 |
| 实际后端、低位权重、GPU 内核与放置联合优化 | 减少目标模型每步权重读流量、kernel 启动和弱节点临界路径 | 与控制面实验并行；保存实际 load_spec 与原生回执 |
| 投机 token 块、连续批处理与请求流水 | 分别提高单请求有效输出率与集群总吞吐 | 分开目标与实验；补齐 hybrid 状态和多序列所有权 |
| KVMem／Fusion 的前缀复用、分层 KV、差量搬运 | 降低多轮 Agent 的重复 prefill，扩大有效历史与并发容量 | 高价值研究；先精确复用，再研究有损选页 |
| ActKV 的 action 价值与分页压缩 | 在长轨迹、内存受限、可并发的 Agent 服务中释放 KV 页 | 先构造 Agent 负载和质量门，再接注意力／分页后端 |
| SeqMoE／Strata 的专家预测、预取、固定槽 | 将 MoE 冷专家搬运与当前计算重叠，降低专家缺失等待 | 单独建立 MoE 实验线；当前 dense FFN 模型先做权重／内核实验 |
| GSQ-RCO 的低比特与混合位宽搜索 | 在质量预算内降低权重容量和流量，扩大较强执行器的可承层数 | 权重制品、内核、实际显存与任务质量共同验收 |

研究按“假设 → 最小原型 → oracle／负控 → 测量 → 迭代”推进。平台差异、缺少接口、论文暂未开源、回滚状态复杂，均转成可拆分的工程任务，影响排期而非取消优化方向。一次原型的负结果只否定所测配置，保留成本分解后继续改变内核、预算或调度方式；方向性的不可行结论须给出明确假设下的数学约束及推导，并标出改变假设后仍可研究的空间。

## 2. 当前链路为什么慢

### 2.1 当前证据与因果边界

实测复用 ready 部署，分开记录 HTTP 全程、初始 prefill、稳定 decode、远端 handoff／completed 和 cleanup。正式基线排除附加采样器的请求；口径、离散度、逐请求身份、分解及额外栈采样见 [R6 当前连续生成表](重构产品验收-R6-2026-10-19.md#异构连续解码基线与控制面热路径采样2026-10-24)。短答案请求可验证三机参与及正确终态，连续输出才足以估计逐 token 速度。

已确认的读取链是 `LinearExecutor._check → NativePorts.current → ExecutionApplication.current → DeploymentService.runnable → snapshot → SqliteModelControlRepository.read/_read`；stage 入口原生就绪检查也进入 runnable。源符号、调用次数、TUI 查询和候选修复统一登记于 #132。采样同时看到执行线程和 TUI 后端线程进入该路径。单一事实源允许从已提交状态生成精简的不可变执行视图；一致性要求约束的是版本、权威、生命周期和失效时机，而非每个检查点都解析全部供给历史。

远端 handoff 到完成包含传输、协议、排队、计算和回传；其余间隙包含 master 前缀计算、同步、数据转换、版本校验与 Python 调度。当前证据支持优先优化控制读取，完整节省比例仍由 A/B 确认。逐 kernel 归因需要补 CUDA event／native timer、消息编解码与传输埋点。

### 2.2 选择参数、硬件能力与实际执行必须对齐

当前各端实际引擎、精度、设备及承层以 [R6 运行时表](重构产品验收-R6-2026-10-19.md#缓存供给链路性能2026-10-24)及最终恢复身份为准：选择中的 `int4`、设备拥有 GPU、节点名称包含 GPU 型号，分别只是意图或硬件信息。性能归因读取 `load_spec`、native receipt、实际加载权重与设备执行证据。ROG 的 CPU 执行应先查准入和构建能力，再对照 GPU 执行；当前观察尚不足以把总退化归因于某一个后端。

源码已经定位两项能力边界：`src/model_module.py:_select_layer_runtime/load_layer_range` 的 PyTorch 层段路径支持 FP16／FP32，整模 bitsandbytes 的 int4／int8 属于另一条加载路径；`scripts/model_tools/build_keep_head_cpu.ps1:IsaProfile` 的生产 keep-head 构建显式关闭 CUDA。因而更换选择标签或只按硬件 GPU 评分，都不足以让这些层段获得低位 CUDA 算力。下一步把层段量化、CUDA keep-head 构建及设备准入做成独立实验，并核实 ROG 实际 DLL 的来源与 kernel 执行。

放置目标也须匹配实验目标。`src/qlh_core/planning/placement.py:placement_score_breakdown` 提供能力启发式，`src/qlh_core/planning/capacity.py:solve_pipeline_capacity` 在容量和参与策略约束下选择范围。相同层数包含不同类型层，embedding／head、full attention／recurrent、权重精度和 offload 又改变耗时。用同模型、同后端的逐段实测成本校准，才能评估“多分给强设备”是否缩短临界路径。

### 4.2 KVMem、Fusion 与 Bonsai：从中应拿走什么

**精确状态复用先于有损压缩。** KVMem 的 `MemoryStamp.frontier`、`BackendIdentity`、`PayloadLayout` 将逻辑历史、模型／后端身份与设备工作集分开；`MemoryTransfer` 以 prepare、spill／restore、publish／abort 处理页交换。Fusion 的 `ProgramImpl::inspect_capture` 允许可恢复的 Host-backed 状态发布，`prepare_materialization` 按需物化。[K1–K3、F2–F3] 这适合 QLH 多轮聊天和工具结果续接：token 前缀相同才复用，历史编辑使相应状态失效，接受前沿、tokenizer、权重、位置、KV dtype、GDN／recurrent state 一起绑定。

**原生字节存储与页选择分层。** `NativeKvPayload` 保存原生 K/V、scale plane 和 padding；换页本身保持字节。`HostKvStorage` 管理 Host／SSD 配额与延迟读取；`SelectionReason` 将新 query 召回与 prefill／decode 压力缩窗区分，`bounded_query/query_replay_plan` 限制检索和 replay 的工作量。[K1–K3] 可迁移为“先只实现精确归档和恢复，再加同预算选页”的两阶段实验，分别证明少重填与有损检索的效果。

**接受状态与统计同提交。** 图召回的接受统计和 checkpoint 对齐，草稿拒绝、replay、取消后缀不会当成成功历史；这是 QLH 投机和 Agent 轨迹缓存可直接借鉴的语义。[K3] 页所有权仍由执行该层的节点持有；跨后端交换需 layout 转换、位置和模型身份 oracle，不能只凭 hidden shape 相同认定 KV 兼容。

**CPU 分担有用，但须计完整成本。** Bonsai 的 `KvMemCpuQuery/kvmem_cpu_scores` 把检索索引与查询暂存放 CPU，AVX2／FMA 路径做打分，主干推理仍用 CUDA；embedding 和视觉也有 CPU 分工。[B1–B3] 对 Android 可先做标量 oracle，再做 ARM 向量化和原生布局适配；对跨机检索额外记录 query 往返、score 汇聚和同步，研究局部索引与异步预取是否足以覆盖网络成本。

KVMem 已验多 GPU 路径为**同主机、同 CUDA compute capability 的连续层 pipeline**；各卡持有本层 KV，支持 pinned-host 中转，作者文档将容量正确性与吞吐分开。[K4] 公共核心与算法可移植，现有发布包的平台范围用来确定原型拆分顺序。

### 4.3 ActKV：动作价值、反馈预算与分页压缩

[A1] 的真实标题为 *ActKV: Efficient LLM Agents through Action-Guided KV Cache Management*。论文在 observation–reasoning–action 边界，用 **action query 对历史 KV 的贡献**给条目评分。重要 observation 即使自身不属于 action token 也可被保留。attention-aware LRFU 形如：

\[
KS_t(i)=\lambda KS_{t-1}(i)+a_t(i)h_t(i).
\]

其中 a 为 action attention、h 为命中指示。反馈预算使用 top-k 概率的对数统计及趋势；论文算法在触发条件满足时扩大预算，实际算法只描述扩容和上限。它需要可靠 action 边界、attention／LSE 访问与阶段统计；action token 占比低与其余历史信息冗余需要分别证明，营销中的“零浪费”“只有动作重要”改写为可测试假设。淘汰后再扩容，恢复已丢 KV 还需保留 Host 历史或重放。

分页部分从 LSE 恢复局部 attention 值，避免为打分 gather 全部 KV；compaction 将保留槽与待覆盖槽构成不相交集合，进行无冲突并行拷贝并回收空页。论文的 `PagedCalAttn/Eviction/PagedCompaction` 是伪代码接口；QLH 当前原生状态合同需要实现真实的 score／page-table／迁移接口。

论文 §8.5 在单张 96GB 卡上用 Qwen3-30B／GPT-OSS-20B、一次提交 1500 个任务，报告平均 3.97× token throughput 和 3.58× task throughput；主要收益链包含页回收后容纳更多并发。长轨迹实验报告相对 FullKV 的平均质量与峰值 KV，压缩 kernel 微基准又是独立指标。QLH 先验证 Agent 任务正确率、内存、轨迹总时长，再比较单请求延迟与并发吞吐，保留全部指标。

### 4.4 SeqMoE：预测负责提前搬运，真实路由负责计算

[S1] 的 *SeqMoE: Toward Full-Load Performance via Predictive and Graph-Compatible MoE Offloading* 将跨 token／跨层专家激活建模为序列，使用另行训练的 Linear–Mamba2–Linear 预测器；排序和分布损失、teacher forcing／scheduled sampling 均参与训练。机制包含：

1. 预测未来专家需求，按 deadline 和 confidence 选择预取；缓存按预测的未来价值保留专家。
2. 固定基址槽和 `expert_id → slot_id` 间接寻址，使 Graph 执行结构稳定；GPU 管理元数据，CPU／copy stream 异步搬运。
3. 使用 tagged 状态保护在途传输与复用槽；miss 补齐真实 router 选择的专家，保证完整计算。

论文预取调度的计数容量模型依赖专家搬运成本近似一致。异构带宽、混合位宽和 SSD 随机读需要把“专家个数”换为字节／时间成本重新求解；论文公式存在需作者代码澄清的索引与更新细节，重实现应先给自己的可复核定义和 oracle。

论文短序列 batch1 的摘要结果为达到 FullLoad 的约 80.22%；模型、显存、总主存与 FullLoad 多 GPU 条件按论文 Table 1／Fig.6 分别记录，不能合成任意小卡的能力。Graph 兼容也主要针对 decode，论文 prefill 采用单独策略。对 QLH 当前 dense FFN，专家预测转成“预测下一层”不会消除其必经权重；可迁移的是固定缓冲、提前搬运、copy／compute overlap 和版本保护。MoE 模型另行研究专家稀疏性。

## 5. 数学约束与仍可改变的执行方式

### 5.1 单请求与多请求使用不同目标函数

固定模型、精确自回归、每步逐层计算且未投机时，token 的层段依赖形成串行关键路径。以互斥时间划分，

\[
T_{token}=\sum_i C_i+\sum_j N_j+H,
\]

其中 \(C_i\) 是各段计算，\(N_j\) 是关键路径通信，\(H\) 是其余串行控制／同步。数学限制是同一个 token 的后一依赖段须等待前一段结果；可优化的是每项耗时、切点、算子、传输方式，以及通过投机一次验证多个位置。

多个独立请求可在不同层段交错。理想稳定流水的资源上界形如

\[
X_{aggregate}\leq\min\left(\frac1{\max_i C_i},\min_j\frac{BW_j}{D_j}\right),
\]

这里忽略控制开销并假设资源独立，实际共享链路／CPU／显存要加资源约束。对于平衡的 P 段、M 个可调度微批，单次流水填充／排空模型的利用率为 \(M/(M+P-1)\)。QLH 现有整请求 FIFO 和整请求执行锁需要改为多序列状态及有界调度，才能检验该机会。所有请求共享 worker 是资源共享事实，实施调度后仍可交错利用不同资源。

### 5.2 量化与搬运的条件收益

对内存带宽受限、权重未跨 token 缓存命中的 dense decode，权重读取近似下界为 \(T_W\geq W_{read}/BW_{effective}\)。低比特降低字节，但解量化、混合层内核和更低 occupancy 可抵消收益；因此容量收益与速度收益分别测。batch 让同一次矩阵计算复用权重，MTP／投机验证也会改变矩阵形状。

offload 的关键路径缺失流量为 \(T_{miss}\geq B_{miss}/BW_{link}\)，固定主存映射或异步 API 仍受流量和延迟约束。若提前时间足够且没有资源竞争，预取可以覆盖等待；若提前时间不足，继续研究更大缓存、更早预测、少搬字节、调整切点或实际执行地点。dense 层每步仍需其权重，MoE 的未激活专家可以无需本步执行；两者用各自的 \(B_{miss}\) 计账。

### 5.3 投机的可获益条件

令一轮提交的有效目标 token 数为 A，草稿、验证、回滚和通信总耗时为 \(T_{round}\)，则

\[
X_{spec}=\frac{E[A]}{E[T_{round}]},\qquad
S=\frac{T_{base}\,E[A]}{E[T_{round}]}.
\]

直接测接受前缀和 bonus token，避免用“提出 gamma 个”替代 A。对于 hybrid，回滚同时恢复 KV、GDN／recurrent state、位置和已提交前沿；全历史 replay 可作为正确性原型，增量 checkpoint／事务状态可继续减少回滚成本。缺少原生 MTP 头时可比较 n-gram／检索草稿、小模型草稿或另行训练的 head。

### 5.4 KV 与 recurrent state 分账

普通 full-attention 层的 KV 载荷近似为

\[
M_{KV}=2\,L_{full}\,S\,H_{KV}\,d_{head}\,b\,C,
\]

其中 b 为每元素字节数、C 为序列数，另加 scale、page table、padding 和 workspace。Qwen3.5 hybrid 的其他层另计 recurrent／convolution state，不能把总层数全部代入 \(L_{full}\)。KV 压缩主要改变长序列 attention 工作集与容量；dense FFN 的权重读流量需另做优化。

在无限任意历史且未来查询可区分全部历史的假设下，固定有限状态无法对所有查询精确保存全部信息，这是可区分状态数量的限制。实际有界 Agent 任务仍可研究精确前缀共享、无损分层、受控有损选页、检索和重算；准确率／任务成功率由负控和任务集验证。

### 5.5 张量并行和拓扑用成本不等式判定

张量并行候选满足收益条件：节省的计算关键路径大于新增 collective／同步成本。粗略通信项可写为 \(n_{collective}\alpha+V/\beta\)，需测具体操作、payload 和共享链路；单 token 小矩阵、长 prefill、batch／投机块各不相同。历史某条链路的 RTT 只约束该条件，不能证明全部 TP 数学不可行。worker 缺少 listener 也属于可实现的拓扑能力，先用已有连接做有向数据路由原型，再比较 star 与 chain。
