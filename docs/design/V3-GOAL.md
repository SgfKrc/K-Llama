# V3 的目标与边界
> 面向可编排的异构调度 · 基于 v2.2 的实测与补丁薄化 · 产出可回退的 v3 路线

> 状态：**已定稿（2026-11-14 用户拍板）**
> 相关：`V3-IGPU-ROLE.md`（设计输入）、`V3-STAGE-SWITCH.md`（接口草案）、`BUILD.md` §4.2（异构两层）

---

## 1 一句话目标

**让设备分配成为显式策略，而不是阈值副作用。**

今天的设备分配是隐式的：`op_offload` 的 m≥64 阈值决定「这个算子给 GPU 还是 CPU」，`-ngl` 决定「哪些层在哪」。没有地方能声明「prefill 阶段整体给核显、decode 阶段整体给 CPU」，也没有地方能观测「这一帧实际按哪个策略走的」，更不能在策略出错时回退。

v3 要做的就是把这三件事补上：**可声明、可观测、可回退**。

## 2 为什么是这个目标（而不是「提速」）

设计草案（`V3-STAGE-SWITCH.md`）的结论是：**阶段化切换本身不提速**。理由：

- prefill 走核显、decode 走 CPU 这个行为，**今天已经被 `op_offload` 的 m≥64 阈值隐式实现**——阈值是算术强度判据（111 FLOP/byte → m≈31）的保守离散化，m≥64 的 prefill 给 GPU、m=1 的 decode 留 CPU。
- 「数据不动」的前提**在代码上不成立**：buft 是二分的，CPU 只认 host buft、Vulkan 只认自己的 device buft，sched 必然在某侧插拷贝。
- decode 的天花板是共享总线的 8.6%，prefill 的 2.51× 已经被吃掉。

所以 v3 的价值不在「更快」，在**把「碰巧这样跑」变成「声明式地这样跑」**。这也正是它区别于 v2.2 的地方——v2.2 是「跑通并验证语义」，v3 是「让调度本身成为一等公民」。

## 3 边界（明确不做）

| 不做 | 理由 |
|---|---|
| **不做新 API 协议** | 沿用 v9/v10。协议层已经稳定，v3 不重写。 |
| **不做模型转换 / 量化** | 交给 `llama-quantize` 和上游。 |
| **不做隐式启发式** | **所有设备分配必须可声明**。散落在代码里的阈值要么提到策略层，要么明确标为「默认策略」。这条是防基线膨胀的核心。 |
| **必须跨机** | Surface（Gen11）/ Y700（ARM）/ 本机（i9）都要能跑。 |

## 4 成功判据

**一个具体场景跑通**，而不是基准分数。

建议的场景：**35B-A3B MoE 在「核显 + CPU」上按显式策略分配跑通，且质量不退化。**

为什么是这个场景：

- 它覆盖了两条硬约束（核显算力优势、CPU 带宽优势）
- 它需要容量规划（12.67 GiB 装进 15.82 GiB 的堆，接近边界）
- 它有现成的对照数据（iGPU 16.64 t/s、CPU 17.33 冷 / 14.09 热）
- 它能被演示，不依赖抽象指标

**判据口径**：跨设备比 token 序列或容差，**不比字节**（`BUILD.md` §4.2 的两层命题）。

## 5 退路（这是 v3 必须遵守的设计约束）

**如果 v3 失败，回退到「基于上游最新 llama.cpp」的 K-Llama-v2.1。**

这条不是「放弃」，是**设计要求**：

- v3 的实现必须**可分离**——不能变成又一层拆不掉的补丁
- **补丁薄化**是 v2.2 已经开始的遗产：`[QLH-SPLIT]` 标记的改动要能按需摘除，而不是和上游代码交织
- 核显方面的修复（今天的 MMVQ `d43316a0d`）**独立于 v3**，可以单独贡献给上游

**推论**：v3 的每一步都要问「如果这步失败，能不能干净地退回去」。不能干净退回的方案，即使性能更好，也应该降级为实验分支。

## 6 与 v2.2 的关系

**v2.2 可能已经完成**：判据 #2–#6 已实测通过（组 15，18/0/0），组 14 的 per-seq 投机通过（20/0/0），组 1–13 覆盖本地链/远程链/KVMem/DFlash。核显这条线的结论也已固化（`IGPU-MOE-MMVQ.md`、`IGPU-SLOWDOWN.md`、`V3-IGPU-ROLE.md`）。

v2.2 的遗产是三样东西：

1. **分段链**（layer-range 推理）——v3 跨机的基础
2. **混合批**（同一 batch 内多序列）——v3 并发形态
3. **补丁薄化**（`[QLH-SPLIT]` 标记）——v3 可回退的前提
