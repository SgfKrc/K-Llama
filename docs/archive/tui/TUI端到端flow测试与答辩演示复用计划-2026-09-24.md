## 二、方案选型

### 候选 A（**推荐**）：Textual `App.run_test()` + `Pilot` 原生驱动（headless）

- 机制：`run_test(size=(W,H))` 起 headless driver；`pilot.click(selector, offset)` / `pilot.press(...)` / `pilot.pause(delay)` 注入鼠标与键盘；断言直接读 widget 树与控件文本。
- **稳定性 高**：headless 无终端/字体/DPI 变量；`pilot.click` 自带落点校验。
- **可移植性 高**：Windows/Linux/macOS/CI 同一套代码；只用既有 `textual` + pytest。
- **可演示性 中高**：可逐帧 `save_screenshot()` 产证据；但**不能**直接当"真终端播放器"（真终端需另起进程）。
- **维护成本 低**：仓库已有同构用例可抄（`tests/test_tui_textual.py:53-111`、`tests/test_tui_write_ops.py:187-219`）。
- **局限**：headless **不覆盖**真终端渲染与鼠标上报链路 ⇒ 不得把 headless 通过当作"真终端可用"的证据。
- **未实测**：本仓库 `tests/` 零 `pilot.click` 先例 ⇒ 落地第一步先写 1 个探针用例。

### 候选 B：pty/伪终端 + ANSI 鼠标序列（SGR 1006）

- 机制：真终端里 Textual 会开 `1000h/1003h/1015h/1006h`，理论上可向 master 端写 SGR 序列模拟点击。
- **稳定性 低**：需要真 TTY + 已知窗口像素/cell 尺寸 + 坐标映射；Windows 走 Win32/ConPTY，行为需实测；断言只能解析 ANSI 屏（正则剥绘图字符），很脆。
- **可移植性 低**（`pty` 是 POSIX；Windows 要 ConPTY）；**维护成本 高**。
- 结论：**不作主路径**；可作为**可选的真终端冒烟档**（默认关闭、不进 CI），用来回答"headless 通过 ≠ 真终端能点"。**未实测**。

### 候选 C：外部 GUI 自动化（pyautogui / pywinauto / SendInput）

- **不选**：① 仅 Windows，焦点/DPI/遮挡导致 flaky；② 无 headless 断言能力，只能截图比对；③ 仓库零依赖零用法（全仓 grep 无命中）；④ 把"演示"与"测试"绑死在演示机桌面上，无法进 CI。

### 推荐结论

**A 为主**（门禁 + CI 断言 + 演示驱动），**B 作为可选真终端冒烟档（默认不跑）**，**C 不做**。
理由：仓库已用 A 写了 12 个 TUI 测试文件与 `startup_matrix --profile tui` 门禁，与既有纪律零冲突；B/C 都无法同时承担「可重复、可门禁、跨平台」。

## 三、测试 flow 设计

### 3.1 控件定位：语义优先，坐标仅作相对偏移

1. **首选 widget 语义选择器 / id**，沿用既有 id 契约：`#nav`（`src/tui_textual.py:1361-1364`）、`#content`（`:1365`）、`#topbar`（`:1358`）、各屏 pane/table（`:1366-1420`）、聊天 `#chat-input`/`#chat-status`/`#chat-log`（`:457-460`）。
2. **页面切换两把钥匙**：
   - 键盘（稳定、已有先例）：`pilot.press("]")` / `"["`（`src/tui_textual.py:1301-1302`；用例 `tests/test_tui_textual.py:102-109`）；
   - **鼠标（本计划的要求）**：`pilot.click("#nav ListItem#nav-cluster")`，或对 `#nav` 用 `offset=` 相对定位；
     落点校验：`ok = await pilot.click(...)`，`ok is False` 表示落点不在目标 widget 上 ⇒ 直接断言失败。
3. **消息链路**（鼠标点击→切屏的因果）：`ListItem` 被点 → `_on_list_item__child_clicked` → `Selected`（`textual/widgets/_list_view.py:388-392`）→ TUI 的 `on_list_view_selected` → `switch_page(...)`（`src/tui_textual.py:1425-1433`）。
4. ⚠️ 落地第一步先交 **1 个探针用例**（点 `#nav` 切屏 + `assert ok is True`），确认稳定后再铺剧本（**未实测**）。

### 3.3 模型依赖隔离与退出码三态

**跳过写法（照抄既有约定）**：

```python
# ① 缺 UI 依赖 ⇒ 整模块跳过（不是失败）
pytest.importorskip("textual")                    # tests/test_tui_textual.py:46

# ② 缺模型/工件 ⇒ 模块级 skipif + 写明缺什么（真机工件门）
pytestmark = [
    pytest.mark.real_model,
    pytest.mark.skipif(not MODEL_PATH.is_dir(),
        reason="需要真实模型工件（真机工件门）"),
]                                                 # tests/test_qwen3_network_sidecar_chain.py:55-61

# ③ 缺工件 ⇒ 函数/夹具级 skip，注明相对路径与补齐方式
pytest.skip(f"需要 keep-head shim（{SHIM.relative_to(ROOT)}）；…")   # tests/test_llama_keep_head.py:46-56

# ④ 资源门（RAM/显存不足）同样跳过
pytest.skip("可用 RAM < 3GB（资源门）")            # tests/test_qwen3_network_sidecar_chain.py:372
```

**一律 `skip`，不用 `xfail`、不静默 `pass`**（`tests/test_qwen3_network_sidecar_chain.py:10-13`：「真机工件门，不虚构证据」）。

**两档划分**：

| 档 | 内容 | 依赖 | 门禁地位 |
|---|---|---|---|
| **F1 假后端（零模型）** | `RecordingApi`（`tests/test_tui_write_ops.py:33-77, 158-180, 215-219`）或 `qlh chat --fixture` 离线 SSE 回放（`qlh.py:206-209`） | 仅 `textual` + pytest | **必跑**，纳入 `unit` 通道 + `startup_matrix --profile tui` |
| **F2 真后端 + 真模型** | 真 `api_server` + 真权重 | 模型工件 + 隔离 venv + 显式开关 | **默认不跑**：需 `QLH_RUN_REAL_MODEL_SMOKE=1`（`tests/test_real_model_smoke.py:27, 99`），走 `smoke` 通道且**串行** |

**脚本退出码三态**（与 pytest 的 skip 语义对齐）：`0` = 全通过；`1` = 有断言失败；`2` = **环境缺失（等价 skip）**——缺 `textual`／缺模型工件／缺隔离 venv，**不判为失败**。门禁侧仍以 `skipped` 呈现，**不得**把 skip 改写成 `passed`。

### 3.4 超时与重试

- **复用既有约定，不另发明**：`_wait_for(pilot, predicate, timeout=6.0)`（`tests/test_tui_write_ops.py:187-200`）——轮询期间 `NoMatches` 视为"未就绪"；就绪判定**不得用屏内控件**，因为 `ContentSwitcher` **只挂载当前屏**（`:203-212`）。
- 节奏用 `pilot.pause(delay)`（`textual/pilot.py:535`）：启动屏逐字 0.45s、数据表填充 2.0s、确认后 0.1–0.3s（既有用例值）；能等条件的用 `_wait_for`，不要固定 sleep。
- 单用例预算受 `pytest.ini:14` 的 `--timeout=300` 约束；单步 `_wait_for` 上限取既有 6.0s；真模型档另立 `real_model`/`slow` 并串行，避免与默认 `-n 4` 争内存（`pytest.ini:15-20` 记录过 16GB 机器被击穿的事件）。
- **不引入 rerun/flaky 把失败变绿**：仓库明文「重复执行用于观察 flaky，不是失败重试」「不使用 rerun 插件把失败隐藏成绿色」（`docs/测试通道运行说明.md:69-78`）。要暴露顺序相关抖动，用 `--repeat` + `--qlh-order-seed`（`tests/conftest.py:27-34`）。

## 四、答辩演示复用

### 4.1 同一脚本两种模式：`--mode assert` / `--mode demo`

同一可执行文件、同一份 step 剧本、同一执行器，只切换"节奏 + 输出 + 失败策略"：

| 维度 | `--mode assert`（门禁） | `--mode demo`（答辩） |
|---|---|---|
| 节奏 | 取最小等待（同 §3.4） | 每步前后 `await pilot.pause(pace)`，`--pace` 默认 1.2–1.5s，现场可调 |
| 字幕 | 无 | 每步 `app.notify(caption)`（`textual/app.py:4621`）/ `bell()`（`:3907`）；或写 `#topbar`、`#chat-status`（**不得改其语义**） |
| 留证 | 只出 JSON 结果 | 每步 `save_screenshot("build/tui-e2e/frames/{step_id}.svg")`（`app.py:1889`） |
| 失败策略 | 立即失败，停在首个不满足的 `expect` | **降级而不中断**：标该步 `DEGRADED`、打印原因、继续播（现场不黑屏） |
| 退出码 | `0` 全通过 / `1` 有失败 / `2` 环境缺失 | `0` 全 PASS / **`3` 有 DEGRADED** / `1` 有 FAIL / `2` 环境缺失 |

## 六、风险与不做的事

### 6.1 已知风险（含规避）

1. **headless ≠ 真终端**：`run_test()` 走 HeadlessDriver，不覆盖真终端鼠标上报与 conhost/字体差异。规避：文档明确"headless 通过 ≠ 真终端可用"；可选 B 档作真终端冒烟（默认关、不进 CI）。
2. **`pilot.click` 在本仓库零先例**（**未实测**）。规避：落地第一步先交 1 个探针用例，确认稳定后再铺全量剧本。
3. **页面挂载竞态**：`ContentSwitcher` 只挂载当前屏，直接 `query_one` 未显示屏控件会抛 `NoMatches`。规避：只用 `_wait_for`，就绪判定不依赖已挂载控件。
4. **textual 版本漂移**：`requirements-tui.txt:8` 是 `textual>=8,<9`，SVG/选择器语义可能在小版本内变化。规避：断言只用公共 API 与 id 契约；SVG 不做相等门禁。
5. **演示现场时长不可控**：真后端冷启动有 30s 上限（`src/tui_backend.py:30, 113-128`）。规避：答辩默认用 F1 假后端档（零等待），真后端档单独预热；剧本支持 `--pace` 与跳过某步。
6. **被误读为"分布式已验收"（最大风险）**：规避：字幕/报告强制打印 `topology`、`physical_dual_host=false`、`real_model_loaded=`，并引用 `docs/验收清单与资源限制登记.md:143` 的口径。

### 6.2 明确不做的事

1. **不放宽任何既有验收门禁**；数值一致性**只认 per-token argmax**，不用 cosine/top-k/时长替代。
2. **不为演示改动生产代码路径**：不改 `src/tui_textual.py` 的行为、不加"演示专用分支"、不在生产入口埋 demo 开关；演示只通过公共 API 驱动（`Pilot` + `App.notify` / `save_screenshot`）。
3. **不引入外部 GUI/浏览器自动化依赖**（pyautogui/pywinauto/Selenium/Playwright 用于 TUI）；仓库当前零命中。
4. **不做 pty + SGR 的主路径实现**；B 档若做，必须默认关闭且不进 CI。
5. **不复活自绘 ANSI TUI**，不重建已消失的 `src/tui_chat.py` / `tui_admin.py`，不修 `scripts/tui_chat_walkthrough.py`（不可运行的遗留物；如要清理，按 [文档状态与清理清单](文档状态与清理清单.md) 的裁撤约定独开票）。
6. **不把演示模式接进 CI/门禁**：演示模式退出码非 0 语义与 CI 的"绿色即通过"冲突。
7. **不用 rerun/flaky 插件掩盖失败**；不写"失败自动重试 N 次"的自旋。
8. **不产出任何夸大的演示结论**：不宣称真模型已加载、不宣称双机物理分布式、不把 loopback 多段/受控预算写成物理 OOM 或跨机结论。
9. **不真改 `.gitignore`**：只给建议行（该文件属并行组在制品）。
10. **不碰并行组在制品**：`src/torch_*.py`、`scripts/torch_*.py`、`tests/test_torch_*.py`、`src/journal_replication*.py`、`tests/test_journal_replication.py`、`docs/主节点动态选举*`、`.gitignore`。
