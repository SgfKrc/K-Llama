## 3. 准备项 1：`ChatScreen` 的具体设计（不阻塞，可立即开始）

### 3.1 依赖对比

| 能力 | 现（`tui_chat.py`）| 目标（`ChatScreen`）|
| --- | --- | --- |
| UI 框架 | **Textual** | **stdlib**（复用 `tui_admin` 的 `AnsiTerm` / `Screen`）|
| HTTP 流式 | **httpx** | **`urllib.request`**（流式 `read`）|
| SSE 解析 | `tui_sse.SSEDecoder` | **同一模块（不变）** |

### 3.2 端点契约（只有 3 类）

```
POST /api/chat/stream                        （streaming_mode=interactive）
POST /api/chat/generations/{id}/cancel
GET/POST /api/sessions*
```

事件序列：`start → token* → (done | error | cancelled)`

### 3.3 边界约束（沿用 `tui_chat.py` 的设计边界，不放松）

- 模型输出经 Markdown 渲染，**不执行内容**；ANSI 注入由渲染层过滤；
- **只以 `done` 事件 metrics 展示执行模式，不推断分布式**；
- 不与管理 TUI 的手写 ANSI 主循环冲突（统一后二者同进程，但 `Screen` 之间互斥）。

### 3.4 为什么现在做它是安全的

- **新增文件**（如 `src/tui_chat_screen.py`），**不改任何现有入口**；
- 只**只读**引用 `tui_sse.SSEDecoder` 与 `tui_admin` 的工具函数；
- **不触碰**并行线正在改的 8 个文件；
- 可与 P1 解耦，**独立测试**（可用 `--fixture` 回放，见 `tui_chat.py` 既有的 fixture 模式）。
