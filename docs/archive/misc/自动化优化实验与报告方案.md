## 0. 结论先行

1. **实验与功能验收分开**：功能、回归、协议测试走 `scripts/run_test_channels.py` 与 pytest；优化实验走本方案的自动实验脚本，数据不混入测试基数。
2. **一切输入先冻结，再跑数**：提示词集、seed、采样参数、模型工件（SHA-256）、引擎/运行时版本、设备画像、门阈值在实验开始前写入实验计划（manifest），运行中不得修改。
3. **一次只变一个自变量**：对照组与实验组除被测变量外完全一致；任何并行执行不得引入资源争用或环境漂移污染数据。
4. **单次实验不构成结论**：每组至少固定次数重复（默认 ≥5 次），报告中位数与样本数，必要时给标准差/置信区间；失败与重试全部留痕。
5. **报告可追溯**：每条实验记录含 `experiment_id`、commit、原始数据文件路径与门判定，任何结论都能从报告反查到原始日志。

## 1. 实验原则（必须遵守）

| # | 原则 | 强制要求 |
|---|---|---|
| 1 | **控制变量** | 一次实验只改变一个自变量；基线组与实验组除该变量外，模型工件、提示词集、采样参数、引擎版本、设备、网络路径全部相同 |
| 2 | **固定输入** | 提示词集版本化并锁定 SHA-256；`seed`、`temperature`、`top_p`、`max_new_tokens`、是否流式全部写入记录；贪心与采样是两种实验，不得混记 |
| 3 | **固定工件与环境** | 模型 `artifact_sha256`、`quant_family`、`effective_bpw`、tokenizer、上下文长度、引擎 commit、运行时版本、设备画像（CPU/GPU/内存/OS）逐项记录；结论不得推广到未测的工件或环境 |
| 4 | **统计纪律** | 每组默认 ≥5 次重复（脚本参数可调，但报告必须注明样本数）；报中位数而非单次最佳；剔除异常值必须给出依据并保留原始值；不同结论至少报告"差值 + 百分比 + 样本数" |
| 5 | **热机与顺序** | 计时前先 warmup（默认 1 次，与 `benchmark_all.py` 一致）；并行组按固定轮换/随机化顺序执行，避免缓存、频率与系统漂移造成系统性偏差 |
| 6 | **资源互斥** | 并行实验必须在 manifest 声明资源（GPU 显存、端口、模型槽位、后端实例）；冲突时串行排队，违规并行产生的数据标记 `invalid` 不计入报告 |
| 7 | **失败留痕** | 单元失败保留原始日志与退出码；自动重试必须记录次数与原因，重试数据与首次数据分开标记，不得静默覆盖 |
| 8 | **预先注册** | 重要实验先冻结方案（假设、组别、指标、门阈值）再跑数据；禁止先看数据后补假设（p-hacking） |
| 9 | **归因纪律** | 单机与分布式、不同量化/引擎的统计独立分组（沿用《测试与评判标准》对照组口径）；"分布式：是/否"必须展开为实际执行模式与参与节点 |
| 10 | **报告可溯** | 每条记录含 `experiment_id`、commit、执行命令、原始数据路径、报告路径、门判定（`passed / failed / invalid`） |

## 2. 适用范围

本方案覆盖的优化实验类型（非穷举，新类型按同一口径登记）：

- **LLM 推理**：量化档位（FP16 / NF4 / Q4_K_M / Q3_K_M / Q2_K / IQ2_*，口径见 [2bit与4bit量化调研与实施计划](../runtime/2bit与4bit量化调研与实施计划.md)）、`torch.compile`、KV 缓存策略、批处理/并发、层间流水线配置、投机解码 draft/verify、上下文长度；
- [历史记录] **图像（SD 1.5）**：采样器/步数/preset、img2img / IP-Adapter / inpaint 参数矩阵、显存占用（复用 `scripts/quality_gate_sd15*.py` 的固定 seed 与 `--review-report` 登记模式）；
- **系统**：冷启动时间、并发吞吐、故障恢复时间（与仿真矩阵衔接，见 [分布式推理仿真测试计划](../distributed/分布式推理仿真测试计划.md)）。

**不适用**：功能/回归/协议测试（走测试通道）、真机分布式验收（L1，仍按各专项计划执行）。实验脚本的产出不得替代 L1/L2 的验收证据。

## 3. 固定提示词集（Prompt Set）

### 3.1 版本化

- 提示词集作为**版本化资产**管理：`prompt_set_id`（如 `ps-v1-zh-en-code`）+ 内容 SHA-256；存放于 `fixtures/prompt_sets/<id>/`，每条 prompt 一个文件或一个带元数据的 JSONL。
- 任何修改（增删条目、改措辞、改长度分布）必须升版本号，禁止原地覆盖。
- 报告中必须声明所用的 `prompt_set_id` 与 SHA-256；不同版本的数据不得横向合并。
- **已冻结（EX-N0，2026-08-09）**：`ps-v1-zh-en-code`（30 条：zh_qa/en_qa/code/math_reasoning/long_context/format 各 5 条），SHA-256 `8cc555f57fa23d45c16820f77cc90b507da04578a1e90eebf46e19d4eb2568a3`，见 `fixtures/prompt_sets/README.md`。

### 3.2 分类建议（v1 冻结时确定最终条目与数量）

| 类别 | 内容 | 用途 |
|---|---|---|
| 中文问答 | 通用知识、说明类问题 | 中文能力基线 |
| 英文问答 | 通用知识、摘要类问题 | 英文能力基线 |
| 代码 | 函数实现、算法、bug 修复 | 代码能力 |
| 数学/推理 | 计算、逻辑推理 | 推理能力 |
| 长上下文 | 长文档问答/总结（覆盖 2048/4096/8192） | 长文本稳定性与 KV 压力 |
| 格式遵循 | JSON、列表、固定模板输出 | 格式遵循率 |

- 每条 prompt 记录 `prompt_token` 数（由固定 tokenizer 计算并入库），保证各实验间输入长度一致。
- 每类至少 5 条（正式评估建议 ≥10 条）；SD 实验沿用已冻结的固定源图 SHA-256 与固定十 seed 口径。

### 3.3 采样约定

- 性能类实验默认贪心解码（`do_sample=False`）；需要采样时固定 seed 与参数并在记录中写明。
- 质量类实验固定 seed 集（参照 SD 质量门的"十种子"做法）与固定生成长度上限。

## 4. 全自动实验脚本架构

### 4.1 组件

```text
实验计划 manifest（yaml/json：提示词集、参数矩阵、资源、门阈值）
        │
        ▼
调度器 run_experiments.py（串行/并行、资源锁、超时、断点续跑、重试策略）
        │
        ▼
执行器 runner（每单元：加载工件 → 校验 → warmup → 跑提示词集 → 采集指标）
        │
        ▼
采集器 collector（统一 schema 落盘：原始数据 + 汇总统计）
        │
        ▼
报告生成器 report builder（聚合所有单元 → records + 对照表 + 结论模板）
```

### 4.2 关键设计

- **入口**：`scripts/run_experiments.py`（规划名，EX-N1 实现）；`--plan <manifest> --parallel N --resume --out build/experiments/<run_id>/`。
- **实验单元（experiment unit）**：一组完整参数的一次运行，产出一条 `experiment_record`；同一单元可含多次重复（`runs`）。
- **串行/并行**：默认串行（顺序与 manifest 一致）；`--parallel N` 仅在所有单元的 `resources` 声明互不冲突时生效，GPU/端口/模型槽位冲突自动降级为排队。SD 与 LLM 显存互斥场景必须声明独占。
- **断点续跑**：已完成单元按输出文件哈希校验后跳过；中途取消不丢已完成的单元数据。
- **超时与清理**：每个单元有超时上限；超时按失败记录并释放资源；结束后强制清理模型与显存（参照 `benchmark_all.py` 的 `del model + empty_cache`）。
- **门判定**：单元级与 run 级门（阈值写在 manifest），`passed / failed / invalid` 三态；`invalid` 不参与汇总。

### 4.3 复用清单

| 现有资产 | 复用方式 |
|---|---|
| `scripts/benchmark_all.py` | runner 的 LLM 性能内核（warmup/run 次数、显存采集、汇总表逻辑） |
| `scripts/quality_gate_sd15*.py` | SD 质量门、固定 seed、`--review-report` 双人目视登记模式 |
| `scripts/run_test_channels.py` | 仅作为前置健康检查（实验前先确认测试通道绿） |
| `tests/simulation/` | 作为分布式/故障类实验的执行后端之一 |
| 《测试与评判标准》 | 指标口径（TTFT、逐 token 延迟、tok/s、内存、对照组） |

## 6. 报告汇总

- 每轮实验产出 `build/experiments/<run_id>/`：`records.jsonl`、`report.md`、`summary.json`。
- `report.md` 含：实验清单与状态、**对照表（实验组 vs 基线：差值、百分比、样本数、门判定）**、失败/重试明细、环境与工件摘要、结论模板（假设 → 结果 → 是否支持 → 遗留风险）。
- `report.md` 与 `summary.json` 额外汇总 EX-N3-S0/v2 的结构化质量证据状态；在 EX-N3 执行器和质量门阈值另行冻结前，该汇总**不改变**性能 gate 的 `passed / failed / invalid` 判定。
- 需要人工复核的结论（如输出质量）复用 SD 质量门的 `--review-report` 双人目视登记模式，签字后报告才可标记 `passed`。
- 报告作为总计划 L4 各项（量化、层流水线、投机解码等）Go/No-Go 与止损判据的数据来源；写进报告的数字必须能反查 `records.jsonl` 与原始日志。

### 6.1 质量证据 v1/v2（EX-N3-S0 与 EX-N3-GEMMA-S1，已完成开发 2026-08-13）

`scripts/experiment_core/quality.py` 定义结果文件可选字段 `quality_evidence` 的唯一最小入口，`schemas/experiment-record.schema.json` 以 `qlh.experiment_quality.v1` 固化其落盘格式，`experiment_core` 的 collector 与报告是首个消费者。

- **LLM 证据**：必须绑定本次 experiment plan 的 `prompt_set_id + SHA-256`，只记录正确性与格式检查的 `evaluated_count / passed_count`，由框架派生比率；不保存 prompt、生成正文、判题解释或评审文本。
- **SD 证据**：只保留资产/工件标识、来源质量门 schema、自动门通过状态及输出计数、人工审核状态和所需审核人数。对既有 `quality_gate_sd15*.py` 报告的适配器只读取这些固定字段，绝不复制 prompt、图像路径、图像/内容摘要或审核人身份。
- **Gemma v2 证据**：仅接受锁定 `model + judge_contract_id + judge_contract_sha256` 及主题命中、关键要素覆盖两组 `evaluated_count / passed_count`；框架派生比率。判题契约、模型或计数任一不匹配即拒绝，prompt、图像、图像路径/URL、模型输出、判题解释与推理文本均不落盘。
- **缺失与无效**：未采集显式写为 `not_collected + reason`；未知字段、错误计数、非当前 prompt set、非预期判题契约或不合规 SD 结构写为脱敏 `invalid`，解析错误文本不落盘。旧记录的 `{correct_rate, format_rate}` 仍可由 schema 读取。
- **边界**：`collected` 表示证据结构可用，不是模型质量结论；SD 人工审核是状态而不是自动质量分；Gemma 静态 fixture 只验证记录通路，不代表模型调用或图像语义验证。缺失或无效质量证据在本阶段不反向改写既有性能 gate。后续 EX-N3 如需以质量决定总 gate，必须先在 manifest 中预注册指标、阈值、失败语义和人工复核规则。

### 6.2 EX-N3 执行准则冻结（2026-08-12，决策）

EX-N3 执行阶段依据以下四项准则运行；所有阈值先按基线值执行，**须经 3 轮真实取数标定后修订**（见 §6.2.5）。质量门默认不改变性能 gate，仅当 manifest 显式声明 `quality.required=true` 才参与总 gate（§6.2.4）。

**已实施的 LLM 执行器（2026-08-12）**：`scripts/experiment_llm_quality_unit.py` 以本地、摘要锁定的 Qwen 1.8B Q4_K_M GGUF 和固定贪心采样执行版本化客观 rubric；`fixtures/quality_rubrics/llm-objective-ps-v1-v1.json`、模型、prompt set 的 SHA 均由 plan 校验。模型输出和 rubric 答案/规则只存在于执行内存及版本化 fixture，`records.jsonl`、报告和摘要只保存评估/通过/无效计数。`experiment_core` 新增独立 `quality_gate`：默认隔离，`quality.required=true` 时才与性能 gate 合并。`scripts/experiment_quality_calibrate.py` 只生成中位数和波动建议，不能自动改写阈值、plan 或本文；同一输出目录则由 `.run.lock` 串行保护，遗留锁须显式 `--recover-lock` 才可恢复。

#### 6.2.1 LLM 判题 rubric

- **题集**：`ps-v1-zh-en-code`（30 条，SHA-256 锁定）；从中划分**客观可判子集**并随 plan 登记：精确答案题（数学/事实，答案精确匹配）、格式遵循题（JSON schema/代码块/指定语言），中/英/代码三档各保留。
- **判题规则**：归一化（大小写、空白、全半角）后比较；精确答案题要求完全一致，格式题按 schema/语言约束校验；拒绝回答、乱码、超长截断计 `failed`；无法判定的题计 `invalid`（不计入分母并提示）。
- **记录**：只上报 `evaluated_count / passed_count`（S0 契约），rubric 本身不入记录文件。

#### 6.2.2 模型组合（可用资源冻结）

| 角色 | 模型/资产 | 工件锁定 |
|---|---|---|
| LLM 基线 | Qwen-1.8B GGUF（Safetensors 视资源门） | 既有注册表 SHA |
| LLM 对照（资源门通过后） | DeepSeek-R1-Distill-Qwen-7B 等 | 按 MF-MEM-N2R 锁定工件 |
| LLM 非 R1 候选（未下载） | Qwen3-4B 官方 GGUF / Safetensors | [Qwen3/Qwen3-VL/Qwen3.5 模型支持计划](../models/Qwen3.5与Qwen3-VL小模型支持计划.md) 的 `QW3-D1` 完成后逐格式独立锁定 |
| SD 质量基线 | `sd15_original_v1` | 离线资产包 SHA（阶段 2 完成） |
| SD 扩展（按实验主题） | 90s / IP-Adapter / inpaint / instruction | 各自冻结 SHA |
| Gemma 判题器 | 官方 `gemma4:12b`（Ollama 路径） | G4.3.2A 锁定（GGUF + mmproj SHA） |

组合随 plan 预注册，禁止运行中换模型。

#### 6.2.4 质量对总 gate 的影响规则

- **默认隔离**：质量门独立成列（`quality_gate: passed / failed / not_collected`），**不改写性能 gate**（S0 语义延续）。
- **可选收口**：仅当 manifest 声明 `"quality": {"required": true}` 时，总 gate = 性能 gate ∧ 质量 gate；`not_collected` 不视为失败，标记并提示。
- **失败语义**：质量 `failed` → 记录 + 人工复核升级通道（§6.2.3 末行）；不自动重跑；证据缺失不反向改写性能 gate。
- **LLM 侧判据（2026-08-13 方案 1；2026-08-16 P5/v2 升级）**：`quality.required=true` 时 LLM 侧考核**客观正确率**（v2 口径 `loose_contains` + 512 token 预算，Qwen3-4B 基线 ≥ 0.15，三轮标定 2026-08-16）+ **人工复核兜底**；格式率判据在 v2 预算下实证失效（推理输出 0/11），required 门置 0 不参与（192 口径仍可用于标定/对比）。R1 蒸馏系与 Qwen 1.8B（v2 下 0/4）不可用。
- **Qwen3 候选恢复条件（2026-08-13）**：`QW3-S0` 已确认 Qwen3-4B 有硬 `enable_thinking=false` 开关，但工件尚未下载、主运行时也未准入；在官方双格式工件分别锁定、非 thinking smoke、三轮客观子集和人工复核全部完成前，以上结论不变，不能把候选名称或下载完成当作恢复正确率门的理由。

#### 6.2.5 标定流程

1. 执行器就绪后以基线模型跑 **3 轮** `ps-v1` 客观子集与 SD 十种子基线，记录正确率/格式率/匹配率分布；
2. 按分布修订 §6.2.3 阈值（原则：基线通过线取 3 轮中位数 − 波动余量；对比规则取基线 × 0.9 或按效果量调整）；
3. 修订后更新本表并标注版本；阈值变更必须随 plan 变更记录，禁止静默改。

**本次标定与修订（2026-08-12）**：`plan-quality-qwen-1.8b-calibration-v1` 对摘要 `703678…f18cc` 的本地 Qwen 1.8B Q4_K_M GGUF、`ps-v1` 与 `llm-objective-ps-v1-v1` 运行三条预注册 CPU 单元。三轮均为正确率 `0/4`、格式率 `4/11`，故中位数与波动余量分别为 `0.00/0.00`、`4/11/0`。终端时限导致第 3 单元有一次重复完成记录；标定汇总器默认拒绝重复，本次以显式 `--select-earliest-unique` 选择最早记录，并在 `calibration.json` 留下审计。新的 `v2` 地板仅用于该弱基线工件的可用性/回归比较；不证明模型具有可接受的问答质量，也不为 DeepSeek、Safetensors、SD 或 Gemma 横向套用。

**本次重标与决策（2026-08-13）**：`plan-quality-deepseek-r1-qwen-7b-calibration-v1` 对 `78272d8d…35c1c` 的本地 DeepSeek-R1-Distill-Qwen-7B Q4_K_M GGUF 重跑三轮，正确率仍 `0/4`、格式率 `2/11`。手动实证根因：R1 蒸馏 thinking 不可关闭（system"直接回答"指令被忽略），输出预算全部消耗于 `<think>` 思考链，最终答案从未生成。**决策（方案 1）**：LLM 侧质量 gate 改为「格式率（非 R1 系，≥ 0.30）+ 人工复核兜底」，客观正确率不参与；`quality.required=true` 的 LLM 侧判据见 §6.2.4。后续若引入非 R1 更强本地模型或用户自持外部端点，可恢复正确率判题并重新标定。

### 6.3 生产质量证据门（EX-N3-PROD，已完成开发 2026-08-23）

`scripts/experiment_quality_production_gate.py` 与 `experiment_core.production_quality` 将一组**已经完成**的 `records.jsonl` 升级为只读的生产质量结论；它不启动执行器、不加载模型、不访问网络，也不改变运行时路由。标准复核命令为：

```powershell
.venv-test\Scripts\python.exe scripts\experiment_quality_production_gate.py `
  --plan fixtures/experiment-plans/plan-quality-total-gate-v1.json `
  --records build/experiments/<run_id>/records.jsonl --check
```

- 先复验 plan、提示词集和 rubric 的锁定 SHA，再要求每个计划单元恰有一条记录；计划/提示词集/模型身份/参数/runs/三轮 calibration、性能 gate 和记录内 quality gate 任一不符即拒绝。
- 审计器只从落盘的受限计数形状重建 LLM、SD、Gemma 质量证据，并重新计算阈值与人工复核门。缺记录或质量门未通过为 `failed`；JSON、身份、计数派生率、未知字段和非规范证据为 `invalid`。
- 结论收据 `qlh.experiment_quality.production_gate.v1` 只保留 plan/records SHA-256、实验 ID、检查项、计数与状态码；不写入 prompt、模型输出、原始日志/路径、图像或审核人身份。`--output <receipt.json>` 才原子写出该收据，`--check` 严格只读。
- 对历史 `plan-quality-total-gate-v1-20260816T195740/records.jsonl` 的复核为三侧 `3/3 passed`；该结果确认既有证据可用于生产门，但不把历史记录改写成新的模型、CUDA、双机、长时或生产路由验收。

## 7.1 多模态闭环：SD 1.5 生图 + gemma-4 图像理解复用（历史记录，主项目已裁撤）

目标：把**图像生成**与**图像理解**接进同一实验流水线，形成可自动判定的质量闭环，不依赖人工看图。

```text
固定提示词集（ps-v1 子集）
      │
      ▼
SD 1.5 离线资产包（build/sd15-assets，逐资产可离线重建）
      │  固定 preset / seed / steps / scheduler（Euler/DDIM 已支持）
      ▼
生成 PNG（每单元一图，报告保留哈希与参数）
      │
      ▼
gemma-4-12B 图生文（路线 A：external_api → 本机 Ollama；复用图像理解能力）
      │
      ▼
描述文本 → 与提示词语义匹配评分（自动门：主题命中率 / 关键要素覆盖率）
```

接入要点：
- **SD 侧**：`sd15_prompt_batch` / `sd15_sampler_matrix`（MODEL-TOOLS P1）已支持固定矩阵与自动图像门，Euler/DDIM 已入引擎；资产来源统一走离线资产包（阶段 2 验收后），保证工件可重建；
- **gemma-4 侧**：图像理解经 `external_api` 引擎对接本机 Ollama OpenAI 兼容端点（Gemma 方案路线 A，零新引擎）；图像以 base64 消息透传；
- **复用边界**：SD 生成图只用于实验质量判定，不把 gemma-4 描述冒充 SD 的能力宣传；gemma-4 描述仅作自动判据，人工目视门（双人签字）仍按 SD 专项要求保留；
- **门判定**：主题命中率与关键要素覆盖率的阈值在计划 manifest 中冻结；Gemma 记录必须同时绑定模型和判题契约 SHA，低于阈值标记 `partial_pass` 并留受限证据；
- **显存互斥**：SD 冒烟与 gemma-4 推理同机共 8 GB 显存，实验调度按资源声明串行（复用 `(key,value)` 资源互斥）。

前置条件：SD 离线资产包阶段 2 验收完成；gemma-4 路线 A 接入可用；两者都满足后再建真实 `experiment_sd15_unit.py` 与 Gemma 理解 runner。已完成的 EX-N3-GEMMA-S1 仅提供 SHA 锁定的计数 schema/fixture 通路，不可替代此前置条件，也不绕过模型、显存/RAM 或网络门。

## 8. 风险与止损

| 风险 | 处理 |
|---|---|
| 并行资源争用污染数据 | 资源声明 + 互斥；违规运行标记 `invalid` 不计数 |
| 提示词集/参数漂移 | 版本化 + SHA-256 校验；不匹配直接拒绝运行 |
| 偶然失败被静默重试掩盖 | 保留原始日志，重试次数与原因入记录 |
| 结论跨工件/环境推广 | 报告必须绑定 artifact/提示词集/环境；未测不宣称 |
| 数据与测试基数混淆 | 实验数据独立目录与 schema，不并入 pytest 统计 |
| 手跑数据混入报告 | 报告只接受 `run_experiments.py` 产出的记录（EX-N1 后） |

触发以下任一条件时，本路线转 `Frozen`：

- 无法维持提示词集与工件版本化（资产经常漂移且无法回溯）；
- 并行调度无法保证资源隔离，数据反复被标记 `invalid`；
- 报告产出无人使用，或与 L4 各项的 Go/No-Go 决策脱节。
