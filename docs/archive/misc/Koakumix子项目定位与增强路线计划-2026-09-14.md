## 1. 子项目地位与命名

- **正式名称：Koakumix**（代码入口 `harness_workbench/`；图标与对外品牌资产待用户提供后登记）。
- 定位：**本地小模型增强对话与工作台**子项目——不是通用 agent harness，而是"同一模型在 Koakumix 里跑，应答质量与可用性明显强于主项目普通对话"的**增强层**。
- 与主项目关系：同仓共管（当前）、代码层零耦合（见 §3.2）、共享度量口径（prompt sets / rubrics / RAG 基准）。

### 1.1 命名与设计理念（用户释义，2026-09-14）

- **Koakumix = Koakuma（小恶魔）× Reasonix 式 harness**——两者的共同哲学：**都是为前缀缓存（prompt cache）服务的 harness**。Koakuma 意象 = 小巧而不庞大：**"小模型、小玩具 harness"**——不追求大而全的通用平台，而是把"**稳定前缀 → 缓存命中 → 低成本长对话**"这一条线做透。
- **理念落到四个支柱**（§2 与之一一对应）：压缩 = 控制前缀增长（让缓存窗口可持续）；记忆 = 跨会话复用稳定前缀（facts/摘要沉淀）；RAG = 把易变知识**外部化**出系统提示（保前缀字节稳定）；小模型组合 = 固定角色前缀（draft/verify 各自的策略文本稳定可缓存）。
- 判定纪律同为"缓存优先"：任何新能力（含生图工具）都要回答"**它破坏前缀稳定性吗**"——破坏则必须外部化为工具调用/引用，不得写回系统提示。


## 2. 价值主张（"为什么存在"）

同一模型、同一硬件，**Koakumix 的价值 = 普通对话拿不到的四种增强**：

| 支柱 | 增强内容 | 直接可感知的差异 |
| --- | --- | --- |
| **A. 长上下文管理** | 压缩引擎（`RuleBasedSummarizer` 默认 + `LLMSummarizer` 显式注入、fail-closed 回退）+ 字符/token 双预算引用边界 | 超预算多轮对话**不爆窗、不丢关键约束**；普通对话截断即失忆 |
| **B. 跨会话长期记忆** | S8：SQLite facts/preferences、FTS5 检索、压缩时事实双写去重、scope 硬隔离 | **重开对话仍记得**先前结论；普通对话无跨会话状态 |
| **C. 检索增强** | 完整 RAG（改写/多路召回/RRF/rerank/多粒度+图谱索引）+ 引用边界 | 答复带**可核对出处**；普通对话只能凭模型记忆 |
| **D. 小模型组合** | draft-verify 角色分工（`EX-SPEC-ROLE-01`）、模型化 rerank、LLM 摘要——用 2B/9B 组合补单模型短板 | 小模型组合**打出更大模型的效果**；普通对话只有一个模型 |
| **横切：工具与安全** | MCP registry + 网络工具 + 红队门（prompt injection/越权 fail-closed） | 能干活且**越权被拦**；普通对话无工具、无安全门 |

**判定纪律**："更强"必须以**对照实验**证明（§4.1），组件存在 ≠ 效果成立。

## 3. 现状盘点（2026-09-14 查证）

### 3.1 已具备

- **编排层**：`api_layer/app.py` 已把 chat + RAG（`rag_retriever`）+ 记忆（`memory_store`）+ MCP + 上下文引擎接成一体（OpenAI 兼容接口、`/v1/models*` 模型管理、`/v1/mcp/manifest`）。
- **能力模块**（80 个 py 模块 / 35 个测试文件）：adaptation、adapters、context_engine、rag、memory、mcp_server、image_workbench、tui.py + ui_react、eval、session、tools、research。
- **票基础**：S1-S8 本机开发门已完成（S3.2 红队、S7 联网+MCP、S8 记忆）；RAG 六票（BASE/META/CHUNK/QRW/IDX/RERANK）完成；`HW-SUMM-01` 摘要器完成。

### 3.2 与主项目耦合度

- **代码层零耦合**：全量复核无 `from src.*` / `import scripts` 引用（唯一例外：`tools/rag_baseline.py` 的 `from src.rag_store import RagStore`，**函数内延迟导入**，属双端基准对照工具的受控例外）。
- 同仓共管、共享 fixtures 与度量口径；运行与回归（`test_harness_*.py` 35 文件）独立。

## 4. 完善路线（差距 → 动作）

### 4.1 增强有效性对照实验（最优先，当前为零）

- 新票 **`EX-HARNESS-01`**：三组对照 × 固定任务集，同一模型下比较——
  - 组 1：普通 chat（基线）｜组 2：+RAG+记忆｜组 3：+压缩+小模型组合
  - 指标：超预算多轮任务成功率、跨会话记忆召回率、RAG 引用准确率、同等任务 token/耗时成本
- 前置/依赖：`EX-CTX-MEAS-01`（30 轮召回曲线）先落地度量口径；报告进入答辩 evidence ledger。
- 验收门：三组对照报告 + 每组 ≥3 轮稳定结果；"增强有效"结论必须有数字支撑（无数字不宣称）。

### 4.2 模型侧增强接线（资产已就绪）

- `LLMSummarizer` **质量测度**（现在可用但未证优于规则压缩；Qwen3-0.6B 角色）。
- **模型化 rerank**（QwenSeek-2B 1.27GB 已下载，作轻量候选）。
- **draft-verify**（`EX-SPEC-ROLE-01`，2B draft + 9B/7B verify；与 `role_asymmetry` 假设一一对应）。

### 4.3 实用化

- 9B GPU offload 提速（8GB 显存可全量；本次 CPU 标定 580s/轮仅作口径基准）。
- 一键启动：模型加载/预热/上下文策略默认档（`cli.py` 单入口）。

### 4.4 价值可见化

- 对话内展示"本次回答用了哪些增强"（RAG/记忆命中引用、压缩是否发生、草稿/验证角色）——否则用户感知不到与普通对话的差别。

### 4.5 后置项（不阻塞价值主张）

- 外部 MCP 服务验收（S7-MCP-02 后置）、生图真机执行器（见 §5）。

## 5. 生图规划（内置生图工具，SD 1.5）

- 目标：Koakumix 提供**内置生图工具**，调用 SD 1.5 完成——**远程推理与本地推理均支持**：
  - **本地推理**：复用 `image_workbench` 既有契约（contracts/manifest/注入式执行器/资产原子落盘），接真实 diffusers/CUDA 执行器（S3.2-IMG-01 后置项）。
  - **远程推理**：仅文本、RAG 和多模态理解可经主项目服务路由；生图与编辑由 Koakumix 自有 `image_workbench` 独立执行，不调用主项目 SD 服务。
- 票：`KX-IMG-01`（本地工具接线）、`KX-IMG-02`（远程路由）、`KX-MM-01`（生图→多模态追问闭环）；与 S3.2-IMG/MM/EDIT 票合并推进。
- 边界：Koakumix 不训练/不微调图像模型；安全红队 fixture（S3.2-RT）对新工具路径同样适用。

## 7. git 子模块化节奏（何时把 Koakumix 拆为独立子模块）

**当前结论：不拆**。拆子模块的成本（独立仓库、detached HEAD/bump 纪律、夹具版本化）在现阶段大于收益；`harness_workbench/` 继续同仓共管、零耦合演进。

**触发条件（满足 ≥2 项时启动拆分评估）**：
1. **接口冻结**：`api_layer`/MCP/CLI 对外接口稳定到可打 semver（破坏性变更低频）；
2. **宿主外使用**：需要被主项目之外使用（第二个项目/外部用户/独立分发）；
3. **独立 CI 需求**：Koakumix 测试不再适合每次跟随主项目全量回归（构建时长/依赖分歧）；
4. **夹具契约化**：与主项目共享的 fixtures（prompt sets/rubrics/RAG 基准）已改为版本化契约，不再依赖同仓引入。

**过渡准备（拆分前先做，不依赖拆分决定）**：
- 包化：`harness_workbench/pyproject.toml`（独立包元数据/入口点）；
- 边界清理：`rag_baseline` 的双端对照改为"显式路径注入"而非 import 主项目；
- 夹具版本化：prompt sets/rubrics 加版本与指纹（多数已有 sha256，补发布流程）。

**过渡准备进展（2026-09-14，已完成三项）**：
1. ✅ **包化**：`harness_workbench/pyproject.toml`——分发名 `koakumix` v0.1.0、**运行时零第三方依赖**（`dependencies = []`，全库仅标准库）、`[project.optional-dependencies] tui = ["textual>=8.2"]`、console script `koakumix = harness_workbench.cli:main`、`package-dir` 映射（代码目录即包根）。
2. ✅ **边界清理**：`rag_baseline` 的 `from src.rag_store import …` 改为**显式路径注入**——新增 `_resolve_main_project_root`（参数 → `QLH_MAIN_PROJECT_ROOT` → cwd）与 `_main_project_importable`（临时 sys.path 上下文）；三个入口函数加 `main_project_root` 参数；CLI 加 `--main-project-root`；无效 root **fail-closed**（`main_project_root_invalid`，不再静默依赖 cwd）。
3. ✅ **夹具版本化**：`harness_workbench/tools/fixture_manifest.py` + `fixtures/MANIFEST.json`（**25 条**：prompt sets `prompts.jsonl` / rubrics / experiment plans 的文件级 sha256，**与 EX-N3 runner 锁定口径一致**——`ps-qwen3-nothink` = `c55caa2a…`、v2 rubric = `14d13d9d…`）；`--check` 确定性校验（无时间戳），可进 CI。

**验证**：全量 harness 定向回归 `254 passed`；manifest `--check` OK；新增测试覆盖显式注入 fail-closed 与 manifest 漂移检测。

**预计时点**：与"§4.1 对照实验有结论 + api_layer 接口冻结"同步评估（不早于 Koakumix 价值验证完成）。
