# 容量诊断与 MTP 预算修复（2026-10-15）

本轮处理票 13 续验发现的两项问题：容量不足被泛化为等待节点，以及 GGUF 中实际不会装入层段的 MTP 张量被计入预算。发行物验收按用户安排后置，票 13 保持开放。master 唯一协调、星状连接、DL／LL 连续 proper segments 的设计与整模守卫不变。

## 容量不足提示

原供给规划失败后进入自动扩池等待，`SUPPLY_WAITING_NODES` 覆盖了容量拒绝原因；主机源权重暂存不足也只提供泛化文本。现在由供给 owner 生成结构化 `capacity_diagnostic`，模型意图与 API／TUI／Android 仅投影它：

- 已连接节点容量不足时保留真实 reason code，界面显示等待容量；节点确实尚在握手时才显示等待加入。两者同时发生时另列正在加入的节点。
- 分别报告 RAM、显存与 CUDA 源权重的主机暂存 RAM，提供节点、候选层段、可用量、所需量及精确字节缺口。主节点不能承担首段时，也保留具名诊断，不发布 worker-only 计划。
- 诊断只在独立副本中增加相同容量增量，复用真实 solver 取得一个保持节点顺序和层段约束的候选；需求仍使用同一边界、倍率、取整与预留。该副本不进入供给、构建、prepare 或执行。
- 候选缺口不是最小缺口；释放所列容量仍需重新盘点与规划。无法形成合法候选时省略未知的所需量和缺口，不把总权重差额冒充逐节点缺口。
- Host staging 依据同一源张量预算单独解释。若 host range 限制导致泛化的区间拒绝，先用原运行时 solver 证明去掉 host 限制能形成候选，再指出该候选的 host 缺口。
- 等待到截止时间后保留原容量原因；新规划开始时清除旧诊断。就绪、取消、准备中及原因不匹配时不显示残留容量诊断；同原因的容量失败仍可查看详细数字。
- 自动等待仍在新节点 inventory 到达后重规划；已有节点释放内存后需重试模型选择，触发新的资源盘点。所示数字是该次 inventory 的快照，不是持续资源监控。
- TUI 与 Android 均展示易读单位和精确 bytes。缺失需求或缺口保持未知；Android 使用严格可空 64 位整数解析，不从 Double 还原 generation 或字节数，不新增客户端准入判据。

结构化诊断保存在供给操作中，意图层没有新增一套容量状态。示例来自真实 Qwen3.5-9B 头部与明确标注的低容量输入，见 `build/capacity-budget-followup-20261015/final-source-replay/capacity-ui-example.txt`；它不是现场容量或新的实际推理操作。

## 独立复核闭环

复核发现一个既存规划约束缺口：8 层、对齐 4 层、master 可用 100 bytes 且首段预算 97 bytes 时，master + worker 可以运行；增加第二个大容量 worker 后，通用 solver 可能为余量更大而选择两个 worker，供给层随后误报 master 容量不足。现在将 master 执行非空首段作为真实 solver 的硬约束，诊断求解及递归重放沿用同一约束，默认通用调用语义保持兼容。缺失或耗尽的 master 仍拒绝，容量守卫未降低。

另修正两处证据生命周期问题：公开取消会清理当前 reason，保留的旧诊断明确标为 `historical=true`；intent 截止仍能从供给 owner 投影原容量原因。Host RAM 的反事实解释保留 `origin_reason_code`／`origin_reason`，能追溯原 solver 的范围拒绝；移除 host 限制得到的候选只用于解释，不发布为计划，不进入 build／prepare。

初始复核、复现与最终复核另存于专项 build 目录，保留发现历史。最终独立报告 `independent-review-final.md` 确认 R1／R2／R3 闭环，所审快照未发现未闭环的 P0／P1／P2；独立定向 187 passed，另有六个隔离复现场景通过，均与最终冻结匹配。复核包含 Android 四文件及其 JVM 证据，不替代设备验收。

## MTP 预算同源

新增不依赖模型加载器的 GGUF 张量选择规则，描述符、磁盘预算、builder 及裁切后的张量集合核验共用。只排除 GGUF 明确声明、位于 decoder 之外的 MTP block；未知非 `blk.*` 张量仍保守计入。非法块名、越界索引与非法标量元数据提前拒绝。预裁工件保持 manifest 的全局源层坐标。

描述符分别保留原文件大小、源 payload 总量、执行 payload 总量和逐张量排除记录，源与工件身份没有因预算修正而重写。没有修改 `runtime_multiplier=2.0`、`safety_margin=1.2` 或 512 MiB 固定安全预留。

真实源 `qwen3-5-9b-local-Q4_K_M.gguf` 的只读复算如下：

| 项目 | 字节 |
| --- | ---: |
| builder 排除的 decoder 外 MTP | 150,980,608 |
| 修复前最小四层段预算 | 5,495,497,319 |
| 同政策下修复后最小四层段预算 | 5,133,143,860 |

全部八个对齐四层区间的 descriptor 预算与 builder 的头部选择结果一致。身份核验读取全文件摘要，没有物化源整模权重或构造原生整模。最终源码复算材料见 `final-source-replay/actual-source-budget-replay.json`（与早期复算的源身份、八个区间和政策一致）；该复算不代表任何历史或当前节点已准入。
