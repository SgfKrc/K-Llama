## 1. 判定标准

进入 A/B 档的候选须**同时**满足四条：

1. **跨项目复用面** —— 脱离 QLH 业务仍有真实使用方；
2. **自包含度高** —— 不 import 主项目业务模块，边界可以一刀切；
3. **有可机器验证的验收门** —— 抽出时可把门一起带走（本仓库最有价值的部分其实是门）；
4. **依赖轻** —— 纯标准库或单一同质依赖。

反面理由（为什么标准要严）：多一个仓库 = 契约漂移 + 双 CI + 版本对齐成本。**"代码量大"本身不构成抽离理由**——这与[既有独立化评估](项目后续可做方向发散与子项目独立化评估-2026-09-09.md) §4 对 harness 整体独立化给出的保留意见一致。

### 2.1 `UNI-A1` 进程归属票据 + fail-closed 重置（`UNI-A1-01` 已完成）

**现状（实测）**：`scripts/demo/demo_ownership.py` 302 行 + `defense_reset.py` 299 行 + `reset.bat`/`reset.sh` + `tests/test_defense_reset.py` 267 行 9 个测试（8 个常规 + 1 个需 `QLH_RUN_DEFENSE_RESET_INTEGRATION=1` 的实机门）。能力：崩溃可恢复的所有权票据（`pid`/`create_time`/`kind`/`root_pid`，原子写入 `*.tmp` → `os.replace`）；默认 dry-run，`--apply` 前按 PID 创建时间、工作目录、内置命令白名单**三重复核**；身份错配/无法停止/端口占用统一 `REVIEW_REQUIRED` 并保留现场；幂等（第二次 apply 为零票据）。

**四条件对照**：复用面——任何"启动子进程做演示/测试/压测"的项目都需要它；自包含——票据层只依赖 `psutil`，耦合点是 `OWNERSHIP_ROOT`/`FRONTEND_ROOT` 与 `_command_matches` 里 QLH 形态的命令白名单（npm/vite/esbuild、`uvicorn src.api_server:app`、两个 demo worker）；验收门——既有 9 个测试可迁移（含"篡改票据必须 `REVIEW_REQUIRED`""幂等""只删已死进程票据"）；依赖——`psutil`（BSD）。

**抽离形态**：包 `spawnledger`——`OwnershipLedger(source, ports=[])` → `register(kind, pid)` → `close()`，CLI `spawnledger-reset [--apply] [--report PATH]`。命令白名单改为**可信代码注入策略**（调用方给出 `{kind: matcher(command, cwd)}`，核心不提供可扩权的宽松默认策略）；`OWNERSHIP_ROOT`、报告路径参数化；`reset.bat/sh` 退化为薄包装。

**前置与工作量**：抽策略层 + 参数化路径 + 补 POSIX 分支测试 ≈ 1–2 人日。本机只有 Windows，POSIX 终止路径必须在 WSL 或 CI 上验一次。

**风险**：Windows 与 WSL/POSIX 已各完成一次真实进程恢复门；后续独立仓库仍需用双平台 CI 持续守门。误杀风险继续依靠冻结根进程创建时间、动作前身份复核、可信可执行文件/命令策略与默认 dry-run 缓解，任何阶段**不得**降级为"信任票据内容"。

**实施记录（2026-09-14）**：正式票 `UNI-A1-01` 已新增内部独立包 `packages/spawnledger/`（`pyproject.toml`、README、独立 pytest 配置、包内测试），公开策略注入、票据、身份复核、dry-run/apply 重置和 CLI；QLH 的 Vite/esbuild/uvicorn/worker 白名单留在 `scripts/demo/demo_ownership.py` 适配层，既有 `defense_demo.py`、`defense_benchmark.py` 与 reset 薄入口保持兼容。随抽包修复非有限/非正创建时间绕过、根 PID 复用后重新签发、损坏票据 `all([])` 清除、票据检查/删除替换竞态与活动原子临时文件误删风险；临时文件编码写入者 PID/创建时间，只在写入者确认失活时清理，旧格式保留复核。Windows 答辩链回归 `81 passed, 2 skipped`（包内 POSIX 门与 Vite 实机门按平台/显式开关跳过），Windows Vite 崩溃恢复门另行实跑 `1 passed`；WSL/Ubuntu 包内测试 `29 passed`，包含真实 POSIX SIGTERM 回收；clean-source wheel 构建成功且不含字节码/测试产物。独立远端与 submodule 化仍按 §7 作为后续阶段，不属于本票。

## 4. C 档：只保留一项入选 + 一项低优先观察

### 4.1 入选：`UNI-C1` venv 环境治理工具

- 位置与规模：`scripts/setup_envs.py`（663 行），**纯标准库**（`argparse`/`venv`/`shutil`/`subprocess`/`tempfile` 等，无第三方）。
- 现状能力（实测 CLI）：`--list` 环境清单、`--all` 全量、`--only`/`--skip` 选择、`--no-node` 跳过 Node 子项目、`--check` 只校验不安装、`--snapshot` 导出 `requirements-lock/*.lock.txt`、`--dry-run`、`--torch-index-url` 指定 PyTorch 源（torch 刻意不自动装）。
- 抽离形态：把内嵌的环境定义**数据化**（一份 `envs.yaml`/`envs.json` 描述"主环境 / 测试 / 打包 / TUI"各层），保留 `--check`/`--snapshot` 语义并增加**快照漂移检测**（当前 `--check` 只做健康检查，不与 lock 比对），产出通用的 *multi-venv manager*。
- 依赖：零第三方。
- 验收门：`--check` 只读校验；`--snapshot` 可复现导出；漂移检测对人为改动的环境报差异；全部离线可跑。
- 毕设适配：中高（工程效能方向，可扩展到 CI 缓存与锁文件治理）。

## 7. 团队分工与落地约定

1. **先内部独立包，后独立仓库**：`packages/<name>/`（自带 `pyproject.toml` + `tests/` + README）→ 验收门跑通 → 再建远端仓库并换 submodule。这样主仓不被搅动，也避免整包独立的契约漂移。
2. **搬代码必须搬门**：抽离时把验收门、脱敏契约（不落正文/密钥/绝对路径）、fail-closed 语义一并带走；只搬代码不搬门，子项目讲不出"可证明能用"。
3. **每个子项目自带四件套**：README（含用法与边界）、验收门命令、离线可跑的测试、脱敏示例输出。
4. **不复制源码回主仓**：主仓只保留 gitlink 与接线文档（沿用 `docagent`、`reasonix-codex-bridge` 的做法）。
5. **一个候选一张票**：本文只提供候选池与排序；正式开工时在开发票文档登记，附依赖与验收门。
