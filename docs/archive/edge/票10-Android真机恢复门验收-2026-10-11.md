## 2. 损坏 prefs 冷启动恢复（核心判据）

操作（注入的是**垃圾字节**，原文件已先备份）：

```bash
adb shell am force-stop com.qlh.inference.debug
adb shell "run-as com.qlh.inference.debug sh -c 'echo not-a-valid-protobuf > \
  /data/data/com.qlh.inference.debug/files/datastore/qlh_settings.preferences_pb'"
adb shell monkey -p com.qlh.inference.debug -c android.intent.category.LAUNCHER 1
```

实测（注入后 21 字节 ⇒ 冷启动）：

```
files/datastore/
  qlh_settings.preferences_pb                                       1885 B   <- 回退后的默认值
  qlh_settings.preferences_pb.corrupt-1791695108014-8673fda7-…         21 B   <- 坏文件已留证
日志: W SettingsDataStore: corrupt preferences replaced with defaults
app  pid = 20704（未崩、未进崩溃循环）
```

⇒ 与票 10 登记的预期一致：**坏文件先复制到应用私有 `files/datastore/` 留证，再回退默认 prefs**，
同一坏文件不会造成无限崩溃。

## 4. 过程失误与教训（**必须如实记录**）

清理注入的坏 prefs 时，我按下面的方式做了备份：

```powershell
$b64 = adb shell run-as com.qlh.inference.debug base64 files/datastore/qlh_settings.preferences_pb
$b64 -join "`n" | Set-Content -Path build\y700-backup\qlh_settings.preferences_pb.b64 -Encoding ASCII
```

**这个备份不可靠**：PowerShell 捕获 `base64` 输出再拼接时失真（回滚时解码得 2397 字节，
而原文件 2351 字节），把"恢复"的文件写回后 **DataStore 仍判定它损坏** ⇒ 再次回退默认。

后果与处置：

- DataStore 归零 ⇒ app **自动 bootstrap 成功重入群**（`first-connect` 公钥交换，无需集群密钥）
  ⇒ 这反倒**非计划内验证了票 10 的 A 步骤后半程**（清数据 ⇒ 重新入群）；
- 外部工件（`/sdcard/Download/QLH/models`，13 个 `.gguf`）与 `shared_prefs/qlh_cluster_credential.xml` **未受影响**；
- 剩余缺口只有 SAF 授权 ⇒ 由用户在设备上重新选目录后恢复（§3），随后三机接力复验通过（§1 末行）。

**教训**：`adb shell` 的二进制/编码输**不要经 PowerShell 变量与 `Set-Content` 往返**。可靠做法是
`adb exec-out > file`（`cmd /c` 重定向，字节级）或 `adb push` + `run-as cp`（本轮最终采用的路径）。
另外 `run-as sh -c` 的工作目录**不是** app data 目录，必须用绝对路径，否则重定向到相对路径会
`can't create …: No such file or directory`。

## 5. 破坏性步骤影响清单（本轮实测补充）

`pm clear` 会清除（本轮以"DataStore 归零"等价观察）：

- DataStore 全部键：`android_node_id`、`server_host/port`、`master_tcp_host/port`、`cluster_id`、
  `model_manifest_url`、`model_tree_uri`（SAF 授权）、`selected_model_uri`、`model_storage_mode`、
  `bootstrapped`、`task_worker_startup`；
- 应用私有日志 `files/logs/*`；`files/models`（空）；`profileInstalled`；电池优化豁免标记。

不会清除：`/sdcard/Download/QLH/models` 下的工件、APK 本体。

⇒ **清数据后**：app 会**自动 bootstrap 重入群**（实测），但**必须重新授权 SAF 目录**（UI 操作），
两者缺一都会退化成"能开但不参与集群"的孤儿态（文档 #78）。
