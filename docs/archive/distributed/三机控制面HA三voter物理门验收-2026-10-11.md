> 状态：**核心判据已通过**（真实三机 + 独立持久账本）
>
> 拓扑：`master-voter`（本机 `100.90.76.108:9102`）+ `rog-voter`（ROG `100.116.17.12:9102`）
> + `y700-voter`（Y700/Termux `100.99.211.13:9102`），voter set
> `cluster_id=qlh-physical-quorum` `epoch=1` `quorum_size=2`。
> 本文是本轮唯一事实来源；缺陷登记在 `docs/已知问题记录.md`。

## 1. 结论

三台机器各跑一个 voter RPC 服务、各持**独立 sqlite 账本**，`QuorumCollector` 经 Tailscale
直连签发/续期租约。实测（同一轮，真实时钟）：

```
1) acquire (3/3)      : accepted=True  term=7  signed=(master-voter, rog-voter, y700-voter)
2) renew (2/3, swap)  : accepted=True  term_same=True  expiry 延长  signed=(master-voter, y700-voter)
3) renew (1/3)        : accepted=False reason=quorum_unavailable
4) takeover after loss: accepted=True  term=8 (was 7)
5) acquire (1/3)      : accepted=False reason=quorum_unavailable
6) renew after expiry : accepted=False reason=quorum_unavailable
```

物理断链（真实杀进程，非模拟）：

| 操作 | 结果 |
|---|---|
| 杀掉 ROG 的 voter（剩 2/3） | `acquire accepted=True term=3 signed=(master-voter, y700-voter)` ⇒ **多数仍可用** |
| 再杀掉 Y700 的 voter（剩 1/3） | `acquire accepted=False reason=quorum_unavailable` ⇒ **fail-closed** |
| 两台恢复后 | 再次 `PASS`，且任期连续推进（`term 5 → 6 → 7 → 8`）⇒ **独立账本跨重启持久** |

⇒ 这同时验证了票 11 本轮修的语义：**严格单调续期**（同 term/lease、expiry 严格延长）、
**续期可换 majority**（原签名节点不在 `available_voter_ids` 时用第三台）、
**多数丢失立即撤销**、**任期推进防重放**、**过期证书不可续期**。

## 2. 复现方法

### 2.1 密钥与 voter set（本机生成一次）

`build/ha-3voter/`（脚手架，`build/` 已 gitignore）内：

```
voter_set.json      cluster_id=qlh-physical-quorum, epoch=1, quorum_size=2
master-voter.key    Ed25519 seed（unpadded base64url）
rog-voter.key
y700-voter.key
```

生成要点：公钥/私钥都必须用 **unpadded base64url**（`base64.urlsafe_b64encode(x).rstrip(b'=')`）——
标准 base64 会被 `cluster_control_contract._unb64` 拒为 `public_key must be unpadded base64url text`。

### 2.2 voter 运行载体（本轮新增脚手架）

仓内 voter RPC **只有内嵌入口**（`api_server` 的 `POST /api/cluster/quorum/voter`），而 Y700
（Android/Termux）跑不了完整后端 ⇒ 新增最小独立 runner：

- `build/ha-3voter/voter_runner.py`：stdlib `ThreadingHTTPServer` + `X-QLH-Quorum-Secret` 头校验 +
  直接复用 `AutoRoleRuntime.handle_rpc`（**wire 契约与内嵌端点完全一致**），
  支持 `--config <json>`（三机 shell 不同，JSON 走 env 是引号雷区）。
- 每机的 config 里带各自的 `ledger` / `log` / `src_dir`（Y700 没有仓库检出 ⇒ 传了 `src/` 12MB）。

启动（三机同一条命令）：

```bash
python voter_runner.py --config <本机 config.json>
```

### 2.3 验证

```powershell
python build\ha-3voter\three_machine_quorum_smoke.py   # 6 项判据
```

注意事项（本轮踩到的坑，均有记录价值）：

- **必须绕过系统代理**：本机注册了 Clash（`127.0.0.1:7897`），`urllib` 默认走它 ⇒ 对 Tailscale
  地址返回 502。脚本里 `install_opener(build_opener(ProxyHandler({})))` 直连。
- **时间戳必须用真实时钟**：voter 账本跨重启持久，用固定的过去时刻会被正确判为
  `quorum_expiry_regressed`。
- **voter 进程必须活过调用它的 shell**：Windows 上 `DETACHED_PROCESS` 会丢 stdout 句柄
  （表现为 0 字节日志），因此 runner **自己写日志文件**；在 Host 会话里则以后台作业承载。

### 2.4 Y700（Termux）侧准备

```bash
pkg install -y python-cryptography     # pip install cryptography 会尝试源码编译并失败
mkdir -p ~/qlh-3voter && cd ~/qlh-3voter   # 传 src/ + voter_runner.py + y700-voter.config.json
python3 voter_runner.py --config y700-voter.config.json
```

## 3. 未覆盖（不得外推为生产 HA）

票 11 文档已登记的**结构缺口**，本轮**未接线、也未验证**：

- **提交证明**：没有把 voter 身份、任期/lease、工作流链摘要与多数耐久 ACK 绑定的证明；
- **候选选主不检验已提交前缀**；跨机重建与未提交尾部截断未实现；
- 手动 journal checkpoint 推送仍是「单副本耐久 ACK」，**不是** quorum commit watermark；
- 未做 split-vote / 真实网络分区（本轮的"断链"是**杀进程**，不是链路层分区）；
- 数据面（Route A 层接力）仍为 master 星状转发 + D→L/L→L 接力，与本控制面正交。

## 4. 与三机层接力验收的关系

同一天完成的两项验收共用同一三机拓扑但互不依赖：

- **数据面**：`docs/三机产品路径层接力验收-ROG-Y700-master-2026-10-11.md`（`fallback=false`）；
- **控制面**：本文（三 voter 选主与 fencing）。

两项验收期间，master 的 `api_server`（HTTP 8000 / TCP 8888）与 ROG/Y700 的 worker 均保持运行，
voter 走独立端口 9102，**没有互相干扰**。
