# QLH 支线开发计划：外置迁移与 Koakumix（2026-09-15）

> 文档状态：**现行**
>
> 生命周期：**支线基线（Active / Migration）**
>
> 适用范围：不属于 QLH 分布式推理核心的功能、产品壳、侧车服务、研究工具和历史材料。
>
> 主线入口：[主线开发计划：分布式推理与边缘优化](../../主线开发计划-分布式推理与边缘优化-2026-09-14.md)。本计划不能反向扩大主仓边界。

## 1. 支线原则

支线不是主仓的“第二产品线”。每个支线必须有自己的仓库、环境、测试和发布责任，主仓只保留稳定合同、模型 manifest、必要的客户端协议和最小适配器。

迁移顺序固定为：**盘点引用 → 归档证据 → 建立独立包/仓库 → 契约回归 → 移除主仓实现 → 更新链接和 README**。未经契约回归，不直接删除仍被主线调用的代码；已确认无调用的功能按“先归档后删”处理。

## 2. 角色敲定

| 支线/仓库 | 责任 | 主仓边界 |
| --- | --- | --- |
| **Koakumix harness** | 小模型定制对话、实验工作台、图像生成、可选多模态增强、MCP 和用户自定义流程 | 通过 OpenAI 兼容 API、模型 manifest 和显式工件引用接入；不 import QLH 源码 |
| **Patchouli（qlh-docagent）** | 文档维护引擎（只读扫描 R1–R5、规则演进、链接与状态维护）+ 知识库 TUI（书架/检索/编目/流转/审计路由/启动动画）+ MCP 只读工具面（8 件）；文档库、RAG 与长期知识检索 | 独立子模块 `tools/docagent`（引擎与 `patchouli/` 包**同仓合并**，主仓 `tools/patchouli` 已删）；主仓只保留接线与文档规则，不保留通用 RAG 数据面 |
| **qlh-shell** | Web/桌面壳、Android 客户端、图形启动器和产品交互包装 | 只调用 QLH API/TUI 合同；不成为主仓验收前置 |
| **qlh-release** | 安装包、更新/回滚、离线资产整合和平台分发 | 读取已签名 manifest；不携带主仓之外的运行时核心 |
| **qlh-toolbox** | 答辩演示、性能图表、网络探针、SSH/补丁同步和环境编排 | 只保存证据生产工具；主仓保留可复现的核心实验脚本和质量门 |
| **reasonix-codex-bridge** | 只读调研、受控任务桥接、checkpoint 和回滚 | 独立子模块；默认只读，写入不替代代码审查 |
| **spawnledger** | 进程归属、清理和运行票据 | 独立子模块；不进入推理业务路径 |

图像生成的唯一实现归属为 **Koakumix**。QLH 可以接受图片输入并执行可选的多模态理解，但不保留 diffusion、图像生成 API、生成任务图、生成模型依赖或生成式前端。

## 4. 支线验收门

每个支线仓库至少要通过以下门：

1. 主仓 clean clone 不安装支线也能运行标准库 TUI（当前 `python -m src.tui_admin --plain`）和 Edge smoke；`qlh chat` 统一别名已由 `CORE-TUI-01` 收口。
2. 支线不通过相对路径 import 主仓源码，不读取主仓私有数据库、密钥或内部路径。
3. 交互只使用版本化 API、TUI 协议、任务协议或模型 manifest。
4. 迁移前后有同一组合同测试；失败时 fail-closed，不自动切回旧实现。
5. 资产由用户持有，下载/缓存/日志/凭据边界在支线文档中单独说明。
6. 迁移完成后主仓 README、文档索引、安装脚本和测试选择器不再把支线标成主线能力。

## 5. 主线与支线的停止条件

- 任何支线若需要修改调度、模型身份、任务租约或推理协议，必须先提交主线合同变更；不能在侧车内私自扩展语义。
- 任何“为了兼容旧项目”而恢复 Web、微服务、生图或旧管理端的请求，直接回到本计划重新评估。
- 支线未完成不阻塞 Edge L 档和主线 TUI；主线也不为支线保留隐式依赖。
