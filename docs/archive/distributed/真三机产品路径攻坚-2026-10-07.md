## 4. 本轮的关键澄清（其中两条是**错判纠正**）

### 4.1 「空响应」= thinking 门，不是数值故障（最重要）

`scheduler_pipeline.py` 的 `native_thinking_prompt = bool(not show_thinking and "<think" in model_prompt[-128:].lower())`
为真时，`inference_service/engine_host.py:_format_model_response` 会：
```python
if native_thinking_prompt and "</think>" not in (text or "").lower():
    return "", None          # 不暴露「未完成的 native reasoning」
```
⇒ `max_tokens` 太小时模型还没输出 `</think>` ⇒ **按设计返回空**。
**链路与数值一直是对的**：逐 token 日志显示真实 token（` + 1 = **2**`）。`max_tokens=48` + `show_thinking=true` 即得 `content='2'`。
⇒ 教训：**「空响应」既可能是数值错，也可能是后处理门**；`show_thinking=true` + 足够 `max_tokens` 是必备的判别手段。

### 4.2 **qwen3.5 的 keep-head 挂点其实可用**（推翻本轮早先的判断）

实测 `build/keephead/probe_q35_hook.py`（本机，prompt 4 tokens）：

| 对比 | 结果 |
|---|---|
| `KeepHeadUpstream(mode="nextn")`（head16 工件）vs `[0,16)` 层输出 | `rel_err=7.169e-02` **`cos=0.988463`** |
| `KeepHeadUpstream(mode="layer_inp", cut_layer=16)`（整模）vs `[0,16)` 层输出 | 同上（两者输出一致） |
| 上述两者 vs 整模 24 层输出 | `rel_err=8.441e-01` `cos=0.261781`（**基准给错时的假象**） |

⇒ **两个模式输出相同，且都对应 `blk.15` 的输出（`output_norm` 之前）**；`rel_err≈7e-02` 是
GGUF `Q4_K_M` 量化 vs HF `fp32` 的正常量级。
⇒ `llama_engine.py:1995-1999` 的 `if model_type.startswith("qwen3"): return None` 是**基于
2026-09-23 之前的旧 `t_h_nextn` 通道**写的；`qlh_keep_head.c:14-21` 记载此后统一改为
`layer_inp` 的 `lid == n_layer` 槽位，挂点问题**已不复存在**。
⇒ **PC worker 侧（`engine_host.py`）没有这条判据反而是对的**。
（本轮一度把它当成 PC worker 的缺口，是把「head 工件输出」误比「整模 24 层输出」得出的假结论。）

### 4.3 本机整链 vs 整模：**4/4 完全一致**

`scripts/xframe_divergence_report.py --same-engine`（`head16 [0,16)` + `cut-16-20 [16,20)` + `cut-k20 [20,24)`）：
`合计 4/4 完全一致，输出长度不同 0，token 不一致 0，首分歧步 = []`。
⇒ Q4_K_M 量化不改变 argmax；数值面无需再查。

## 5. 已排除的干扰项（避免下次重踩）

- **bat 中文注释**：`cmd` 按 ANSI 代码页解析 `.bat`，非 ASCII 注释会被拆成命令并报
  `'必须与' 不是内部或外部命令`。**服务仍能起来**，但环境变量可能未按预期生效 ⇒ 一律写纯 ASCII。
- **SD 卡侧目录无效**：APK 的 `layer_ranges` 来源是 `ModelManager.listLayerArtifacts` **实时扫描**，
  但**优先 SAF tree**；未选目录时回退**内部存储** `filesDir/models`（`ModelManager.kt:299-317`）。
  本轮一度只改 `/sdcard/Download/QLH/models`，而 APK 实际扫的是内部目录 ⇒ 怎么改都不生效。
  **正解是在 App 设置里选中 SAF 目录**（`/sdcard/Download/QLH/models`），而非删文件。
- **SAF 递归 2 层**：`ModelManager.kt:484/499` 的 `maxDepth = 2`；把 manifest 下移到
  `_retired/` 只是第 1 层，**仍会被扫到**。要停用须改扩展名（扫描只认 `.json`）或移出 2 层。
- **APK 进程复用**：`am force-stop` + `am start` 有时**不换 PID**，App 仍用启动时扫描的旧列表。
  验证须比对 `pidof` 是否变化。
- **工件 sha 必须与 manifest 一致**：`_configured_layer_artifact` 会重算 GGUF 的 sha256 并与
  manifest `artifact_sha256` 比对，不符即返回 `None`（表现为「配置了却不生效」）。
- **持久化 `model_sha256` 会把候选钉死**：`scheduler_pipeline.py` 恢复流水线时按
  `state["model_sha256"]` 逐个校验候选路径；沿用旧 state 时 GGUF 的 sha 会让 HF 目录候选被跳过。
  验证新引擎选择须用**全新 `QLH_STATE_DIR`**。
- **日志行会被折行**：`local_docs/*.out` 里以时间戳开头的行才是一条完整日志；读之前要先把
  续行拼回去，否则关键字段（`tokens=` / `hidden_sha256=`）会被截断而看不见。
