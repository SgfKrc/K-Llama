## 0. 结论

1. **`Qn_K_M` 模板在 qwen35 上会结构性失败**。整模 `Q2_K` 实测 KLD **2.7199**、逐 token
   argmax 一致率 **31.74%**、PPL 9.03 → **132.4**。qwen35 的 Gated DeltaNet 分支中，
   `ssm_alpha`/`ssm_beta`（每层 0.13 MiB 的 4096×32 时间步调制）被模板一并压到 Q2_K。
   小体积、结构性必需的张量需要单独保护。
2. **UD 的"动态"是 per-tensor 位宽分配，分配依据是张量类别，不是层位置**。UD-Q3_K_XL
   逐层等效 bpw：前 8 层 **4.139** / 中 16 层 **4.169** / 后 8 层 **4.332**。
3. **`UD-Q4_K_XL` 使两个 CPU 段同时变大**。它的 lm_head 仍是 Q6_K、`token_embd` 仍是
   Q4_K，与 Q4_K_M 相同；差异全在层内（`ssm_out` Q5_K→Q8_0、`attn_*` Q4_K→Q5_K、
   `ffn_gate/up` 降至 IQ4_XS）。结果 `[0,8)` 1029.5 → **1081.9 MiB（+5.1%）**、
   `[8,24)` 1995.1 → **2136.5 MiB（+7.1%）**。
4. **逐层敏感度由传播路径长度决定，形状是 U 形偏左**。固定 1 层 Q3_K 只改位置：
   L0 KLD **0.0776**、L8 0.0147、L16 0.0070、L24 0.0038、L31 **0.0098**。
   单调衰减 20.6× 对应"误差沿深度累积放大"；末端反弹对应"末层紧贴输出端，无后续层平滑"。
5. **lm_head 是性价比最高的一端**。Q6_K→Q4_K 省 **250.1 MiB**，KLD 3.3e-5→5.704e-3；
   中段降 Q3_K 省 588.3 MiB，KLD 0.0724。每 MiB 代价差 **5.4 倍**。
6. **`Q3_K` 系在 master#cpu 上是负收益**。CPU repack 内核
   （`ggml_repack_get_optimal_repack_type`）不支持 Q3_K、IQ3_\*、IQ2_\*。现状 Q4_K_M 中段
   99.9% 字节走 repack；换 Q3_K_M 降至 43.8%，换 UD-Q3_K_XL 降至 **50.3%**。
   该节点是 decode 关键路径，丢 repack 的损失大于省 13.8% 字节的收益。
7. **上游 BF16 → 下游 Q4_K 的阶梯已经成立**。本机读制品头：`[0,8)` 的 pytorch 段 67 个
   张量全为 `BF16`；`[8,24)` 的 GGUF 为 115 个 `Q4_K` + 11 个 `Q6_K` + 89 个 `F32`。
   按字节/参数计 BF16 为 2.0、Q4_K 约 0.55，相差 3.6 倍。NInfer 上游原生 BF16，
   引擎切换不改变阶梯方向；把上游降到 4-bit 会使阶梯反转。

## 1. `UD-Q4_K_XL` 与 Unsloth Dynamic

### 1.1 命名体系

`UD-` 前缀 = Unsloth Dynamic。`Q4_K_XL` 以 K-quant Q4_K 为基准类型，`_XL` 是档位后缀。
命名不构成跨提供商的位宽保证；实际内容须读 GGUF 的 tensor type 表。

qwen35-9b 已发布文件（`unsloth/Qwen3.5-9B-GGUF`，模型卡标注 Dynamic **2.0** 代际）：

| 文件 | 字节 | 本机口径 |
|---|---|---|
| `Qwen3.5-9B-UD-Q2_K_XL.gguf` | 4,121,781,472 | 3930.8 MiB |
| `Qwen3.5-9B-UD-Q3_K_XL.gguf` | 5,053,834,464 | 4819.7 MiB |
| `Qwen3.5-9B-UD-Q4_K_XL.gguf` | 5,966,095,584 | 5689.7 MiB |
| `Qwen3.5-9B-Q4_K_M.gguf` | 5,680,522,464 | 5417.4 MiB |
| `imatrix_unsloth.gguf_file` | 5,150,208 | 公开 imatrix |

### 1.2 动态分配的落点（本机解析 GGUF header）

三个 UD 档的非块张量完全一致：`output.weight = Q6_K`（795.7 MiB）、
`token_embd.weight = Q4_K`（545.6 MiB）、`output_norm = F32`。UD 不改动 lm_head 与
embedding，差异全在层内。

按张量类别（32 层合计，MiB）：

| 张量 | Q4_K_M | UD-Q4_K_XL | UD-Q3_K_XL | UD-Q2_K_XL |
|---|---|---|---|---|
| `ffn_gate`+`ffn_up` | 1812.0 (Q4_K) | 1859.1 (Q4_K/IQ4_XS) | 1435.2 (Q3_K/IQ4_XS) | 1104.2 (Q2_K/IQ3_S) |
| `ffn_down` | 1113.6 (Q4_K/Q6_K) | 1132.1 (Q4_K/Q5_K/Q6_K) | 950.0 | 717.6 |
| `attn_qkv`（线性层） | 553.7 (Q5_K) | 553.7 (Q5_K) | 453.0 (Q4_K) | 264.2 (Q2_K) |
| `ssm_out` | 276.8 (**Q5_K**) | 427.8 (**Q8_0**) | 330.3 (**Q6_K**) | 276.8 (Q5_K) |
| `ssm_alpha`+`ssm_beta` | 6.7 (**Q8_0**) | 12.6 (**F16**) | 12.6 (**F16**) | 6.7 (Q8_0) |
| `attn_v`（4 个全注意力层） | 24.3 (Q6_K) | 27.5 (Q6_K) | 24.2 (Q5_K) | 15.5 (Q3_K) |

三条实际规则（本机反推，`[实测数据]`，第 3 条部分 `[推测]`）：

1. **保护结构性小张量**：`ssm_alpha`/`ssm_beta`（每层 0.13 MiB）抬到 F16（UD-Q4/Q3）或
   Q8_0（UD-Q2）。这正是 `Q2_K` 模板崩溃涉及的张量。
2. **压大体积 FFN、保 attention 与 SSM 输出投影**：`ffn_gate/up` 是唯一被系统性降到基准
   档以下的类别；`ssm_out` 则被抬到 Q8_0（32 层共 427.8 MiB）。
3. **层位置只影响注意力类型，不表达上下游优先级**：qwen35 每 4 层一个全注意力层
   （L3/7/11/…/31），这些层的 `attn_*` 单独处理；其余按类别分配，bpw 沿深度近似平坦、
   末端略高。

`_XL` 不蕴含"越靠前越高比特"。UD-Q3_K_XL 中 `blk.0.ffn_down = Q5_K` 而
`blk.20.ffn_down = Q4_K`（前高后低），同时 `blk.0.ffn_gate/up = Q3_K`、
`blk.31.ffn_gate/up = IQ4_XS`（前低后高）。逐层等效 bpw 合计为后段最高。

### 1.3 官方公布的质量/体积数据

同档位下以 +1.7%~4.4% GB 换 −2%~−8% KLD。该表印证 UD 比同档位模板略大，与本文在

## 2. imatrix 驱动的量化

### 2.1 原理与用法

`llama-imatrix` 跑校准文本，对每个张量累积 Σ(激活²)（对角近似 Fisher 信息），
`llama-quantize --imatrix` 据此加权量化误差最小化，使高激活权重获得更细的量化格点
（[tools/imatrix/README.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/imatrix/README.md)）。
相关 PR：#4861 引入、#4930 推广到全部 K-quant、#4969 legacy quant、#9400 GGUF 格式存储。

生成 imatrix 不需要 HF 授权、不需要联网：`llama-imatrix -m <任意 GGUF> -f <任意文本>`
纯本地。qwen35-9b 的公开 imatrix 亦可用（`imatrix_unsloth.gguf_file`，5.15 MB），
其 `imatrix.datasets=['unsloth_calibration_Qwen3.5-9B.txt']`、`chunk_count=80`、
`chunk_size=11264`（≈900k tokens），覆盖全部 32 层、496 个 tensor 条目
（`[实测数据]`，本机解析该文件）。

### 2.2 自算成本（本机实测）

| 配置 | 每 pass | 实测总耗时 |
|---|---|---|
| CPU（`-ngl 0`），4 chunks，`-c 4096` | 18.39 s | 74.8 s |
| GPU（`-ngl 99`），8 chunks，`-c 4096` | 8.79 s | 72.4 s |

外推到 80 chunks × 11264 tok：GPU 约 **30–35 分钟**，CPU 约 60–70 分钟（RTX 4060 Laptop
可用 `-ngl 99`）。imatrix 对领域敏感，自算语料取 `chat_history/` 与 `docs/`。

两个已知坑：本机 `runtime/llama-cpp/b10964/llama-imatrix.exe` 报并行配置错误无法启动，
`build/moe-cache-20261026/b11889/` 的可用（本文数据均来自 b11889）；`--process-output`
默认关闭，官方说明 `output.weight` 通常不宜用 imatrix 加权。

### 2.3 手工实现分层分配

`llama-quantize` 的细粒度选项足以复刻 UD 式分配
（[tools/quantize/README.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/quantize/README.md)）：

- `--tensor-type <regex>=<type>`：正则匹配张量名，可多次指定
- `--tensor-type-file`：从文件读取规则串，适合 15 条以上的配方
- `--output-tensor-type` / `--token-embedding-type`：专管 `output.weight` 与
  `token_embd.weight`
- `--imatrix` + `--include-weights` / `--exclude-weights`：限定 imatrix 作用范围

源码层面（`src/llama-quant.cpp` 的 `llama_tensor_get_type`），`--tensor-type` 命中即短路，
不走 ftype 内建规则；未命中才回落到模板逻辑。手工配方与模板可安全叠加。

可直接执行的命令模板（本机 `--dry-run` 验证过）：

```bash
llama-quantize --allow-requantize \
  --imatrix imatrix_qlh.gguf \
  --tensor-type-file tensor_types_qlh.txt \
  --output-tensor-type q5_k --token-embedding-type q4_k \
  src.gguf out.gguf Q4_K_M 16
```

`tensor_types_qlh.txt` 内容（按 §3.2 的 U 形敏感度排布，全部落在 repack 支持的类型内）：

```
attn_v=q6_k
blk\.([0-7])\.(ffn_gate|ffn_up|ffn_down|attn_qkv|attn_gate|attn_q|attn_k|attn_output|ssm_out)\.weight=q5_k
blk\.(28|29|30)\.(ffn_gate|ffn_up|ffn_down)\.weight=q5_k
blk\.(8|9|1[0-9]|2[0-3])\.(ffn_gate|ffn_up|ffn_down|attn_qkv|attn_gate|attn_q|attn_k|attn_output|ssm_out)\.weight=q4_k
```

本机 `--dry-run` 实测该配方：`[0,8)` = **1135.9 MiB**（+106.4）、
`[8,24)` = **1861.8 MiB**（−133.3）、`[24,28)` = 539.7 MiB（+31.1）、
`[28,32)` = 527.7 MiB（−4.6）、lm_head(Q5_K) = 666.9 MiB（−128.8）、
`token_embd`(Q4_K) = 545.6 MiB（不变）；整模 **5277.67 MiB（4.94 BPW）**，
`[8,24)` 的 repack 覆盖 **99.9%**。

净效果取决于哪一段在关键路径：对 Surface 是盈余（lm_head −129 MiB、层仅 +7.4 MiB），
对 master#cpu 则取决于中段 −116.9 MiB 能否兑现。此处的取舍由 §6.2 的放行门判定。

## 3. 分层精度的证据与本机实测

### 3.1 llama.cpp 内建规则与外部实现

- **内建规则本身就是两端抬高**：`src/llama-quant.cpp` 的 `llama_tensor_get_type_impl` 中
  `use_more_bits(i_layer, n_layers)` 在 `i_layer < n/8` **或** `i_layer >= 7n/8`
  **或** `(i_layer - n/8) % 3 == 2` 时返回真。Q4_K_M 用它把 `ffn_down`、`attn_v`
  抬到 Q6_K。
- **Unsloth 的 UD 按张量类别而非层位置分配**（§1.2 实测）。
- 层敏感度的量化研究可参考 Layer-Wise Quantization（arXiv 2406.17415）；
  `llama-imatrix --show-statistics` 实现其 ZD Score 作为逐层重要性指标。
- `Qwen3.5-9B` 的逐层敏感度公开数据：未找到。§3.2 为本机实测。

### 3.2 位移敏感度的形状

**实验 A（8 层等量窗口）**：Q3_K 精确作用于 8 层，四组文件字节完全相同
（5029.69 MiB = 5,284,979,936 B），只改窗口位置。基线为 lm_head Q8_0 的 logits，
语料 wikitext-2 `wiki.test.raw`，16 chunks × `-c 512`，CPU 8 线程：

| 窗口 | Mean KLD | Same top p |
|---|---|---|
| L00–07 | **0.116763 ± 0.007859** | 85.907 % |
| L08–15 | 0.045965 ± 0.004156 | 90.613 % |
| L16–23 | 0.032879 ± 0.001017 | 91.838 % |
| L24–31 | 0.029880 ± 0.001056 | 92.377 % |

首末比 **3.91×**。

**实验 B（单层，固定 1 层参数量，只改位置）**：

| 被 Q3_K 的层 | Mean KLD | Same top p |
|---|---|---|
| L0 | **0.077596** | 88.971 % |
| L8 | 0.014741 | 95.539 % |
| L16 | 0.006989 | 96.201 % |
| L24 | 0.003770 | 97.279 % |
| L31 | **0.009797** | 94.314 % |

固定误差源、缩短传播路径后 KLD 从 0.0776 降至 0.0038（**20.6×**），因此主导机制是
**误差沿深度的累积放大**，与上游权重是否更高精度无关。

**L31 反弹**是第二种机制：末层输出直接进 `output_norm` → lm_head，中途无后续层做非线性
重整，误差不被平滑。敏感度曲线因此是 **U 形偏左**。

**对配方的含义**：上游段提高精度时，误差要多走 24–32 层放大，收益被放大；下游降精度则
传播长度短。同时末层的 `[28,32)` 中 L31 与紧邻的 L28–30 保留高精度 —— 其 KLD 敏感度
是 L24 的 **2.6 倍**。

### 3.3 lm_head 与 token_embd 的取舍

**实验 C（lm_head 阶梯）**：其余固定 Q4_K_M，只改 `output.weight`：

| `output.weight` | 体积 | 段内变化 | Mean KLD | Same top p | ΔPPL |
|---|---|---|---|---|---|
| Q8_0（基线） | 1080.7 MiB | — | 0（参照） | 100 % | — |
| **Q6_K（现状）** | **795.7 MiB** | 0 | **0.000033** | 99.608 % | +0.007 |
| Q5_K | 666.9 MiB | **−128.8** | 0.001484 | 97.745 % | −0.001 |
| Q4_K | 545.6 MiB | **−250.1** | 0.005704 | 95.539 % | +0.059 |
| Q2_K | 333.7 MiB | −462.0 | 未测 | 未测 | 未测 |

参照系（[tools/perplexity/README.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/perplexity/README.md)
的 LLaMA-3-8B 记分板）：`q6_K` 整模 KLD 0.005452、`q8_0` 0.001355、`q4_K_M` 0.031273。
即 `out_q5k`（0.001484）≈ 整模 q8_0 水平，`out_q4k`（0.005704）≈ 整模 q6_K 水平。

**实验 D（token_embd）**：`--token-embedding-type` 只改 embedding（其余 Q4_K_M +
lm_head Q5_K）：

| `token_embd` | 体积 | 整模 |
|---|---|---|
| Q2_K | 318.3 MiB | 5001.7 MiB |
| Q4_K（现状） | 545.6 MiB | 5229.1 MiB |
| Q6_K | 795.7 MiB | 5479.1 MiB |

嵌入层 KLD 未及测量（实验因磁盘压力中断）。

**lm_head 体积与输出质量的取舍**：

- Surface 段（`[28,32)` + `output` + `token_embd`）= **1881.0 MiB**（按
  565.5 + 834.36 + 572.13 MB 换算到 MiB 为 1880.6 MiB，吻合到 0.4 MiB）。
- lm_head Q6_K→Q4_K 省 **250.1 MiB**，相对整段 −13.3%；相对 lm_head 自身
  （795.7 → 545.6）为 −31.4%。两个口径的分母不同，结论一致。
- 代价 KLD +0.0057，仍属"整模 q6_K 级"误差。
- 对照：中段降 Q3_K 省 588.3 MiB，KLD **0.0724** —— 每 MiB 代价是 lm_head 的 **5.4 倍**。

机理与 §3.2 相同：`output.weight` 每 token 只调用一次，误差不进残差主干、不被 24 层
复合放大；层内张量的误差会被后续所有层反复放大。

实验 C/D 由 `--allow-requantize` 从 Q4_K_M 二次量化得到，含额外二次误差。落地应从
BF16/F16 一次量化。绝对数值可能偏悲观，相对排序（lm_head 便宜、中段贵）不随二次误差
方向改变，因为二次误差对所有候选同向叠加。

## 4. 分设备、分段、分张量的配方

### 4.1 硬约束：master#cpu 的 repack 可用性

CPU 重排内核 `ggml_repack_get_optimal_repack_type`
（`ggml/src/ggml-cpu/repack.cpp`）注册的类型集合为：**Q4_0、Q4_K、Q5_K、Q6_K、Q2_K、
IQ4_NL、MXFP4、Q8_0**。Q3_K、IQ3_S、IQ3_XXS、IQ2_S、IQ2_XS、IQ2_XXS、IQ4_XS 不在其中。

本仓 22b 实测 repack 值 pp **1.13–1.36×**、tg **1.05–1.21×**（代价：hidden 相对 L2 差异
2.46%/4.04%，每次动 repack 需重过数值门）。

叠加到 `[8,24)` 段（按张量类型加权统计）：

| 方案 | `[8,24)` 体积 | repack 覆盖 | IQ 张量占比 |
|---|---|---|---|
| **Q4_K_M（现状）** | **1995.1 MiB** | **99.9 %** | 0 % |
| Q3_K_M 模板 | 1583.1 MiB (−20.7%) | **43.8 %** | 0 % |
| Q2_K 模板 | 1262.7 MiB (−36.7%) | 71.5 % | 0 % |
| UD-Q4_K_XL | 2136.5 MiB (+7.1%) | 90.1 % | 9.5 % |
| **UD-Q3_K_XL** | 1720.1 MiB (−13.8%) | **50.3 %** | **22.6 %** |
| UD-Q2_K_XL | 1281.1 MiB (−35.8%) | 47.9 % | 33.3 % |

master#cpu 上任何 Q3_K 方案都使约一半字节掉出 repack 快路径。该节点瓶颈在解量化
（每 token 27.8 GB/s，已接近纯读上限），Q3_K 的两级查表解包正好落在该路径上；
IQ 系列在本仓 CPU 上另有 pp 慢 3–5× 的既有结论。

### 4.2 各段配方

| 段 | 设备 | 现状 | 配方 | 体积变化 | 风险 |
|---|---|---|---|---|---|
| `[0,8)` | master GPU fp16 | 5261 MB | 保持 fp16 | — | 换 GGUF 需换引擎、重做 `layer_inp` 钩子、重过数值门；省 4.2 GB 而显存不紧张（8 GB 装 5.26 GB） |
| `[8,24)` | master#cpu | 1995.1 MiB | 保持 Q4_K_M | — | 降 Q3_K 省 20.7% 但 repack 99.9%→43.8%，decode 关键路径净亏 |
| `[8,24)` 备选 | master#cpu | 同上 | 仅 `ffn_down` 降 Q3_K | 约 −100 MiB（−5%） | 需自测；repack 损失局部化在 `ffn_down`（该张量占 24.8%） |
| `[24,28)` | y700 Android | 508.6 MiB | 保持不变 | — | ARM 上 IQ 张量解包开销更高 |
| `[28,32)` 层 | Surface | 539.7 MiB | 保持；L28–30 可降 Q4_K | 约 −25 MiB | §3.2：L31 敏感度回弹 2.6× |
| **`output.weight`** | Surface | **Q6_K 795.7 MiB** | **Q5_K** | **−128.8 MiB（段 −6.8%）** | KLD 3.3e-5→1.48e-3，top-p 一致 99.6%→97.7% |
| `output.weight` 进取版 | Surface | Q6_K | Q4_K | −250.1 MiB（段 −13.3%） | KLD→5.70e-3，top-p 一致 95.5%，属"整模 q6_K 级" |
| `token_embd` | Surface | Q4_K 545.6 MiB | 保持不变 | — | Q2_K 省 227 MiB 但 KLD 未测；embedding 影响面大 |

Surface 段只动 lm_head 不动层：该段有效带宽 12.4 GB/s、4 核 Intel，是全流程最慢段；
段内 lm_head 占 **42.3%**（795.7/1881.0），4 层部分仅占 28.7%（539.7 MiB），
降至 Q4_K 的上限约 25 MiB。同等工程量下，动 lm_head 的收益是动层的 5 倍。

### 4.4 D 与 L 的精度阶梯，含 NInfer 变体

上游引擎（D）与下游引擎（L）的实际精度由本机读取制品头得出：

| 段 | 引擎 | 实测精度 | 依据 |
|---|---|---|---|
| `[0,8)` | pytorch（D） | **BF16** | `models/qwen3-5-9b/model-0000{1,2}-of-00004.safetensors` 头部 67 个张量全为 `BF16`，无 FP16/FP32 混入 |
| `[8,24)` | llama（L） | **Q4_K_M** | `q35-9b-local-mid8-24.gguf` 共 215 张量：115 个 `Q4_K`、11 个 `Q6_K`、89 个 `F32`（后者为各层 norm 与 `ssm_*` 小张量） |
| `[24,28)` | llama（L） | Q4_K_M | 同一模板产物 |
| `[28,32)` | llama（L） | Q4_K_M | 同上，`output.weight` 为 `Q6_K` |

即当前阶梯为 **BF16 → Q4_K**。按字节/参数计，BF16 为 2.0 B/参数、Q4_K 约 0.55 B/参数，
两者相差 **3.6 倍**，已满足"上游精度高于下游"。

**NInfer 上游变体**：`NInfer原生 BF16`（见
[NInfer与llama混合层段及异步页流水补充调研](NInfer与llama混合层段及异步页流水补充调研-2026-10-25.md)
的 `execution::TextContext::run_layers` 与边界 f32 转换）。NInfer 侧另有
`q4_g64_fp16` 的量化布局，但该格式用于**下游**或独立对比实验；上游保持 BF16 时，
引擎从 pytorch 切到 NInfer **不改变梯度方向**，配方无需重做。

**编排约束**：上游保持 BF16、下游最高到 Q4_K，这条阶梯适用于 D 与 NInfer 两种上游。
把上游降到 4-bit（`q4_g64_fp16` 或任何 Q4 级布局）会使阶梯反转 —— 上游误差要多走
24–32 层放大（§3.2），收益为负。

**D/L 混合编排下的量化动作清单**：

| 动作 | 段 | 是否随上游换 NInfer 而变 |
|---|---|---|
| 上游保持 BF16 | `[0,8)` | 否 |
| 中段保持 Q4_K_M（保 repack 99.9%） | `[8,24)` | 否 |
| 末段层保持 Q4_K_M，L28–30 可降 Q4_K | `[28,32)` | 否 |
| `output.weight` Q6_K→Q5_K | `[28,32)` | 否 |

### 4.3 工具链的可得性

- `llama-imatrix` 自算 imatrix（GPU 约 30 分钟）
- `llama-quantize --tensor-type / --tensor-type-file / --output-tensor-type /
  --token-embedding-type` 任意分层配方（§4.2 全部条目）
- `llama-perplexity --kl-divergence` 全套验证

**依赖外部工件**：

  v2.0 代际）
- `Qwen3.5-9B` 逐层敏感度表 / 分层推荐：未找到公开数据

## 5. 单点优先项

**把 `output.weight` 从 Q6_K 降到 Q5_K。**

```bash
# 从 BF16 一次量化（推荐；无 BF16 时退化到 --allow-requantize）
llama-quantize --imatrix imatrix_qlh.gguf \
  --output-tensor-type q5_k --token-embedding-type q4_k \
  qwen35-9b-bf16.gguf qwen35-9b-qlh-v1.gguf Q4_K_M 16
```

预期效果：

- Surface 段 `[28,32)+output+token_embd`：**1881.0 → 1752.2 MiB（−128.8 MiB，−6.8%）**；
  整模 5357.9 → **5229.1 MiB**
  - 口径：1881.0 与 5357.9 为 `llama-quantize --dry-run` 对 Q4_K_M 模板的重算值；
    原始发布文件对应 1873.6 / 5417.4 MiB，7.4 MiB 差异来自重算时
    `ssm_alpha/beta` 的 Q8_0→Q4_K 变化。两种口径下 −128.8 MiB 相同。
- 若 Surface 是端到端瓶颈段（12.4 GB/s 读 1881.0 MiB ≈ 159 ms/token），
  每 token 省约 **11 ms**
- 精度：KLD 3.3e-5 → 1.48e-3，逐 token argmax 一致率 99.6 % → 97.7 %

验证流程（约 5 分钟）：

1. 产出 `out_q5k` 与 `ctl_requant` 两个对照件
2. 用现状 Q6_K 版产 KLD 基线：
   `llama-perplexity -m 现状.gguf -f wiki.test.raw -c 512 --chunks 16 --kl-divergence-base base.kld`
   （本机约 29 s，产物 2.03 GB）
3. 比对：`llama-perplexity -m 新件.gguf -f wiki.test.raw -c 512 --chunks 16 --kl-divergence-base base.kld --kl-divergence`
4. 放行门：`Same top p ≥ 97.0 %` 且 `Mean KLD ≤ 2.0e-3` 且 `RMS Δp ≤ 1.5 %`

选择这一项的理由：单点、可先于 imatrix 执行、不改引擎、不重裁层、不引入 IQ 张量、
不破 repack、不影响其他段、可回滚（换回 Q6_K 原文件即可）。

## 6. 质量验证

### 6.1 三个指标的分辨力（本机实测）

**PPL 不适合作为诊断指标**：同一批 24 chunks 下，`output.weight` 从 Q6_K 变到 Q8_0，
PPL 依次为 7.4121 / 7.4113 / 7.4126 / 7.4363，±0.24 的噪声覆盖全部差异。分辨
lm_head 级别的变化需要 10 倍以上语料。

**KLD 是主判据**：同一批件 KLD 为 3.3e-5 / 1.48e-3 / 5.70e-3，信噪比充分
（±0.00008 误差 vs 三个数量级跨度）。Unsloth 的立场与此一致：输出 token 值正负抵消使
PPL 失真，应采用 KLD 或更硬的 benchmark。

**`Same top p`（逐 token argmax 一致率）是最直观的单指标**：99.6 % / 97.7 % / 95.5 %。

### 6.2 最小验证集（本机已跑通）

1. **语料**：wikitext-2 `wiki.test.raw`（1,290,590 B），源
   `https://huggingface.co/datasets/ggml-org/ci/resolve/main/wikitext-2-raw-v1.zip`
   （`scripts/get-wikitext-2.sh` 的官方源）
2. **KLD 基线**：`llama-perplexity -m <当前生产件> -f wiki.test.raw -c 512 --chunks 16
   --kl-divergence-base base.kld --kl-divergence=0`。产物约 **2.03 GB**，落 G 盘，
   不落 C 盘临时目录
3. **逐候选比对**：加 `--kl-divergence`。单件 CPU 8 线程约 **30 s**，
   10 个候选约 **5 分钟**
4. **放行门**：
   - `Same top p ≥ 95 %`（对应 KLD ≲ 6e-3，即"整模 q6_K 级"）
   - `Mean KLD ≤ 5e-3`、`RMS Δp ≤ 2 %`
   - 中段降档类改动放宽到 `Same top p ≥ 90 %`，单独记录
5. **任务级兜底**（覆盖长程行为）：取 Unsloth 的 Divergence-300 思路，从 `chat_history/`
   抽 300 条真实 prompt，greedy 解码 32 token，比对 BF16 版与量化版的逐 token argmax
   轨迹一致率。不通过说明 KLD 门漏掉长程退化。本仓现有的"2 plus 2"端到端冒烟对量化
   误差不敏感，不作为门。
6. `rel_err` / `cos` 门的分辨力不足：本仓已记录 GGUF Q4_K_M vs HF fp32 的
   `rel_err≈7e-02` 属于正常量级，无法分辨 Q4→Q5 这一级变化。

### 6.3 Q2_K 在 qwen35 上的失败

`Q2_K` 模板实测：PPL 9.03 → **93.4（24 chunks）/ 132.4（16 chunks）**，
`Same top p` **31.74 %**，KLD **2.7199**。llama.cpp 官方 LLaMA-3-8B 的 q2_K KLD 为
0.4451 —— 本模型差 6 倍。归因（`[推测]`，未做单变量验证）：模板把
`ssm_alpha`/`ssm_beta` 一并压到 Q2_K，而 UD 将二者保在 F16/Q8_0。

**对配方的含义**：qwen35 上任何按 `Qn_K_M` 模板降档的动作都必须先过 §6.2 的放行门，
不能依据其他模型的 q2_K 表现外推。验证方法：只对 `ssm_alpha`/`ssm_beta` 强制 Q8_0、
其余走 Q2_K，观察 KLD 是否回到 0.5 以内。

---

## 7. 结论与执行顺序

UD 整体替换的净效果是段体积增大（`[0,8)` +5.1%、`[8,24)` +7.1%），且其动态分配方向
（后段 bpw 最高）与"上游精度高于下游"的约束相反。按性价比排序：

1. **lm_head Q6_K→Q5_K** —— 段体积 −6.8%，KLD 仍属整模 q8_0 级
2. **中段维持 Q4_K_M** —— 保住 repack 99.9% 覆盖，这是本仓唯一已兑现的 CPU 收益
3. **自算 imatrix + `--tensor-type-file` 实施分层配方** —— 并为 L31 留余量
   （其敏感度是 L24 的 2.6 倍）
