## 3. 本轮攻坚的问题链（12 层，逐层实测确证）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | ROG 不入群 | `build/perf/rog-start-worker.ps1` 里硬编码的 `QLH_CLUSTER_SECRET` 是**过期值**（票 9 后长期凭据以 `LocalSecretStore` 为唯一事实源，实际值为带 `6*4` 前缀的新值） | 用 store 的实际值启动 |
| 2 | ROG 连上即断：`invalid packet length: 1213486160` | `1213486160` = ASCII `"HTTP"` ⇒ **HTTP API 与 TCP 控制面抢同一端口**（master 误把 `QLH_API_PORT` 也设成 8888） | HTTP 8000 / TCP 8888 分离 |
| 3 | Y700 每 30s 重试被拒：HMAC 签名不匹配 | 设备侧持有的是**更早**的集群密钥 | 走 `POST /api/bootstrap/first-connect` 公钥交换重新入群（**不需清数据**） |
| 4 | Y700 `modelId=` 空、`ranges=[]` | master 报的 `model_sha256` 是 **HF 目录聚合 sha**，工件 manifest 声明的是 **GGUF 文件 sha** ⇒ `source_digest_mismatch` | master 改走 **GGUF 引擎**，两侧口径同源（`a86078042c3e…`） |
| 5 | master 无身份 ⇒ Route A 死锁 | `/api/models/current` 在**整模加载态**（`loaded:true`）**不返回 `descriptor`**，只有 `pipeline_prepared` 态才返回；而 Android 需要 `descriptor.model_sha256` 才扫描/广告工件 ⇒ 死锁 | **改代码**：整模态补**完整公开描述符**投影（`src/api/routes_models.py`） |
| 6 | 预检 `model_preflight_descriptor_incomplete` | `descriptor` 与工件 manifest 都缺 `hidden_size` / `tokenizer_sha256` / `source_model_id` | 三处 manifest 补齐（`tokenizer_sha256 = sha256(tokenizer.json)`） |
| 7 | Android 仍 `ranges=[]` | `MainViewModel` 用**顶层 `model_id`**（注册表 id）过滤工件的 `sourceModelId`，与工件的 `source_model_id` 不一致 ⇒ 被过滤 | 注册 id 与工件 `source_model_id` 对齐（`qwen35-2b-Q4_K_M`） |
| 8 | `pipeline_local_commit_failed: GGUF 整模恢复不接受 layer_range` | Route A 的本地 commit 会带上本机段区间，而 llama.cpp 的段由**裁层工件**表达（`layer_range_mode=precut_artifact`） | **改代码**：与 `QLH_LAYER_GGUF` 声明区间一致时接受（`src/llama_engine.py`） |
| 9 | keep-head worker 立刻退出：`GGML_ASSERT(n_tokens_all <= cparams.n_batch) failed` | 默认 `n_batch=512`，而 qwen3.5（M-RoPE）embd 批次按 **4×n_tokens** 读 pos ⇒ 越界（上游 #28963 家族） | **改代码**：`n_batch` 默认提到 2048（`QLH_KEEP_HEAD_N_BATCH` 可调） |
| 10 | 回程 `stage_result` 报 `message exceeds maximum size` | 协议只实现了 **master→worker** 的分片（`hidden_ref`）；worker→master 的 `hidden_out_f32` **无分片**，而分片引入后预检放宽 ⇒ 长 prefill 顶到 8MB 帧限（"输入输出同尺寸"的旧假设被打破） | 用独立 `session_id` 降低 prefill 长度规避；**回程分片仍是缺口**（见 §5） |
| 11 | Y700 收到 offer 后**静默重连**、设备侧零日志 | `handleOffer` 位于 `receiveEvent()` 之后，而**帧读取/解码失败路径不留痕** | **改代码**：`TaskWorkerClient` 在帧尺寸/body 读取/`TaskWorkerProtocol.decode`/`handleOffer` 入口/传输异常五处补诊断 |
| 12 | 同上，真正原因 | Android 的 `stage_offer` 字段白名单**漏了主仓 v3 新增的 `request_deadline_ms`**，而 `requireExact` 是**双向精确**匹配 ⇒ `payload fields do not match schema` | **改代码**：`TaskWorkerProtocol.kt` 白名单补 `request_deadline_ms` |

## 5. 遗留与未覆盖（不得外推为已完成）

- **回程（worker→master）隐藏态无分片**：长 prefill（实测 `tokens=1004`）时
  `stage_result` 超 8MB 帧限。当前只能靠控制 prefill 长度规避；协议侧需补齐回程分片。
- **`/api/models/current` 的 `model_id` 语义**：顶层是**注册表 id**，`descriptor.model_id` 是模型名。
  Android 用顶层 id 过滤工件 ⇒ 两者必须一致。本轮靠"注册 id 与工件 `source_model_id` 同名"绕过，
  契约本身仍欠明确（建议单独立项）。
- **`rog-start-worker.ps1` 已过时**：密钥过期 + 走 `inference_svc_main.py`（PyTorch peer）⇒
  **不进** Route A 的 `eligible_node_ids`（`peers` 不是 v3 task worker）。PC 侧应改用
  `build/keephead/start_worker.bat` 那套（`api_server.py` + `QLH_LAYER_GGUF` + shim）。
- **`_task_worker_capabilities` 的能力判据过窄**：用 `importlib.util.find_spec("llama_cpp")` 判断
  llama.cpp 能力，而 **shim（`QLH_KEEP_HEAD_SHIM`）执行路径不需要该 pip 包** ⇒ ROG 明明能用 shim
  却被判"未声明 engine"。本轮从本机拷贝 `llama_cpp` 0.3.35 到 ROG 绕过；判据应同时认 shim。
- **`PIPELINE_TIMEOUT=120s` 是硬编码**（`src/config.py:514`），无 env 旋钮。长思考请求
  （`show_thinking=True` + 大 `max_new_tokens`）会 `request_deadline_exceeded`（实测跑到 535 步）。
- **未验收**：Surface 不参与（离线）；不涉及 A1 relay 段；未做多轮长上下文压力；
  未验 `fallback=false` 在弱网/单节点掉线时的行为。

## 7. 与 2026-10-07 那轮的关系

2026-10-07 的三机是 `master + Surface + Y700`，Surface 是**PC layer worker**（`start_worker.bat`）。
本轮把 Surface 换成 ROG，**产物形态完全一致**（`route_a_stage_offer_v3` /
`master_pipeline_route_a` / `fallback=false` / `workers_used` 含两个 client 段），
但暴露了 §3 的 12 层问题 —— 其中第 5/8/9/12 层是**代码缺陷**，其余是部署配置或契约滞后。
