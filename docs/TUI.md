# TUI 设计

> 状态：设计定稿，未实现
> 更新日期：2026-10-29

## 1. 要解决的问题

旧版是一个 189 行的纯 ANSI 界面（已随重写删除），能看但不堪用：

| 问题 | 表现 |
| --- | --- |
| 布局浪费 | 生成区只占顶部一行，其余全黑 |
| 状态行会顶掉顶栏 | 没有分区，文字一多就滚 |
| 无法交互 | 只能 `--prompt` 传参，退出即丢历史 |
| 分段条形错位 | 按固定 50 ms 归一化，大值被截断，两段宽度不一致 |
| 吞吐数字是假的 | 分块灌入时 `first_token_at` 算错，出现过 6801.9 tok/s |

这些东西无论怎么美化都救不了，得重做布局。

## 2. 旧仓库的教训

前身仓库有一个 `tui_admin.py`，2889 行、7 个管理屏、纯标准库，还带一个 Textual
聊天页（未过发布门）。两千九百行去管后台状态，最后和它管理的系统一起被丢掉了。

新 TUI 的规模上限：**450 行**。超了说明在往管理后台的方向长，那不在本项目范围内。

## 3. 布局

四区，可调比例：

```
┌ slimarc ────────────────────────── 12.4 tok/s ── 3 段 ─┐
│ 对话区（可滚动）                                          │
│   我是一名大三学生，正在准备考研。                         │
│   在考研复习过程中，我遇到了一些难题…                      │
│                                                          │
├ 流水线（可滚动，段数不定）────────────────────────────────┤
│ 0 gpu   8L ████░░░░░░░░  6.0 ms  local                   │
│ 1 cpu  16L ████████████ 52.1 ms  local                   │
│ 2 ROG   8L ████████████ 121.7 ms 100.116.17.12           │
│                                                          │
├ 参数（可折叠）───────────────────────────────────────────┤
│ temp 0.7   top_p 0.9   top_k 40   seed 42                │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ > 输入…                                            Enter │
└──────────────────────────────────────────────────────────┘
```

### 为什么要分屏

后面要接调参面板、单段延迟直方图、KV 缓存占用等。**现在就把区域切开，以后往格里填，
而不是每加一个功能就重排一次布局。** 分屏的第一目的是可扩展，不是好看。

### 流水线区必须可滚动

段数现在是 2-4，将来可能更多（ROG 之外还有别的机器）。固定高度会在第五段时爆掉。
用滚动容器，高度按可用空间自适应。

## 4. 技术选型

**Textual**（Rich 同作者）。理由：

- 分屏、滚动、输入框、焦点管理都是现成控件，不用手写 ANSI 光标运算
- 支持 CSS 式的布局描述，加面板只加一段样式
- 动画（启动画面）有内置的过渡，不用自己插帧
- 单依赖约 15 MB

代价是多一个依赖。已经确认不要求零依赖。

## 5. 一行启动

```powershell
koakuma
```

命令名沿用前身仓库的引擎层命名（`Koakuma` = 统一引擎入口，上层不区分 llama.cpp /
torch）。放在 `koakuma.cmd`，同时给一个 `koakuma.ps1` 供 PowerShell 直接调。

命令要做的事，按顺序：

1. 找拓扑：`SA_TOPOLOGY` 环境变量 → 否则 `topology.toml` → 否则列出目录下的候选文件并提示用 `--topology` 指定
2. 找 shim：`SA_SHIM` → 否则 `shim/bin/qlh_keep_head.dll`
3. 跑内存预检，不够就明确说差多少、建议怎么改
4. 起 worker（本机段），连远端段
5. 进 TUI

**失败要说清楚。** 现在 `chain_client` 报错是 `refusing to start: ... Move a stage to
another host`，这句话对使用者没有帮助。TUI 启动阶段要把"哪一段、多少内存、差多少"直接
打在屏幕上。

## 6. 启动动画

前身仓库的动画"做得很一般"，原因大概率是：全屏擦除 + 逐行打印 ASCII art，一次性的，
和后面的加载过程没有关系。

这次的做法：**动画就是加载进度本身**。

```
   ▄▄▄  slimarc
  ▐███▌ 层段分布式推理
   ▀▀▀

  loading topology      ✓  4 stages
  shim                  ✓  H:\...\qlh_keep_head.dll
  memory precheck       ✓  expected 8.37 GiB / 14.12 GiB
  stage 0 gpu   8L      ████████████░░░░  62%   loading weights
  stage 1 cpu  16L      ░░░░░░░░░░░░░░░░
  stage 2 cpu   8L      ░░░░░░░░░░░░░░░░
  stage 3 ROG   8L      ✓  connected 100.116.17.12
```

要点：

- 每行对应一件真实工作，完成打勾，进行中显示进度
- 从 worker 日志里抓 `load_tensors: ... MiB` 的进度，或至少显示"已用时/预计"
- 全部完成才进 TUI，中途按 `q` 可中止并清理进程（不留孤儿）
- 不追求炫技。**能看出卡在哪一步**比好看重要

启动阶段的等待是真等（大模型加载几十秒），所以动画有实际用途，不是装饰。

### 进度数据是真的

worker 日志里有两类行，够算真实百分比：

```
llama_model_loader: loaded meta data with 54 key-value pairs and 294 tensors from ...
create_tensor: loading tensor blk.3.attn_q.weight
```

分母是 `N tensors`，分子是 `create_tensor` 已出现次数。实测 stage-1 有 294 行、
stage-0 有 214 行，与分母完全对上。所以进度条不是估的，是数出来的。

抓法：`spawn_worker` 已经把每个 worker 的 stdout 重定向到了
`build/relay-records/stage-{i}-{kind}.log`，启动画面轮询这些文件即可，不需要改
worker 协议。

## 7. 要修掉的数字 bug

| 位置 | 现状 | 应该 |
| --- | --- | --- |
| 吞吐 | 用 `first_token_at` 到现在的跨度，分块灌入时算错 | 用相邻 token 的时间差做滑动窗口 |
| 分段条形 | 按 50 ms 归一化，大值截断 | 按当前最大段归一化，或对数刻度 |
| 首 token | 没有 | 显示 TTFT，这是体验的关键指标 |
| 已用时间 | 常显 0.0s | 从第一次 token 开始计 |

## 8. 环境变量配置

需要一个面板显示并修改当前生效的配置，而不是让人去翻 `.env`（前身仓库有 94 个
`QLH_*` 变量，绝大多数没人知道干什么的）。

新 TUI 只认这几个，全部有默认值：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `SA_TOPOLOGY` | 拓扑文件 | `topology.toml` |
| `SA_SHIM` | shim 路径 | `shim/bin/qlh_keep_head.dll` |
| `SA_CTX` | 上下文长度 | 4096 |
| `SA_BACKEND_DIR` | ggml 后端目录 | shim 同级 |

**启动时把这些实际值打在启动画面上**，让人一眼看到用的是哪个拓扑、哪个 shim。
改配置在 TUI 里做（调参面板），不改环境变量。

## 9. 验收

1. `koakuma` 一条命令从零进 TUI，不报错
2. 启动画面每行都对应真实步骤，卡在哪看得出来
3. 分段条形宽度正比于实际耗时，段数 6 个以上时流水线区可滚
4. 吞吐数字与 `chain_client.py` 实测一致（同一拓扑、同一 prompt）
5. TTFT 单独显示
6. 中文零替换字符
7. `Ctrl+C` / `q` 退出后无残留 python 进程
8. 内存不够时给的是"差 X GB"而不是一句 Move a stage

## 10. 不做

- 不做管理后台。没有多屏切换，没有日志浏览，没有配置增删。
- 不做历史持久化。退出即丢，要留记录用 `> out.txt`。
- 不做主题系统。一套配色够了。
- 不在 TUI 里改环境变量。那是 shell 的事。
