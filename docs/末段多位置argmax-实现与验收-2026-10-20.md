# 末段多位置 argmax：实现与验收

> 状态：**部分实施**（生产合同与本机原生开发门通过；Android设备数值门开放）
> 更新日期：2026-10-20
> 适用范围：票21b-0 `COMM-MULTIPOS-01` 的请求／结果合同、PC及Android执行接线、固定输入数值验收与兼容边界。draft、接受／纠错、跨段KV恢复和生成收益归票21b。

## 1. 协商与结果合同

`src/qlh_core/contracts/token_output.py` 的 `validate_token_output_request`、`validate_token_output` 是PC的纯合同。`src/task_worker_protocol.py:_validate_capabilities` 接受可选布尔能力 `multi_position_argmax`；`SchedulerPipelineMixin._execute_layer_stage_offer(want_all_tokens=True)` 仅向声明值为 `true` 的对端发送 `token_output="all_positions"`，缺能力的对端沿标量路径执行。`RemoteFullWorkerProvider.reserve` 再核对能力；worker准入及执行器再核对实际执行支持。

混版本发布顺序为先升级master，再升级worker。上述标量回退覆盖新master接旧worker、未声明能力的worker及旧native ABI；新worker直接连接旧v3 master时，旧端精确字段表会拒绝HELLO中的新键，值为false也会拒绝。PC的 `QLH_MULTI_POSITION_ARGMAX=0` 可完全省略这个键，其余既有扩展仍按各自版本合同核验；Android当前使用实际JNI能力广告，无单独关闭该广告的运行时开关。`hello-compatibility.json` 保存冻结旧decoder的复现和摘要。

请求限定 `layer_forward`，显式 `root_input.want_hidden=false`、`positions` 与 `hidden_spec.n_tokens` 等长且连续递增，位置为非负int32。可选 `seq_ids` 必须等长并绑定同一序列。显式位置优先于 `root_input.pos_base`；未请求多位置时保留既有标量合同。

结果置于既有 `output` 对象，保持顶层envelope字段：

```json
{
  "token_argmax": 4,
  "token_argmax_by_position": [2, 3, 4],
  "positions": [41, 42, 43],
  "n_tokens": 3,
  "n_vocab": 8
}
```

字段组同时出现；每个token为int32且处于 `[0,n_vocab)`，标量等于列表末位。行数、位置长度及连续性受显式校验，多位置组与 `hidden_out_f32`／`hidden_out_ref` 互斥。协议先核对摘要，provider和pipeline接收端再绑定原offer的行数及positions，拒绝缺组、未请求的组和自洽但对应其他位置的结果。结构非法的多位置组由 `task_worker_protocol.InvalidTokenOutputResult` 携带拒绝回执：envelope、身份语法、摘要、metadata和消息大小均须先通过。scheduler沿注册节点和provider路由，provider再核对pending身份、接受状态、重放与既有终态，以 `invalid_token_output` 立即结束匹配请求并丢弃结果分片；取消后的迟到回执保留原终态。

## 2. 执行路径

- `scripts/model_tools/keep_head_shim/qlh_keep_head.c:qlh_kh_forward_embd_tokens` 新增带输出容量的可选C接口，容量以int32元素计。遍历所有位置的全部logits，拒绝NaN／Inf；全部成功后才写调用方输出。失败后的KV按现行请求清理合同处理。
- `src/llama_keep_head.py:KeepHeadUpstream.forward_hidden_to_tokens` 校验形状、int32、单序列、batch及ctx，返回 `list[int]`。`n_vocab`／`supports_multi_position_argmax` 来自实际native handle；隔离worker的初始化回执和 `hidden_tokens` IPC贯通该能力。`keep_head_multi_position_available` 在短寿命子进程探测ABI、有限logits守卫，不加载模型；旧shim缺导出时返回false。探针按路径、mtime、大小和环境缓存，超时15秒。
- `EngineHost._execute_layer_forward_stage_locked` 适配GGUF新入口；safetensors路径的 `_execute_supplied_layer_forward` 对全部行执行lm_head、有限性检查和逐位置argmax。`SchedulerCallbackSet.supports_layer_multi_position_argmax` 将能力查询显式接到真正层段owner。PC设置 `QLH_MULTI_POSITION_ARGMAX=0` 可省略新能力广告，重连／刷新后使用标量。
- `RemoteFullWorkerProvider.handle_message` 在接受结果前核对请求绑定；无效结果终结对应attempt并保留物理结果已收到的事实。`NativePorts.stage`保留经过校验的多位置组及其摘要；`LinearExecutor.run` 经 `tail_token`选择最后一行，常规greedy保持标量计算成本，内部`_all_position_argmax=True`可单独验证取末位兼容。显式投机执行与状态恢复的现行来源见[21b实现与验收](投机批验证-实现与验收-2026-10-20.md)。
- Android `nativeLayerForwardTokens`、`LocalInferenceEngine.layerForward`、`TaskWorkerService` 与 `AndroidFullWorkerStageExecutor` 贯通相同字段；`MultiPositionArgmaxContract` 同时服务协议和直接执行入口。`AndroidWorkerCapabilities` 依赖实际JNI查询，旧 `.so` 缺符号或查询失败时省略能力。
