# 测试策略

> 状态：**规则**
> 更新日期：2026-10-28
>
> 起因：旧仓库 `src/` 129,337 行，测试面同样庞大，但用户判断「CI 脆性极高，测试一大坨但没什么用」。
> 新原型不能重复这个错误。

---

## 1. 旧仓库测试为什么失败

不是"测试写少了"，而是**测的东西不对**。三种典型失效：

| 失效类型 | 表现 | 为什么没价值 |
| --- | --- | --- |
| **测实现细节** | 断言内部函数调用次数、私有字段值、日志文案 | 重构就红，但重构不改变行为 |
| **测环境** | 依赖时序、并发调度、文件系统顺序 | 随机红，重跑就绿，最后被忽略 |
| **测已被验证的东西** | 同一个不变量写了 5 个测试 | 增加维护面，不增加信心 |

它们的共同点：**红了之后第一反应是"这测试有问题"，而不是"代码有问题"**。到这一步测试就死了。

## 2. 新原型的规则

### 2.1 只测四类

| 类别 | 测什么 | 例 |
| --- | --- | --- |
| **不变量** | 违反后系统会产出错误结果 | 切点是 4 的倍数、层段恰好覆盖 0–40、hidden 维度匹配 |
| **协议边界** | 字节级编解码往返 | 6 种消息 encode→decode 相等、半包/粘包正确切分 |
| **数值正确性** | 与参考实现逐位比对 | 首段 hidden vs 整模对应层输入 |
| **错误路径** | 坏输入给出可读报错 | 不存在的文件、层数不匹配、端口占用 |

### 2.2 明确不测

- 私有函数、内部实现路径
- 日志文案（除非文案本身是用户可见的诊断信息）
- 时间、并发顺序、调度优先级
- 第三方行为（llama.cpp 自己怎么加载）
- "能不能跑起来"（那是集成测试的事，不进 CI）

### 2.3 数量纪律

**每个模块的测试行数 ≤ 该模块行数 × 2。** 超了就说明在测实现细节。

当前状态：

| 模块 | 行数 | 测试行数 | 比值 |
| --- | ---: | ---: | ---: |
| `topology.py` | 170 | 286 | 1.7 ✅ |
| `protocol.py` | 66 | 待写 | — |
| 其他 | — | 只做集成验证，不写单测 | — |

### 2.4 集成验证不进 CI

层段推理的正确性**只能端到端验证**：切工件 → 三段加载 → 跑 token → 与整模比对。

这条链要 20 GB 模型、8 GB 显存、30 秒启动。**它不该进 CI。** 做法：

- CI 只跑单元测试（纯函数、协议编解码）
- 端到端验证作为**手动任务**，一条命令，输出一段可粘贴的结论
- 端到端失败时，报错必须能直接定位到"哪一段、哪个工件、哪一层"

`scripts/check_correct.py` 就是这样的手动任务：它输出 `max abs diff` / `cosine`，没有人需要
读它的源码就知道是否通过。

## 3. 一个具体的对比

旧仓库常见写法（**不采用**）：

```python
def test_scheduler_assigns_layers_to_workers():
    sched = Scheduler(config)
    plan = sched.plan()
    assert sched._retry_count == 0          # 私有状态
    assert plan.stages[0].worker_id == "w0"  # 实现细节
    assert len(sched._history) == 1          # 内部记录
```

新原型写法（**采用**）：

```python
def test_gap_in_coverage_is_rejected():
    # 漏层会比多切更隐蔽：链路照常跑完，只是算错了层
    path = self._write(self._three({1: dict(layers=8), 2: dict(layers=8)}))
    with self.assertRaises(TopologyError) as ctx:
        topology.load(path)
    self.assertIn("must cover every layer exactly", str(ctx.exception))
```

差别：后者断言的是**一个会让用户拿到错误答案的失效模式**，且错误信息本身是给用户看的。

## 4. Rust 版

同样的规则，用 `#[test]` 与集成测试目录：

- `src/` 内的 `#[cfg(test)]`：纯函数与协议编解码
- `tests/`：**不写**需要模型的测试
- 端到端靠 `slimarc check` 子命令，手动跑

不引入 `mockall`、`fake`、`proptest` 等测试框架——它们会增加依赖面，
而当前要测的东西用 `assert_eq!` 就够。
