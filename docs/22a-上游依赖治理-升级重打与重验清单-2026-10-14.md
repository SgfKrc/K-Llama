## 3. 重打流程（升级上游时执行）

前置：**`GGML_NATIVE=OFF` 是刻意选择**（见 §4），重打时不要顺手改掉。

```
1. 记录当前基线
   - vendor 子模块的当前 revision（detached HEAD 的补丁 commit）
   - `scripts/model_tools/llama_quantize.lock.json` 里的 `upstream.revision`
2. 取新上游 revision → 在 submodule 内 checkout
3. 应用补丁：git apply --check 先干跑，再 apply
     - 冲突点预期集中在**逐架构 wiring**（各 `src/models/*.cpp` 的 graph 构造附近）
     - 上游若新增/改名架构 ⇒ 该架构要么补登记，要么**保持未登记**（行为见 §4 的 fail-closed）
4. 重新构建（命令见 §6）→ 产出新的 libllama + shim
5. 重跑 §4 的判据；任一不过 ⇒ 不升级（或回退到旧 revision）
6. 更新 `llama_quantize.lock.json` 的 revision 与 marker（沿用 `★ QLH <日期>` 约定）
```

## 4. 重验判据（**这是本票的核心，不可省**）

| # | 判据 | 依据 | 不过怎么办 |
|---|---|---|---|
| 1 | **逐 token argmax 一致**（对同精度整模） | 本仓既定纪律；历史上 Qwen3.5-9B 两段/三段 32/32 | **不升级** |
| 2 | **未登记架构必须 fail-closed** | `src/llama_keep_head.py` 的 `SHIM_SYMBOLS` + 逐架构登记；未登记架构 decode 时 `GGML_ASSERT`（**不会静默给错值**） | 补齐登记，或明确不支持的架构要报错到位 |
| 3 | **`GGML_NATIVE=OFF` 保持不变** | `docs/跨框架接力数值差异机理-2026-10-05.md:167`：同架构 + 同二进制 + `GGML_NATIVE=OFF` ⇒ **0/7168 差异**；x86_64↔ARM64 ⇒ **7168/7168 全不同**（归约按 ISA 宽度分 lane） | 若确需改 ISA ⇒ 走票 22d，并**额外**重跑本判据 |
| 4 | **段边界语义不变** | `src/llama_keep_head.py:1-36`：两种模式都取 `layer_inp` 的 `lid == n_layer` 槽位（段末层输出、`output_norm` **之前**） | 修到语义一致；不得改用 `output_norm(H)` |
| 5 | **下游注入仍走官方 API** | 下游用 `llama_batch.embd` 注入（L→L 16/16 行为等价已在 README 登记） | 保持 |

⚠️ **不要用"pip 绑定的 `llama_get_embeddings_ith`"当替代**：它返回 `output_norm(H)`
（`cos=0.999998`、`rel_err=0.0018`）⇒ **不能当接力上游**（`src/llama_keep_head.py:3-6` 已实测否决）。

## 6. 构建命令（**记录用；票 22d 才执行**）

来自 `scripts/model_tools/build_keep_head_shim.ps1:32-36`（上游建库提示）：

```
cmake -S android/app/src/main/cpp/llama.cpp -B <BuildDir> -G "MinGW Makefiles"
      -DCMAKE_BUILD_TYPE=Release -DBUILD_SHARED_LIBS=ON
      -DLLAMA_BUILD_TESTS=OFF -DLLAMA_BUILD_EXAMPLES=OFF
      -DLLAMA_BUILD_SERVER=OFF -DGGML_NATIVE=OFF -DLLAMA_CURL=OFF
cmake --build <BuildDir> --target llama -j 8
```

**shim 为什么必需**（同脚本 `:3-8` 的原文要点）：pip 绑定的 llama.cpp **只暴露 `embeddings` 通道**
（返回 `output_norm(H)`），不能当层接力上游；项目补丁导出了 layer-input / nextn API，
但 **`llama_context_params` 是 by-value 大结构体** ⇒ 必须用**与 DLL 同一份 `include/llama.h`** 编译 shim
⇒ 这就是 `qlh_keep_head.dll` 的存在理由，也是"**升级上游必须重编 shim**"的原因。

## 7. 一页纸执行摘要

- **性质**：上游内部已实现、只是未导出 ⇒ 补丁薄（暴露 + 逐架构 wiring），但**不能省**。
- **升级六步**：记基线 → 更新 submodule → `git apply`（先 `--check`）→ 重建 libllama+shim → **重跑 5 条判据** → 更新 lock。
- **硬红线**：`GGML_NATIVE=OFF` 不动；未登记架构必须 fail-closed；`output_norm(H)` 不能当段边界 hidden；任一 argmax 判据不过就不升级。
- **减负希望**：只有 `#27112`；现状 **open+stale、PR 已关** ⇒ **不可依赖**。
