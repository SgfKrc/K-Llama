## 2. 首启、首连与native配置

`AppRuntime.open_identity`幂等打开身份，生成secret后重建最终设置投影，使typed配置、旧设置中的secret和凭据epoch一致。旧安装资料迁移采用可重试的`identity_migration`标记；主文件写成功而旧副本擦除失败时，下一次显式启动继续清理。损坏加密凭据直接报告失败，保留原件。

[bootstrap.py](../src/bootstrap.py)`first_connect`验证加密信封后调用注入的`accept_bootstrap`。`RuntimeServices.bind_runtime`把首连和首选master地址持久化接至所属`AppRuntime`；成功后发布新配置revision并刷新scheduler／host，保留原`boot_id`。相同cluster的低epoch和同epoch不同secret被拒绝。`IdentityStore._persist_config`在公有配置写入失败时恢复原加密记录；[routes_cluster.py](../src/api/routes_cluster.py)`rotate_cluster_secret`通过同一runtime入口轮换，并保留先轮换后断开peer的既有边界。

`SettingsStore.load_listener`只解析公开监听输入，供[qlh.py](../qlh.py)`_shell_options`在探活前使用。已有健康后端时无需读取或解密本地凭据。CLI端口／监听地址优先；TUI默认loopback，远端目标保持只连接；`BackendSupervisor`使用同一环境快照设置bind，启动前把实际端口写入runtime。`api_server.run_api_servers`也从快照读取`.env`中的`QLH_BACKEND_HOST/PORT`。

[model_host.py](../src/model_host.py)`configure_runtime_environment`、[engine_host.py](../src/inference_service/engine_host.py)`EngineHost`和[llama_engine.py](../src/llama_engine.py)的层段路径／shim选择传递实例环境。[llama_keep_head.py](../src/llama_keep_head.py)`KeepHeadUpstream`将快照交给native子进程，隔离日志路径，并在创建子进程后关闭父侧stderr文件句柄。`environment=None`保留旧调用方兼容语义；新实例传入空字典也保持空快照语义。

## 3. 控制权、续期与恢复许可

[authority.py合同](../src/qlh_core/contracts/authority.py)`AuthorityIdentity`固定cluster、voter-set epoch、leader、term和lease；`AuthorityProof`另持证书digest、expiry及committed floor。同identity合法续期更新proof，[worker_prepare.py](../src/worker_prepare.py)绑定稳定identity并通过最新proof验权，保留已准备assignment。

恢复顺序为：规范化输入 → 验签／验时效／验term／验floor → 关闭旧写准入 → 发放`RecoveryPermit` → 受保护恢复 → 重验并发布。恢复只使用规范化后的证书副本。恢复失败、取消、撤销或过期后保持恢复义务；无recovery重新安装同proof、续期proof或更高term均无法绕过。受保护恢复成功后才解除该义务。

`RecoveryPermit.mutate`在owner短锁内核对revision与时效，取消立即使旧许可失效；旧恢复callback未退出前拒绝新接管。[journal_replication.py](../src/journal_replication.py)`truncate_to/apply_checkpoint`在`BEGIN IMMEDIATE`后和`COMMIT`前重查许可，过期或取消触发事务rollback。checkpoint网络获取在mutation guard外执行；迟到结果进入持久化前再次验权。

[clock.py](../src/qlh_core/control/clock.py)`operation_clock`保持跨IO推进；显式测试时间仍计入操作耗时。`AutoRoleRuntime.handle_rpc`对reserve／prepare／sign／commit使用接收端本地时钟，忽略请求中的`now_ms`。请求方提供未来时间无法越过未过期租约，提供过去时间也无法复活过期proof。

[cluster_quorum.py](../src/cluster_quorum.py)`SQLiteVoterLedger`将已签名accepted floor与vote原子保存，另标certificate committed floor；缺失、倒退和同位置不同digest均被拒绝。已签名但尚未commit的durable vote也维持租约排他，重开ledger后仍生效。旧ledger进入`needs_import`只读状态；`import_recovery_manifest`要求核验签名、精确覆盖durable vote和保留floor，一次性导入后拒绝再次覆盖。未知或不完整旧证据保持只读；wire schema继续为1。

## 4. 关闭与入口替代职责

`AppRuntime`对共享app的两个lifespan计数，最后一个使用者退出时等待启动收尾。停止后迟到的初始化结果无法发布ready。关闭等待超时或资源失败保留owner和`cleanup_failed`状态，允许重试。自有host负责unload，借用host由调用方管理。`AutoRoleRuntime.close`等续租线程退出后再关闭replica；线程未退出时保留引用。默认API只关闭自身标记的logging handler，保留宿主capture和原root级别。

| 现有入口／职责 | R1接点与后续切换条件 |
| --- | --- |
| 源码CLI／TUI | `qlh._run_textual_shell` → `BackendSupervisor` → `AppRuntime`；复用后端与自建后端归属分别验证，Textual退出链整体迁移按R5 |
| 主API | `_run_runtime_startup`显式打开身份、初始化日志／authority／本地库／scheduler；`/api/health`可响应和`/api/ready`就绪分别报告 |
| 冻结程序首启与参数分派 | [launcher.py](../packaging/packaging/launcher.py)`main`保留现有分派；替代owner为bootstrap。R5切换前须把role／path默认注入接入`SettingsStore`，使首启与源码入口消费同一配置 |
| native与离线helper | `KeepHeadUpstream`保留当前冻结worker CLI协议。`launcher._run_keephead_worker`及早期离线helper须在R5切换前先于业务import、日志重定向和UI分派；验证windowed标准流、纯stdout、stderr及exit code |
| 安装、验签、更新和保数据修复 | [qlh_launcher.py](../packaging/packaging/qlh_launcher.py)`LauncherController`的维护职责迁入轻量维护CLI，verify／diagnose与install／repair分开；R5再裁撤独立壳 |

packaging、Android及其他客户端子模块保持原revision。R1确定替代责任及兼容合同；冻结构建切换与真实发行包执行属于R5／R6。
