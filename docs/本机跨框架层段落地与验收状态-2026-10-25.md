## 1. 已实现（有代码 + 有证据）

### 1.1 三个身份分离

| 身份 | 语义 | 缺省值 = 今天的行为 |
| --- | --- | --- |
| `node_id` | 物理节点 + 传输身份（TCP 键、incarnation 归属、故障归属） | 不变 |
| `executor_id` | 节点内执行器（`""` = 主执行器） | `""` |
| `capacity_domain_id` | 共享同一份内存总账的域 | `= node_id`（每节点独立） |

**缺省值让既有三机拓扑逐字节不变** —— 这是所有改动的回归门。

### 1.2 各层落点

- **契约层**：`Segment.executor_id` / `PipelineNode.executor_id`，唯一性判据放宽到
  `(node_id, executor_id)`。新字段一律**加末尾带默认值**（`Segment` 已有 9 个位置参数，
  插中间会静默错位）。
- **容量层**：`capacity_domains()` + `validate_capacity_domains()`，超额 `fail closed`。
- **执行层**：本机执行器复用 `LocalFullModelProvider` 容器，执行体是
  `EngineHost.execute_task_worker_stage`（签名与 `ProviderExecutor` 协议逐字匹配，
  自带 `_worker_layer_lock()`）。**懒建**：构造 provider 不构造 `EngineHost`。
- **producer 链**：`QLH_LOCAL_CPU_EXECUTOR=1` 开启后，`_get_pipeline_capacity_nodes`
  产出一条同 `node_id`、不同 `executor_id` 的记录；`assignment` 透传身份；
  部署与两个控制面白名单登记 `local_executors`。

### 1.3 离线可证的形态

`scripts/probe_local_executor_placement.py`（**不需要集群**）复刻四执行器与真实约束后：

```
usable（head → middle → tail）:
  master       mode=head
  master/cpu   mode=middle
  android      mode=tail
  rog          mode=tail

admitted=True
  master       [0,8)      ← GPU 段（PyTorch）
  master/cpu   [8,24)     ← 同机 CPU 段（llama.cpp keep-head），16 层
  android      [24,25)
  rog          [25,32)
```

**这就是目标形态**：CPU 段权重常驻主机内存、CPU 就地计算、零 PCIe 搬运。

## 3. 根因链（这一票真正花了时间的地方）

**所有故障几乎都是同一个模式**：某个位置把 `node_id` 当作唯一身份，或把"一次性副作用"
当作"稳定的声明值"。共清掉 6 处：

| # | 位置 | 症状 |
| --- | --- | --- |
| 1 | `capacity._normalize_nodes` 唯一性判据 | `node_id must be non-empty and unique` |
| 2 | `ExecutionPlan` / `validate_pipeline_nodes` | 同机两段撞 `execution_requires_two_nodes` |
| 3 | `SupplyCapacityEvidence.project()` 的 `by_id` | 主段被 CPU 段覆盖 ⇒ 主记录消失、CPU 段拿到主段切点 |
| 4 | `model_supply` 的 `capacity_by_id` | 供给 plan 里 master 被标成 `executor_id='cpu'` |
| 5 | `capacity_domains()` 用 `capacity_bytes` | **VRAM 与 RAM 被合并记账** ⇒ 假超额 |
| 6 | `_normalize_nodes` 的排序 | CPU 段（middle）排在 head 前 ⇒ DFS 单向不回头 ⇒ **结构性跳过** |

其中 **#5** 与 **#6** 最不直观：

- **#5**：`capacity_bytes` 对 CUDA 节点是 **VRAM**（`capacity_source="gpu.vram_free_gb"`），
  对 CPU 执行器是 **RAM**。直接相加会把两种独立资源混成一份总账。共享**内存**域必须按
  `host_capacity_bytes` / `domain_allocatable_bytes` 记账。
- **#6**：排序决定 DFS **遍历次序**，而 DFS 是**单向**的（`cursor` 只前进、不回头）
  ⇒ 段类型必须与层顺序一致。次序为 `head(0) → 未声明(0.5) → middle(1) → tail(2)`。
  **"未声明"要早排而不是晚排** —— 它最灵活，早安排不会被挤掉；晚排会被有约束的
  `tail` 占满位置 ⇒ 无解（这是第一版假设的错误，被
  `test_per_artifact_modes_select_the_matching_range_and_identity` 直接打掉）。

**分摊必须幂等**：不能在 `host_capacity_bytes` 上原地做减法（
`_get_pipeline_capacity_nodes` 会被多次调用、每次重建 records，扣除只对那一次生效），
也不能扣那个字段（它承载 `safetensors_layer_offload` 的 host 预算）。正确做法是
**从声明值重新推导**（`domain_allocatable_bytes`）。

QLH_LOCAL_CPU_EXECUTOR_HOST_FRACTION=0.7
QLH_LAYER_GGUF=models/q35-9b-local-artifacts/q35-9b-local-mid8-24.gguf

**工件**：`q35-9b-local-mid8-24.gguf`（`[8,24)`，3.23 GB，`blk.8..blk.23`，215 张量），
由 `scripts/cut_layers.py --k 8 --end 24` 从整模裁出；`head4` / `mid4-24` / `tail24-32`
为既有工件。
