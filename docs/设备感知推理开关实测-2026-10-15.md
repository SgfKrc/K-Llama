## 1. 目的与判据

回答一个问题：`flash_attn` 与 KV 量化（`-ctk/-ctv`）**在什么情况下该开**。

判据是 decode 吞吐（`tg128`）与 prefill 吞吐（`pp512`），各测 3 次取均值，相对基线
（`-fa off` + `f16` KV）给出倍率。只看吞吐，不掺入显存——显存收益单列在判读里。

## 4. 判读

1. **`flash_attn` 没有单一结论，取决于路径与规模。** CPU 上 dense 2B **变慢**
   （0.927×，pp 也降 125.1→115.5），同机 dense 9B 与 MoE 35B-A3B 却**变快**
   （1.053× / 1.041×）；CUDA 三条路径一致略赚（tg 1.009–1.020×，pp +8.3–11.6%）。
   ⇒ 「有开关」不等于「该开」，也不能只按「CPU 还是 GPU」分类。
2. **KV 量化几乎不带来吞吐收益。** 8 个有效组合里 tg 落在 0.935–1.049×，最低是
   CUDA dense 2B 的 0.935×；CPU dense 2B 的 prefill 明显变差（q8_0：115.7→95.7，
   即 0.83×）。它的价值是**按字节省显存**，不是提速——与既有结论（CPU 边缘段净亏）一致。
3. **硬约束：量化 KV 必须配 `flash_attn`。** `-fa off` 与 `-ctk q8_0/q4_0` 同时使用时，
   CPU 与 CUDA 两边都直接 `failed to create context with model`（6 条路径全部复现）。
   这是**能不能加载**的问题，不是快慢问题。
4. CUDA 上的 MoE 用 `-ncmoe 999`（experts 留 CPU）跑出 19.6 tok/s，与既有
   `--cpu-moe` 结论一致（35B-A3B 的正确 offload 姿势）。

## 5. 对推理开关映射的影响

- `src/inference_switches.py` 的 `EVIDENCE["kv_cache_type"]` / `EVIDENCE["flash_attn"]`
  已按本表改写（带机器与模型口径）。
- 新增**依赖约束**：量化 KV 会联动打开 `flash_attn`
  （`overrides["flash_attn"] = "on(kv-cache-required)"`）；显式给出
  `QLH_INFER_KV_CACHE=q8_0` + `QLH_INFER_FLASH_ATTN=0` 这种不可能组合时 **fail-fast**。
- 这些数据绑定表中机器、模型、构建与工作负载。当前自动策略及实际参数接线以[票20实现与验收](设备感知推理开关-实现与验收-2026-10-20.md)为准；采用开关需匹配当前本机标定。

## 6. 量化的两面：容量收益 vs 计算/带宽代价

同一批实验的另一半证据（`llama-server` 自报的 KV 分配，9B Q4_K_M，全程 `-fa on`，
KV 类型是唯一变量）：

| ctx | `f16` KV | `q8_0` | `q4_0` |
|---|---|---|---|
| 8192 | 256 MiB | 136 MiB（53%） | 72 MiB（28%） |
| 32768 | 1024 MiB | 544 MiB（53%） | 288 MiB（28%） |

- **容量侧**：q8_0 把 KV 字节压到 **53%**、q4_0 压到 **28%**，比例与 ctx 无关
  （纯 block 量化比：f16 = 2 B/元素，q8_0 = 34/32，q4_0 = 18/32）。
- **计算/带宽侧**：第 3 节同一批 A/B 里 tg 落在 0.935–1.049× —— 量化**没有**换成速度。
- 机理：decode 每步都要把量化块 dequant 回计算精度（额外算力），块状布局也让内存访问更碎；
  省下的字节带来的带宽收益不足以抵消。
- 附带一条结构事实：该 9B 是 **hybrid** 结构，**只有 8 层吃 KV**（日志 `8 layers`），所以
  KV 的绝对量本来就不大（32K + q4_0 也只省 736 MiB）。这与「边缘段优先承载线性层」的既有
  结论同向：能省 KV 的手段里，**减少吃 KV 的层数比压缩 KV 字节更划算**。

⇒ **把量化当容量旋钮用（装不下才上），不要当提速手段** —— 与「量化是容量旋钮」的既有裁决
一致，本轮补上了同口径的吞吐与字节两侧数据。

## 7. 未覆盖

- 更大的 dense（27B/32B）与其它家族（Gemma / Llama）；
- 其它 CPU（含 `AVX512`/`VNNI` 构建的 llama.cpp）与其它 GPU；
- 线程数扫描（既有 Surface 结论是 `n_threads=8` 最优，本轮用工具默认 10）；
- 长上下文：本表固定 `pp512`，KV 量化的**显存**收益随 ctx 增长才明显（既有结论 32K 下省 28%）。
