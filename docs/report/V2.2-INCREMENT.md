> 面向 v2.2 发布说明 · 基于两个版本 tag 的 patch 逐文件对比 · 产出可核对的增量清单与口径警告

## 0. 一句话

**v2.2 不是 v2.1 的后代**：v2.1 基于上游 `09338b85e`（2026-11-12），v2.2 基于 `a956a852c`（2026-11-14），两者之间隔着 **66 个上游提交**。v2.2 相对 v2.1 的净增量是 **9 个新文件 +555 −90**、**6 个文件删除（+744）**、**49 个共同文件的行数演进**，外加那 66 个上游提交带来的行为变化。

## 2. 口径警告（先读这段，否则下面的数字会被误读）

**「共同文件的行数 delta」不等于「我们的改动」**。两个版本的 patch 各自相对自己的上游 base 计算，而上游在两天里改了同一批文件（`llama-context.cpp`、`speculative.cpp`、`llama-split-proto.h` 等）。所以：

- **§3 和 §4 是干净的**（只出现在一边的文件，delta 就是我们的）；
- **§5 的 delta 是「我们的改动 + 上游改动」的混合**，只能作为方向参考，不能当作「v2.2 比 v2.1 多写了 N 行」。

要精确分离，得把 v2.1 的 patch 应用到 `a956a852c` 上再比——那是一次 rebase 实操，本文不做。

## 8. 结论

**v2.2 相对 v2.1 的增量，按重要性排序**：

1. **上游跟进**（66 个提交，含 DFlash 重构）——这不是我们写的，但 v2.2 拿到了，v2.1 没有。
2. **Vulkan / Intel iGPU 修复**（4 文件 +210）——v2.2 独有，实测 MoE decode +56%。
3. **权重 buffer 策略**（+153）——v2.2 独有，把权重放哪从副作用变成显式声明。
4. **代码质量**：删了 2460 行死代码（slim-arc 三个 orphan 单元 744 行 + prefetch 的 NOT WIRED 块约 1700 行），43 行 fork API 搬出公共头（`include/llama.h` 从 +60 降到 +11），内部标记与版本标签清理，注释英文化。
5. **MoE pinning**（+182）——v2.2 独有，但本机不可用（Windows WDDM 不支持大范围 file-backed pin）。

**v2.2 没有的**：v2.1 的 5 个中文提交历史（v2.2 是 4 个英文提交）；两者不能直接 cherry-pick 互换，因为上游 base 不同。

**v2.1 仍是有效的历史节点**：它标记的是「分段链功能完整 + 验收 77 项全绿」的那一刻，基于 11-12 的上游。v2.2 是「同一套功能 + 上游同步 + 代码治理」的重建。
