### 1.4 协议 v7 / v8 / v9

| 版本 | 加了什么 | 符号 | 帧大小变化 |
| --- | --- | --- | --- |
| v5 | tail 只回 top-k 候选，不回整行 logits | `common_sampler_candidates_check()`、`plan_remote_candidates()` | 993 KB → 352 B/token |
| v7 | 验证帧每行回一个 int32 argmax；帧内行号必须等于 batch 绝对下标 | `DECODE_FLAG_VERIFY_ROWS`、`request_remote_verify_rows()` | 单帧 993,312 B → 48 B |
| v8 | MTP draft 下沉到 tail，k 步递归在 stage 内跑 | `OP_MTP_DRAFT`、`DECODE_FLAG_NEXTN_ROWS` / `RSP_FLAG_NEXTN_ROWS` | 一帧回 k 个 id |
| v9 | `layer_inp` tap 挂到 decode 回复上，跨机零损失 | `DECODE_FLAG_LAYER_INP` / `RSP_FLAG_LAYER_INP`、`request_remote_layer_inp()`、`layer_tap_out` | prefill 512 行 = 8 MB / 4 MB |

（数字出自 `PROTOCOL-V9.md` §1–§3。）v9 的三个设计约束：

1. tap 复用 decode 回复而不是新开 op——它是「这一帧 tail 隐藏行的附带品」，必须与产生它的那一帧绑定；
2. 请求带的是**源模型层号**，stage 自己减 `layer_lo`，于是同一个请求能发给链上每一段；
3. 必须升 `PROTO_VER`——`n_taps` 只挪了 padding，v8 / v9 帧长一样，唯一防线是版本前置检查。

## 4. 控制面：944 行做三件事

`control/qlhctl.py` 只有三个子命令，不做第四件事（模块 docstring 逐条列了「不做什么」）：

| 子命令 | 做什么 | 关键实现 |
| --- | --- | --- |
| `up` | 读拓扑，按**链序反序**拉起每段（尾段先、链首最后），等它自己打印 ready | `spawn()` / `wait_ready()` |
| `status` | 对每段报 pid / 端口 / ready 行，一次调用内说明哪一段不在 | `probe_stage()` / `cmd_status()` |
| `down` | 按 state 里记下的 pid 停掉 `up` 起的进程，并复核端口已释放 | `stop_pid()` / `cmd_down()` |

四个实现决定，各自对应一类具体失败：

1. **ready 的判据是段自己打印的那一行，不是「端口能连上」。** `split-stage` 从 v10 起先 bind 再加载，
   所以端口在模型读第一个字节之前就是通的——把 TCP connect 当 ready 判据，会把一段还在读 20 GiB
   权重的进程报成健康（`control/qlhctl.py` 文件头）。
2. **`verdict` 有五个状态**：`unknown`（state 里没有这一段）/ `DEAD`（进程不在）/ `starting`（活着、
   还没 ready）/ `LISTEN-GONE`（进程活着、ready 过，内核里却没有监听）/ `ok`（`probe_stage()`）。
   前四个各自对应一种可处置的故障。
3. **远端 shell 用一条命令分清三种**：`$0` 在 `cmd.exe` 里不会被展开（原样打出 `$0`），
   `uname -s` 在 Windows 上给出 MINGW / MSYS / CYGWIN 前缀 → `posix` / `win-cmd` / `win-bash`
   （`remote_style()`）。`win-cmd` 的脚本走 stdin 交给 Git Bash——走参数的话 `>` `&` `|` 会先被 cmd
   当自己的元字符解释一遍。
4. **Windows 上 `nohup` 不可用，改走 WMI**：Windows OpenSSH 会话结束会杀掉整棵进程树（实测
   `nohup sleep 60 &` 在 ssh 退出 2 秒后就没了，Linux 上不受影响），所以写一个 `.cmd` 负责重定向、
   再交给 `Win32_Process.Create`（`_win_launch()`）。

   代价是 pid 变成一层 `cmd.exe`，停止要 `taskkill /T` 杀树——这也让「cmd 活着 == 段活着」成立。

另有两处小但必要的：

- `preflight_ports()`：端口被占时 214 ms 退出，而不是先读完几 GB 权重才发现；
- `check_weights()`：两段加载的不是同一份权重时，链会产出「看着通顺的垃圾」，这里补一道 size / mtime
  的**启发式**自检（`OP_HELLO` 只报 range / 宽度 / 深度，区分不了同形状不同权重的 GGUF）。

## 5. 安卓 / ARM64：移植面从「3 处 shim 移植」缩到「1 个 `#include`」

v2 要在 arm64 上跑，得把 `shim/` 的三处移植改掉。v2.1 不需要 shim——链在 `llama_context` 里，编
`llama-server` 与 `split-stage` 就行，唯一的编译失败是 `src/llama-split-remote.cpp` 上的
`error: unknown type name 'addrinfo'`。

POSIX 要 `#include <netdb.h>` 才有 `addrinfo` / `getaddrinfo`（Windows 从 `ws2tcpip.h` 拿）。补在
`src/llama-split-net.h` 的 POSIX 分支之后，clang 21.1.8 + cmake 一次编过，`libllama.so` /
`libggml*.so` / 两个可执行文件全出（`ANDROID-SURFACE-段接入评估.md` §1.4）。

两条部署侧的非代码成本，写在这里因为它们是实现的一部分：

- **`LD_LIBRARY_PATH` 没有槽位**：二进制依赖同目录的 `.so`，而拓扑没有环境变量字段；做法是写一个
  wrapper 脚本设 `LD_LIBRARY_PATH` 后 `exec` 真二进制，拓扑的 `bin_dir` 指向 wrapper 所在目录。
- **安卓上 `ps` / `pgrep` 看不见别的进程**：`pgrep -af split-stage` 在尾段活着时返回空，所以「那段
  还在吗」只能问 `kill -0 <pid>`（控制面正是这么探的）或从端口 / 协议层问。
